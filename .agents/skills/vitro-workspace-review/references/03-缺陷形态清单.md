# 缺陷形态清单

> **开审前扫一遍。** 本表按"形态"聚类，每一条都在本仓真发生过。
>
> 用法：拿到一批代码，按本表逐类过一遍（每类给"判据 / 查法 / 实例"），比从头读一遍命中率高得多。
> **新形态追加到本表**（规则见 [`05-演化机制.md`](05-演化机制.md)）。
>
> **实例写法四条**（2026-10-02 立，防腐化）：
> 1. **禁写一次性测量值**：测试数（`34/34 全绿`）、`PASS n / FAIL m`、批次号、文件数、条数——它们随代码演进而过期，而本表只增不改，过期的数字**没有任何机制修正**。
> 2. **允许写"形状"而非"真值"**：对比关系（`70 任务 → 28 任务`）、临界样本（`20 × 0.2 = 4.0`）、触发条件属于判据本身，可留。
> 3. **日期只保留"形态最早可考"的场合**，且写成 `（Y-M 立）` 而非 `（Y-M-D 实测 34/34 全绿）`——**要的是"真发生过"，不是"当时多少"**。
> 4. **实例优先给"可复现判据"**（一条命令 / 一段注入写法 / 一个文件:行），其次才是"当时观察到什么"。复现不了的实例，只留一句结论并注明来源。

## A · 锚的问题（测试写了但没有牙）

> **按"改坏为什么不红"归类**；各触发面括号内为**原条目号**（历史引用可据此追溯）。
> **共同查法**：对每个实现点做**突变注入**（改坏它）+ **对照注入**（同时改坏 1–2 个已知有锚的点）——只有前者全绿而后者红，才叫"**这一点**无锚"；否则只能说"这套测试整体没牙"。

### A1 · 锚对"错的实现"零判别力

锚能跑、也断言了，但**样本或参数挑得让错误实现照样绿**。六种触发面：

- **a. 样本自身对称**（原 A2）：`encode` + `decode` 往返断言通过，但两者共用同一约定 ⇒ 约定本身错了也测不出。对"顺序 / 下标 / 默认值"这类共用约定要**单独加锚**。实例：符号表插入序的序突变多处全绿（现序正确，但往返锚天然测不出序）。
- **b. 判别样本对两个候选语义输出相同**（原 A5）：`atan2(1.0, 1.0)` 对称 ⇒ 对弹参序零判别力（`pow(2, 10)` 才有）；`fmod` 样本全是正 x ⇒ 分不出截断与最近取余。查法：对每个样本自问"它能反证哪个候选"。
- **c. 算术判据的样本全落在分界点之外**（原 A10）：`ceil` / `round` / 阈值比较类**临界判据**，把判据写错一格（`<` ↔ `<=`、half-up ↔ half-even）时全绿。查法：找出"**恰落在分界点上**"的输入（`ceil` ⇒ 乘积 / 商恰为整数；`round` ⇒ 恰 `.5` 平局；阈值 ⇒ 恰等于阈值），数锚样本里有没有。实例：`FrameWindow::trim` 的 `discard = ceil(len × ratio)`，锚样本的 `len × ratio` 全是小数 ⇒ 注入 `<=`（= floor+1 语义）后全绿；补 `with_limits(19, 0.2)` 推 20 帧（20×0.2 = **4.0** 整数积）的锚后，同一注入立即红。
  - **同族面（2026-10-11 补）：临界可能在「中间计算的舍入域」而非参数域**。自实现 `round(x)` 的经典病根 `x + 0.5` 再 floor/ceil——输入 `0.49999999999999994`（小于 0.5 的最大 double）与 0.5 的精确和**恰是两 double 的中点**，tie-to-even 入 1.0 ⇒ 返回 1.0 而真值 0.0；锚样本（±0.5/±1.5/±2.5）全离边界远，因为分界点不在输入参数里，而在**中间加法的舍入结果**里。查法：对"加 0.5 再取整"类实现，必测集加 `nextDown(0.5)` 型样本（C 探针真值对拍）；对照注入（改坏已知有锚点）证明测试体系有牙后，修复预演不炸锚 = 该面零锚坐实。
  - **同族面（2026-10-11 追补，同「中间舍入域」）：科学计数法格式化替代实现的「尾数进位归一」**。手写 `%e`/`%E`/`%g` 的常见三步——`exp = floor(log10(abs))` → `mantissa = abs / powi10(exp)` → `format_fixed(mantissa, prec)`——分界点**不在输入参数域**，而在「除法缩放 + 四舍五入」后的中间结果：仅当 `format_fixed` 舍入后得到 `10.0…`（mantissa ≥ 10）时才须进位（`exp+1`、mantissa 重算）。锚样本全取普通值时零判别力：`printf("%e\n", 999999.99)` 真值 `1.000000e+06` / 实现 `10.000000e+05`；`%.0e`+`9.5` 真值 `1e+01` / 实现 `10e+00`；`%g`+`999999.99` 真值 `1e+06` / 实现 `1000000`。查法：对「缩放 + round」类实现，必测集加**舍入结果恰跨进位阈值**的样本（`9.999999x` 系、`999999.99`、`%.0e`+`9.5`/`99.0`）；**对照**：注入正确的进位重算后该包测试仍全绿 ⇒ 该面零锚坐实。
- **d. 分派的分支维度未覆盖**（原 A11）：按类型 / 枚举分派的判据（`match kind() { Char => 1, Double|LongLong => 8, _ => 4 }`、按 Tag 选通道、按 Op 选文案），样本只落默认 / 兜底分支——或只落在"**取值恰好等于默认值**"的分支 ⇒ 把分派整体退化成写死常量时全绿。查法：**逐分支列出取值**，要求每个非默认分支至少一个样本；对"默认值恰好等于正确值"的分支尤其要单独做"写死默认"注入。实例：`find_variable_name_at_addr` 的元素宽度按**元素类型**分派（char 1 / double·long long 8 / 其余 4），锚只用 `int[4]`（默认分支，取值与默认值同为 4）⇒ 写死为 4 后该包全绿，而 `double[N]` 的 `&arr[k]` 全部解析不出名字、`char[N]` 的数组外地址被误归属。
- **e. 锚用的参数规模把分支挡在门外**（原 A12）：带"上限 / 阈值参数"的分支（`if want_start > start_step`、`discard > len`、`size > budget`），锚一律拿**协议默认大值**构造 ⇒ 触发它所需的参数规模远大于锚样本，该分支**既走不到、也没有断言**。查法：把该分支整体 **no-op 化**后跑该包全部测试，`failed == 0` 即命中；再问"用**最小可配参数**能不能造出可达输入"——能就补锚，造不出才按 A5 降级为不可达。实例：`finish_replay` 的 discard 钳位需 `target ≥ window_size`（协议默认 2 000），锚族 target 全 < 100 ⇒ 写死后该包与其下游包全绿；而这段代码承载 3 次历史事故修复。
- **f. 锚只断言部分样本 / 部分下标**（原 A4）：一批同类对象（`decoded[0..n]`、多通道）里锚只覆盖其中一个。查法：数同族对象个数与锚里的下标集合。实例：某解码器 6 个通道里 5 个用 `.map()` 重建、独 1 处共享引用，而锚只断言 `decoded[2]`。
  - **同族面（2026-10-11 补）：同函数族的锚位错位**——同一检查在**同包两条路径**各实现一遍（`resolve_unary` / `resolve_assign`、`sprintf` / `snprintf` / `sscanf` 臂族），锚只挂在其中一条上 ⇒ 另一条改坏全绿。查法：同函数族**逐臂列锚名**（该臂的突变注入红不红），缺臂即候选；对照注入同文件有锚臂应红，区分"缺臂"与"整套没牙"。
- **g. 审阅处方本身没过边界样本**（2026-10-02 补）：审阅给出的**修复处方**（替代实现方案）只拿单一顺路样本验证过 ⇒ 处方在边界上翻车，照方抓药会引入新分叉。与 a–f 是镜像关系：那些是"实现没被锚反证"，这条是"处方没被样本反证"。查法：处方给的替代实现，要拿**既有锚的全部样本**（尤其边界值——早退分支遮蔽的、数值边界的）跑一遍，而不是只验一个顺路样本。实例：审阅处方"confidence 改裸 `to_string()`"，验证样本 2/3 恰好落在被删函数的早退分支之外 ⇒ 处方看似成立；边界 1.0 上 `Double::to_string` 输出 `1` 而 oracle 恒 `1.0`——照方实施即引入新分叉（实测否决，改走 `double_to_json_text` 单源）。
  - **同族面（2026-10-04 补）：修复批的自验样本只落在「非空 / 非默认 / 有值」触发面**。修复者按"能复现原 bug 的那个输入"验一遍就收工，而该条件还有**空 / 零 / 缺省 / 缺参**形态——它们在**同一段代码的另一条分支**上（常是 `else` / 缺省参数 / 空数组），修完仍然漏。查法：把修复声称触发的条件**取边界形态再跑一遍**（参数为空串 / 数组长度为 0 / 旗标不出现 / 值为 0），与"有值"形态的结果对拍；再问一句"这条边界走的是不是同一个 `if` 臂"。实例：某命令的"参数静默丢失"修复，只在**带至少一个附加参数**时验证通过，零附加参数时走 `else` 臂、参数整段不下发 ⇒ 最常见调用形态仍是坏的（两侧结果对拍即现：一侧 0 个参数、另一侧 1 个）。
  - **同族面（2026-10-18 补，P1-1 实证）：同一检查在多条语法路径各可达一次，自验样本只覆盖其中一条**。`static` 初始化器的枚举常量折叠在「聚合定义带声明器」与「普通局部声明」两条 parser 路径各接一次线，修复自验样本（语料+wbtest）全落文件作用域/前者 ⇒ 普通局部 `static int s = K;` 仍误拒 E3075。查法：修复挂在某条 parse/resolve 路径时，grep 该函数的全部调用点（"谁还会到达同一段检查"），逐调用点问"自验样本走过这条吗"——修复函数正确 ≠ 接线覆盖全。
  - **同族面（2026-10-05 补）：行为开关型修复只验「该开的那一侧」，未对照「不该开的那一侧」**。修"某条件命中即改走新路径"这类开关（封顶改报诊断 / 前缀扫描 / 阈值夹紧 / 分支改写）时，自验样本常只取**新路径该命中的形态**，而**旧路径该继续走的形态**（同一判据的不命中面、另一个条件的输入）零对照 ⇒ 把"不该开"判成"该开"没有任何锚会红。查法：为该开关的**每个条件**各造一个样本（命中面 + 非命中面），非命中面必须验"行为与修前一致"；对"新判据本就为真"的兜底态尤其要单独跑。实例：include 深度封顶由 `None`（判无环、继续走动态保险丝报「嵌套过深」）改报 `Some`（环诊断）后，新锚只造了**深环**（该开）样本，**100 文件无环深链**（不该开）实测被误报为「检测到 #include 依赖环：c1.h -> … -> c65.h -> （include 依赖图超限…）」（约 800 字符，归因由正确倒退为错误）；同批的 atof 前缀修复只取合法前缀样本（`12abc`/`-2.5e1xyz`），**悬空指数** `"1e"`/`"1e+"`（C 取更短的合法前缀 `"1"` ⇒ 1.0）漏验 ⇒ 0.0 vs Clang 1.0。判据：**修复的"开"与"不开"两侧都要有锚**，只在"开"侧埋锚 = 把回归面留给下一次。
  - **同族面（2026-10-06 补）：双出口「成功路径 / 失败路径」的诊断渲染，修复只补了"成功"那一侧**。同一段"补诊断输出"改动里，成功路径与失败路径常是两段**各自带早退分支**的独立组装——修者按"能复现原 bug 的那个输入"（通常是编译**成功**用例）验一遍即收工，失败路径（`errors` 非空 ⇒ 提前 `return`）仍漏。查法：造「**编译失败 且 同程序另有该阶段产出的 warning/hint**」的极小用例（如"类型错误 + 同程序另有类型警告"），跑两侧出口（CLI 默认臂 vs 参照臂 / 文本出口 vs 结构化出口）逐行对拍——失败侧少行即命中。实例：统一 CLI 双出口（wasm 壳 / native exe）的 `run` 诊断渲染，一侧补了"成功路径丢非错误级诊断"，而**编译失败路径**仍丢（gateway 帧在 typeck error 时早退、`type_warnings` 从未进 `diagnostics`；native 同分支则显式输出 `warns`）⇒ 默认臂对"类型错误 + 类型警告"的输入少一行 warning，而两侧的成功路径逐行一致。判据：**修复面若含两段独立早退分支，"开/不开"之外还要按"成功/失败"各埋一条锚**（与本条上一个是同一"只验顺路样本"病的另一个维度）。
  - **h. 照搬批只搬了 oracle 一部分单测**（2026-10-03 新增，与 d 同族）：oracle 的单测常按"每个分支一个 `#[test]`"组织，照搬侧若只挑了其中几个形态写成锚（哪怕写成端到端全链路锚），**未搬的分支既走不到也没有断言**——而"锚了很多条"的观感正好掩盖这一点。查法：列出 oracle 测试文件的 `#[test]` 函数名集合，与目标侧锚**逐分支**（不是逐条）对齐；对每个"无对应锚"的分支做**突变禁用**（判据改恒假 / 返回值退化成兜底态），全绿即命中。实例：某五态分类器只锚了其中两态（其余分支的样本恰好也落在被锚的那两态上），把第三个分支的判据改成 `> 999999`、第四个分支的返回值改写成兜底态后，该包测试仍全绿；oracle 侧恰有对应的三个单测未被搬。处方 = 按 oracle 单测逐分支补齐，或把聚合分派改成表驱动 + 逐表项锚。
  - **i. 锚手写的输入节点类型 ≠ parser 实际产出的节点类型**（2026-10-07 新增，与 h 同族——h 是"少搬了分支"，本条是"锚的入口路径不对"）：仓内单测常**手写 AST 节点**（不经 lexer/parser），若选错了节点变体，锚就落在**另一条函数路径**上，而被审的那段实现走的是 parser 真实产出的那个变体 ⇒ 锚与实现永不照面，翻遍测试也判不了它。查法：对每条锚问一句"parser 对这个输入形态实际产出哪个节点变体"（`grep` 该变体的构造点 / 跑一次 dump-ast 看真实产物），与锚里 `Expr::Xxx(...)` 的变体名对表。实例：某"未声明函数"补诊断把逻辑加在 `resolve_call_ptr`（C 的 `CallPtr` 臂），而既有 E3036 锚手写的是 `Expr::Call`（C++ ctor 路径、C 输入不可达）⇒ 把新分支条件置恒假后该包测试**全绿**，锚完全没照到被审的那段；对照注入（改坏锚真正覆盖的报错码）立即红，证明是"锚错位"而非"整套测试没牙"。
  - **j. 锚把被测值 `ignore(...)` 掉**（2026-10-10 新增，与本族"锚漏 / 锚错位"并列的**最粗一档**，也是 D8「空转锚」家族的最简形态）：测试**调用了**被测函数却没接住返回值（`ignore(render(...))` / `let _ = ...`），于是缺参、崩溃、`.unwrap()` 失败这类"调用本身会炸"的错仍会被抓到，而**返回值 / 文案 / 数值的任何篡改零判别**。识别法：`grep -n "ignore(\|let _ = " <pkg>/*_wbtest.mbt`，逐条问"丢掉的那个值有没有在别处被断言"。**不必造样本就能判**——直接改坏被丢掉的被测值（追加一个字符 / 换一个常量），全量跑该包测试；**必须带对照**：同文件里另找一个真有 `assert_eq` 的入口，改坏它应当红（否则只能说"整套没牙"）。实例形态：一组"改造前逐字节基线"锚里，有两条 `assert_eq` 全文比对（有牙），紧接着三处 `ignore(...)`——把其中一条模板尾部加两字后该包全绿（对照：改另一条有 `assert_eq` 的模板，同一锚立即红）。处方：把 `ignore` 换成落盘基线全文的 `assert_eq`；或至少在注释里把"此处仅冒烟、文案另有锚"写明，别让注释自称"三态快照"。
- **l. 声称"突变证红"但锚未入库**（2026-10-17 新增，与 j 并列的"最粗一档"）：提交信息写"突变证红有牙（改坏 X → Y 红）"，而那次突变是**一次性手工动作**——既没进 `*_wbtest.mbt`、也没进语料，仓库里找不到任何断言能反证该实现点。**不必信"证红"字样**：把被声称覆盖的实现段整体 no-op 化（`if cond {` → `if false && cond {`），跑该包测试——`failed == 0` 即命中（对照：同函数里另一个**已知有锚**的点改坏必须红，否则只能说整套没牙）。再补一步**可达性**判定（同 A5）：no-op 后重建产物跑一次端到端，输出或行为**确实变了**才叫"真锚缺口"，否则属等价/不可达分支。实例形态：某语法子形态（嵌套 member-designator 点链）修复只在提交信息里留了"段名断链 rc=1"的叙述，`grep` 全仓该形态的 wbtest 与语料**零命中**；注入多段链 no-op 后 typeck/parser 包测试全绿，而重建后同一源码的 offsetof 返回值从 `33` 变 `32`（分支可达）⇒ 该实现点永久无锚，clang 直拍语料也不覆盖（语料只有单段形态）。处方：把那次手工突变**固化成锚**（wbtest 直调 + 语料补一条该子形态）。

- **k. 锚断言的模式位吞掉语义差异位**（2026-10-11 新增）：模式匹配断言写成**通配形态**（`assert_true(x is Int(_, _))`），而两条候选语义的差异恰在**被通配的那一位**（unsigned 位、可空位、旗标位）⇒ 该位翻转真值锚照样绿。查法：对每条模式断言**逐位**问"此位翻 true 会红吗"——答不上的位要么改显式构造器匹配（`Int(true, _)`），要么补独立断言。与 a–f 的分工：a–f 是**样本**没落在差异上，本条是**断言写粗**把差异通配掉；突变注入（把该位实现改反）全绿 + 对照注入红即坐实。

  - **m. 修复把兜底值换成"另一个错值"，而正确值同样在锚的判别面之外**（2026-10-17 新增，与 j / l 同族——j 是"锚丢返回值"、l 是"声称有锚实则无锚"，本条是**连"改对"都不红**）：修复批声明"按真实布局 / 真实口径计算"，实现却把**入参层次**传错（把整数组类型递给只吃**元素类型**的求尺寸函数 ⇒ 得 `count × 元素尺寸`），于是原先的兜底常量被换成另一个错值（且对 `count ≥ 2` 的聚合数组比修前**更大**，负向更重）。判法无需任何"改坏"动作——**把修复点替换成按真值侧同源实现算出的正确值，跑全量测试**：`failed == 0` 即该取值零锚（**必须带对照**：同批另一个修复点做反向注入应红）。再补可达性（A5）：构造"该聚合之后**没有别的符号**"的地址段做端到端探针，看消费该值的协议字段/文案是否真的错（若紧邻还有另一个变量，精确命中会**掩盖**误归属 ⇒ 只在"空段"上外现）。实例形态：vm 侧新增元素步长 helper 调 `compute_type_size(数组类型)`（该函数对 Array 返回**整个数组的字节数**），三个消费点（地址归属窗口 / 数组快照步长 / 越界 index 与归属窗口）全按 `数组总长 × 元素数` 算；把 helper 改成先取元素类型（正确值）后全量用例仍全绿，端到端 `pointer_snapshots[].target_name` 把"数组真尾之后 8 字节"的地址判给了该数组名（两侧臂一致）。处方：修复批须给出"新值 ↔ 真值侧同源实现"的**逐项对表**，并至少一条 wbtest 直锚边界两侧（真尾之内 / 之外各一）。

  - **n. 新增「结构化字段」只有一条路径被端到端锚住，同族消费点反向突变全绿**（2026-10-24 新增，与 l 同族——l 是"声称证红但锚未入库"，本条是**锚只入库了一条路径**）：给 VM/host 增加诊断字段（如 `trap_code`）时，协议基线通常只冻结**一条**触发路径（例：i32 除零），而同族其余消费点——host 侧 fault→码映射、snapshot/restore 往返、reset 清位、其他 trap 臂——既无 wbtest 也无基线帧。查法：逐个消费点做反向突变（改值 / 删赋值），跑全量测试；**带对照**：改那条被基线锚住的路径应红（实证：把 i32 除零的 `code="E3088"` 去掉 → `protocol_frames` 帧 6 DRIFT）。仍绿者即零锚。注意区分"新字段缺失"与"字段值错"：host fault→码映射把 `E3087` 改成 `E3086` 也全绿，属值面零锚。

  - **o. 单测零判别力 ≠ 无锚：锚可能在真实闸上**（2026-10-25 新增，PR #303 审阅；与 l 同族但方向相反——l 是"自称有锚实则无"，本条是"单测无判别力但防线有牙"）：判定"某实现点有没有锚"时，**单测文件与真实闸是两条不同的覆盖面**——单测只覆盖构造夹具，闸覆盖真实产物面（对账类闸拿冻结基线比真实跑批产物）。突变注入后单测全绿**不能**直接判"无锚"，必须**再跑闸实际执行的那条命令链**（连 cwd 一并复刻）才能定性。查法 = 突变后跑两次：① 对应单测文件（判"这批测试有没有牙"）② CI 里那一行命令（判"防线有没有牙"），两者**分开记**。**边界**：两者皆绿才是等价分支 / 不可达，此时仍须**构造漂移形态**证明该比对面**独立生效**（去掉一个比对面，其余不兜底 ⇒ 它是真防线而非冗余；否则两个比对面互为冗余时，去掉任一个都检不出）。实例形态：跨语言迁移批新增 30 例单测，16 处突变在单测里零判别力；走完整 CI 命令链后其中 10 处仍绿——逐条构造漂移形态验证后确认为**等价分支**（码集 / errs / warns / gcc_ok 四个比对面经漂移形态证明各自独立生效），真实盲区只有一处且属迁移前既有形态。方法学教训：突变验证的闸**必须连 cwd 一并复刻**——判定型脚本的相对路径基准随 cwd 变，从子目录调用会读到别处的基准文件而**假红**（本轮一度据此得出"全部被捕获"的假结论）。

  - **p. 新增「静态求值 / 折叠单源」的「不支持即静默 0」降级面，锚与语料都未覆盖**（2026-10-26 新增，与 m / n 同族——m 是「兜底值换成另一个错值」，本条是「兜底值根本没人测」）：给引擎新增一个「静态求值单源」（地址常量求值 / 常量折叠 / 编译期求值）时，实现通常带一条**降级分支**（「这个形态静态求不出来 ⇒ 回填 0 / 维持旧行为」）。该分支的**输入面没有任何锚**——既无 wbtest 也无语料条目 ⇒「这一形态真的不支持」与「实现漏了这个形态」**无法区分**，后者一路静默到运行期（指针为 0 ⇒ NULL 解引用 trap；或值算错 ⇒ 静默错值）。**查法**：① 把求值器的**匹配节点枚举出来**，逐个 fallback 分支造**合法 C** 样本（外层包装形态、指针基座、非整数字面量下标、负下标、元素类型本身是数组……），每个样本跑 clang 取真值 + 跑引擎双侧对拍；② 凡 clang 给值而引擎给 0 / trap ⇒ 该形态**未被覆盖**（不是「设计上不支持」——C 合法即应有值）；③ 逐形态定去向：能求值的进语料、不能求值的**至少给诊断**（「静默 0」是最坏形态——它把编译期可诊断的错误推迟成运行期崩溃）。**边界**：C 语义上本就不合法的形态（文件作用域引用尚未声明的符号 ⇒ 非常量表达式）**不算本条缺口**，但会暴露另一面——引擎若接受这类非法输入且不报「未声明」，那是**诊断面**缺口，与求值器无关。实例形态：文件作用域地址常量链（成员 / 下标链）新增静态求值单源后，实测**字面量下标的链**全部与 clang 一致（嵌套成员 / 数组元素 / 二维数组元素 / union 成员 / struct 内嵌数组 / 多维链 / 函数内 static 聚合基座），而**外层带 cast 包裹**的同款链落到「不支持」分支 ⇒ 静默 0 ⇒ 运行期 NULL 解引用，而 clang 正常给值。处方：求值器的匹配节点要**穿透外层包装**（cast 等），或至少在降级分支补诊断；补语料时**按 fallback 分支矩阵补形态**，别只补「主案」。

  - **q. 文本层判据从「字面量」换成「结构特征」后只锚了正例 ⇒ 放宽出的误报面零锚**（2026-10-28 新增，PR #347 审阅；与「行为开关型修复只验该开的那一侧」同族——那条的触发面是**行为分支开关**，本条是**判据条件的语义宽度**）：把 `contains("<某字面量>")` 类判据换成「结构形态」判据（「等号某一侧含下标」「某字段非空」）时，新判据的**命中集严格变宽**——原字面量判据顺带排除掉的一整类行（单向读取 `x = a[i]`、初始化 `int min = a[i]`、字符串/字符字面量里的等号、注释行、`printf("…", a[i])`）现在全部命中。修复者通常只对**目标写法**（正例）和**一个特意想排除的形态**（反例）埋锚 ⇒ 上面那一类是零锚的，而且它只在**真实语料的惯用写法**上外现（单测正例跑不出来）。查法：① 把新判据的命中面按**语义分类列全**（真目标形态 / 语义近邻 / 无关行），每类一个样本直调判据函数，逐条比对「应命中」；② 反例矩阵必须含**原判据因字面量缺失而天然排除的形态**（否则测不出「放宽」这件事）；③ 消费点若只在某族上下文可达，语义近邻样本要取**该族模板的真实惯用写法**（如排序里「把首元素读进标量当极值初值」），别用编造行。处方：结构判据要**双向约束**（交换行还须「两侧下标表达式不同 / 目标侧确为写」），反例矩阵写进同一 wbtest，别只留一个反例。同批附带面：同一根因（命名敏感判据）在多条通道各有一份实现时，只改其中一条 ⇒ 两条通道对同一源码给出不同语义；「同批翻案 N 处只给 1 处补锚」亦然，逐处做单点突变（不是三处一起改）才看得见哪几处零锚。

  - **r. 「编号空间 vs 过滤后数组下标」错配——`list[id - 1]` 的 id 分配集合 ≠ 列表元素集合**（2026-10-31 新增，PR #390 审阅）：当 id 由全局计数器分配（如 `file_id` 自增），而消费侧数组经过过滤（如剔除 `stub:` 键的 `included_files`）时，`list[id - 1]` **必然错位**——且错位后仍能产出「看似合理」的结果：本例 file_id 分配时 stub 头（`<stdio.h>` 教学桩）也占号（fid=1），过滤后数组 [sib.c] 使 fid=2 取到越界/错位元素 ⇒ 含标准库头的真实程序修复零改善，多 .c 形态还**错报兄弟文件**（错误在 a.c 报成 b.c|1——真实文件 + 合法行号，比越界崩溃更难发现）。**判据**：凡写 `list[id - 1]`，就问一句「id 的分配集合是否等于 list 的元素集合」；不等则按 id 直查全表（Map[id]），不按下标换算。**锚判别力连带**：本例首版锚只用「纯自定义 include」样本恰好绕过 stub 路径——锚样本必须覆盖**真实程序的主场景**（几乎全部 C 程序都 include 标准库头），「锚有牙」（反向突变红）不等于「判别力盖住主场景」；查法 = 列出修复宣称覆盖的形态全集，逐形态问锚样本是否在场。
### A2 · 输入面没盖到

锚本身有牙，只是**喂进去的输入从没触发过那条路径**。

- **a. 只有合法输入**（原 A1）：实现里有"受检访问失败 → trap / 短路 return"分支，但测试输入**全部合法**。查法：读实现的 error / catch 分支，反查测试里有没有构造过触发它的输入。实例：host handler 层数十处 `catch` 收口，对若干处做突变全绿——`host_fopen` / `host_fread` 的受检路径确实无锚（host 测试全用合法地址）。
- **b. 语料形状单一**（原 A6）：某函数在全部语料里只有一种形状的用法。查法：`grep -rn "<fn>(" corpus/<suite>/`（原 `native/tests/cases/` 随 2026-10-05 删区迁至 `corpus/`，语料直接铺在 7 个 suite 目录下，**无** `cases/` 中间层）看全部用法。实例：全语料只有 `round(2.5)` 一处且是**正**平局 ⇒ 结构性抓不到负平局缺陷（而负平局全错）。
  - **同族面（2026-10-25 补，PR #299 审阅）：同批「一处根因改多处消费点」时，红锚语料往往只反证其中一部分消费点**。修复批把某条解析/查表链的**优先级**在 N 个消费点统一重排（各消费点分散在不同文件），而红锚语料只覆盖该链最常见的几类形态（标量读 / 写 / 自增），**聚合面与地址常量面等其余消费点零触发** ⇒ 语料对那几处改动**零判别力**，相关包单测也不覆盖 ⇒ 双向盲区。查法（比逐点突变便宜得多）：**指令流差分**——修复前后对同一语料 dump 指令流，差分里没有的路径即该锚零判别力（配套：`globals_init_32` 一并比，地址常量面落在 code 之外）；再用定向突变（只还原那组消费点）确认锚仍绿 + 单测仍绿。**边界**：差分「无差异」只证「锚零判别力」，**不证「路径不可达」**——可达性另造探针（命中错值才算坐实）。处方：语料按**消费点矩阵**补形态（每处改动至少一条能反证它的语料），别只补主案。实例形态：static 局部遮蔽同名 global 的修复改了 6 处消费点，锚只反证 3 处（读值 / 自增 / 复合赋值），struct 聚合面与地址常量面那 3 处改动零判别力——而那 3 处各自都真实修好了一类静默错值（探针命中错值坐实），却无任何锚拦截回归。
  - **同族面（2026-10-11 补）：C 高频习语逐个 grep 语料，零命中即必探**——审解析器/词法器时，把教科书级习语列成清单逐个查语料覆盖：`struct 定义带声明器`（`struct T{…} t;`）、`typedef 多声明器`（`typedef struct{…} A, *B;`）、一元 `+`、`long long int` 三连拼写、hexfloat、嵌套 offsetof、三目含逗号表达式……一轮实测 **9 个实锤全部落在"语料零命中"的习语上**——语料作者不会写自己没想到的形状，习语清单是廉价的盲区探测器。
- **c. 只有"平均情况"的基准**（原 A9）：微基准只测顺利路径 ⇒ 结论方向被样本分布决定（某 API 在 0% 失败时快 2.5×、**100% 失败时反而慢 1.35×**）。基准必须覆盖**失败率 / 规模 / 边界**三个维度。
- **同族面（2026-10-24 补，PR #284 审阅 P2-1）：限定符类诊断文案的自洽指纹 = 指针层级归属错的显影**——限定符类诊断文案里**两侧含同名 const**、或出现 `T const` / `** const` 这类「const 挂在外层」的渲染（C 记法 const 在最内层 pointee / 第一层指针自身位），即声明符链 const 层级归属错的指纹（parser 挂最外层指针位）。查法 = 拿「**形参与实参类型完全相同**」的形态（`char* const[]` decay `char* const*` 传 `char *const *` 形参）打一遍——clang 零诊断处报了「const 位差异」即误报（精确匹配形态的警告必为层级错；真限定符差异形态两侧类型必不同名）。实例：`char** const ← char* const[2]`（t 侧 const 渲染在 `**` 后）正确类型串应为 `char* const*`——文案把病历直接印出来了。
- **d. 诊断/错误路径的文案面无锚（2026-10-10 补，与 b 同族）**：收编 / 统一一类内建检查时，闸只覆盖**合法调用**的形态（差分 digest 锁的是正常路径产物、单测喂的也是合法输入）⇒ 参数个数错 / 类型错这条支路的**文案文本**没有任何锚。查法：改坏该支路的文案字符串（一个字），单测与差分 digest 应双双全绿即坐实；**必须带对照**——同时改坏一个已知有锚的判定点（应红）与一条已知被 digest 覆盖的真值（应 DIFF），否则只能说"整套闸没牙"。实例形态：把内建调用的 count 校验文案从中文数字统一为阿拉伯数字（同批坦白写进了提交信息），上下游全绿通过——与提交信息同一段自称"与原臂逐字节同构"**自相矛盾**（口径可核对：`git show <c> -- <新臂文件>` 的 `report_error` 字面量 vs 被删旧臂的字面量）。处方：给"错误支路"补一条直调锚（喂错参数个数，断言文案），或把它纳入差分语料。

### A3 · 锚把与 oracle 不同的行为固定成了预期（锚错 > 锚漏）（原 A3）

- **判据**：既有测试的期望值与 oracle 实际行为**不一致**，但测试是绿的 ⇒ 修复时会"按错的来"。
- **查法**：发现"两侧形态不同"时，**先查是不是既有锚已锚定了错形态**。
- **实例**：`getchar` 行尾不产 `\n`——既有白盒锚用的正是"每行不含换行的数组"形态，把与 oracle 不同的行为锚死，三道防线因此全绿。
- **批量侦测法（2026-10-11 补，oracle 退役后高危）**：判据真值源已反转（oracle 照搬 → Clang 直拍），wbtest 注释里含「oracle 同」「oracle 实测」字样的锚是**按退役真值钉死**的高危集合——`grep -rn "oracle 同\|oracle 实测" moonbit/` 列全集逐批 retest。已完成的先例：ctype 负码位销案；未做面：string 族有符号字节差、NaN 文案、memchr 负 c（锚明文断言"负 c 恒不中"）、f64 正指数 JSON 文本。**修复这类面的连坐动作 = 改实现的同时翻转锚**，只修实现会假红。
- **同族面（2026-10-25 补，PR #307 审阅）：迁移批直译旧测试时，期望值里的「输入形态」可能早已不存在于真实生产者输出 ⇒ 锚绿但锚的是幽灵形态**。判据 = 对每个「解析某闸输出」的函数，**从真实生产者取一行**喂给解析器；返回不可采而单测全绿即命中。查法：① 跑一次真实生产者取尾行（如 `node <gate> ... | tail -1`）；② 把该行直调解析函数看 `ok`；③ `grep` 解析函数的测试样本串是否出现在生产者源码里——测试样本只存在于测试文件 = 照抄历史形态。**双跑对拍查不出**：新旧两版共用同一正则时同病，逐位一致反而掩盖。处方：解析器测试必须至少一条**真实生产者行**的样本，并在生产者输出形态变更时连坐；`--run` 类采集器另加「解析失败率非零即红」的守卫。实例形态：某采集器解析 PASS 行，测试样本是旧形态（旧版闸输出），真实闸已改成另一种措辞 ⇒ 该真值键永久 unavailable，而 49 例单测全绿、Go/ts 双跑 stdout 逐位一致。

### A4 · 分解式数字无锚，只有头条数字有锚（原 A7）

- **判据**：文档写"X = a + b + c"，闸只比 X。
- **实例**：`protocol 44 = 白盒 32 + 黑盒 6`（32+6=38≠44，行内不自洽）而计数闸只比头条 44。
- **同族面（2026-10-25 补，PR #312 审阅）：行级冻结 ⇒ 一整行「现值句」可全无锚**。对账工具的冻结判定是**行级**的（行内出现日期 / as-of 词即整行免对账），故一行里只要带了日期，**该行所有数字**（头条 + 分解式分项 + 历史对照值）都不参与漂移判定。查法 = 对该行每个数字做 **±1 扰动**，逐个看闸是否转红；全绿 = 该行零锚。实例形态：路线图「测试防线」行同时装现值（语料数 / 用例数 / 测试数）与日期（对齐日期 / 批次日期）⇒ 整行冻结；该行分解式的分项（baseline / knr / leetcode / gap）与头条各漂数十仍无人察觉（旧值 448 与实际 501 差 53 长期存活）——同批实测该行四个数字逐一 ±1 扰动**全部转绿**。处方：现值行与日期分离（现值句不写日期），或把数字绑到带关键词的独立行并单独给锚；审这类行时把「行内是否有日期」列为必查项。

### A5 · 不可达分支不硬报（判定纪律，非缺陷形态）（原 A8）

- **判据**：某分支在当前实现下**永远走不到**（前置不变量保证）。
- **查法**：**能否找到一条区分两条路径的输入**；找不到 ⇒ 等价或不可达，属读码判定，**不硬报**——收尾时列进"未覆盖"表并注明"判据不足"。
- **实例**：某 `catch` 前的 `register_alloc` 已保证地址在已登记区域内 ⇒ 后续受检写必成功 ⇒ 该分支不可达。

## B · 分叉（两侧不等价）

### B1 · 名字对位陷阱：同名函数语义不同
- **判据**：把 `libm::f` 机械映射到目标语言标准库同名函数。
- **必查清单**：`round`（**平局方向**：C99 要求远离零，而 core 自称 half up ⇒ 负平局全错）、`log`→`ln`、`mod`→`fmod`（**截断**取余 vs IEEE **最近**）、`floor/ceil/trunc` 的 ±0 符号。
- **实例**：`round(-0.5)` 真值 `-1.0` vs 实现 `-0.0`；`-1.5`→`-2.0` vs `-1.0`。**正平局恰好一致 ⇒ 只看正样本会全绿**。

### B2 · 行的边界形态（含不含换行符）
- **判据**：一侧"每行含尾换行"，另一侧剥掉。
- **实例**：一侧 = `split_inclusive('\n')`（行**含** `\n`），另一侧**剥**了；同一文件里 `scanf` 路径补了 `\n` 而 `getchar` 路径**没补** ⇒ 两个入口行为不一致。

### B3 · 空串 / 零元素极端
- **判据**：修好了"尾随分隔符"边界，漏了"空输入"。
- **实例**：修好 `"a\n"` 后，`("", 0)` 仍分叉——一侧 `"".lines()` = **零行**（`None`），另一侧当**一行空串**（`Some("")`）。

### B4 · 多字节字符的边界前移
- **判据**：增量 / 差分接口按字节游标推进，未回退到 UTF-8 字符边界。
- **实例**：输出 `delta` 的 cursor——一侧有 `while !all.is_char_boundary(start)`，另一侧没有 ⇒ 切出半个字符。

### B5 · 文法宽容（非法输入被静默接受）
- **判据**：解析器只"扫字符"不做文法校验。
- **实例**：JSON 数字里 `1e` / `01` / `1.` / `.5` / `1e+` 全部 **ACCEPTED**（RFC 8259 均禁止）。

### B6 · 递归深度无上限 ⇒ 栈溢出
- **判据**：递归下降解析器（JSON / 表达式 / 嵌套结构）**无 depth 计数**。
- **实例**：自写 JSON 解析器的 `parse_value` ↔ `parse_object/array` 递归无 depth 限制 ⇒ 深嵌套可致进程崩溃（`0xc00000fd` = `STATUS_STACK_OVERFLOW`）；`serde_json` 默认 **128** 层硬限制 ⇒ **两侧安全边界完全不同**。长驻进程（JSON-lines 服务）尤其危险。
- **注意**：阈值**不稳定**（依赖上下文 / 栈余量），复现可能不稳定——如实记录，别硬下"必崩"结论。

### B7 · 输出通道的去重 / 限额 / 幂等
- **判据**：一侧有 `if !contains(&msg) { push }` / 预算裁剪 / 首错优先之类的**状态相关**行为。
- **实例**：堆耗尽通报有去重（3 次失败只出 1 条），另一侧无条件 push ⇒ 3 条。

### B8 · 批量 / 转换 API 破坏输入（引用共享）
- **判据**：一侧是不可变借用（`.clone()` / 重建），另一侧共享引用 + 就地 `clear()`。
- **实例**：批量解码破坏输入——解码后原对象的字段被清零。

### B9 · 跨语言 JSON 输出的键序
- **判据**：一侧 `serde_json` 未开 `preserve_order` ⇒ 键**按字典序**；手写 emitter 常是**插入序**。
- **实例**：`{"behavior_contracts":…,"frozen_at":…,"schema":…}`（字典序）vs 实现 `schema` 打头。
- **同族面（2026-10-25 补，PR #303 审阅）：跨语言迁移的「逐字节一致」声称对**非确定性输出面**不成立**——旧实现用 map 迭代 + 不稳定排序 ⇒ 同输入连跑三次得到三个不同哈希。判据：声称逐字节一致前**先验参照实现自身是否确定性**（同一输入连跑 N 次比哈希 / 比字节）；非确定性面只能声称「集合 / 计数一致」，不能声称逐字节一致。新版用稳定排序（同计数按字节序）⇒ 差异是**修复**而非漂移，但旧声称须撤回（文档/提交信息的「逐字节一致」清单要逐项标确定性）。查法 = 参照实现连跑 N 次取产物哈希，N>1 且互异 ⇒ 该面不满足逐字节一致的前提。实例：Go 侧码分布用 `sort.Slice(kvs, v > v)`（不稳定排序）+ map 随机迭代 ⇒ 同计数诊断码的输出顺序逐次不同；TS 侧补同计数按码名字节序 ⇒ 两次跑哈希恒等。
- **同族面（2026-10-25 补，PR #307 审阅）：「逐位一致」声称的**比对选集 ≠ 声称全集**——只比主路径 / 只比判定字段，而元数据字段与旁路子命令从未比对**。判据：把声称覆盖的**子命令 × 字段**列成全集，逐格跑对拍；差集非空即过度声称。查法：① 子命令逐个 diff（`diff <(go … A) <(node … A)`，A 取 check / report / facts 等全部入口，不只 CI 那一行）；② 产物字段用脚本枚举差集（除 value/status 外还比 `source` / `note` / `how_to_get` 等元数据），别只比主值。实例形态：声称「22 键逐位一致 + 两子命令 stdout 逐位一致」，实测 2 键 `source` 不同（旧路径 vs 现役路径）、check 一致而另一子命令 stdout 两行不同——差异本身可能是有意的口径演进，但**声称须收窄并登记**，否则下游把「逐位一致」当契约。
- **同族面（2026-10-28 补，PR #342 审阅）：「新旧响应逐位一致」只比了**返回的帧数组**，漏了**窗口覆盖范围**——`cache_start_step` + 帧数是独立可观测面**。判据：同一 seek 序列两侧同时记 `{success, payload.step_index, payloads.length, cache_start_step}`，任一不等即「逐位一致」不成立（**帧内容逐位相同也照样分叉**：一侧返 N 帧、另一侧返 0 帧）。查法 = 逐 seek 记这四元组再比，别只对 payload 数组做 diff。根因形态：重放收尾窗口起点由**恢复锚点位置**决定（`frames.reset_to(cp)` 后只重放 `[cp..target]`，`cp` 近则窗口短），任何改变锚点分布的改动（淘汰策略 / 存锚节流）都会让 `target-cp` 变小 ⇒ 回看窗口塌缩，极端 `cp == target` 时窗口只剩 1 帧、`payload.get` 回看请求返空。处方：声称等价时把「窗口覆盖」列进比对面；若产品面要求「seek 后恒有 window-1 帧可回看」，取锚须下探到 `target-window+1` 以下，而非直接 `nearest(target)`。
  - **同族附带面（同一实例）**：等价论证若建立在「某行防止状态累积」上，先查该状态的**唯一写入点**是否与生效门互斥——互斥即该行结构性死代码、论证空转。查法：`grep` 该状态的写入点，与生效门条件并排看是否能同时成立；突变删掉该行跑全量 + 端到端对拍，全绿即坐实（此处不必报缺陷，但注释里的「等价性论证」须撤回，否则后续维护者会把它当不变量保留）。

### B10 · 相对路径基准不同（`dir_of` / 文件名解析）
- **判据**：一侧取"文件名所在目录"、另一侧取"当前目录"。
- **查法**：造形态极小语料（裸文件名 / `./x` / 绝对路径 / 子目录 / 嵌套 include 链 / 取不到的根相对路径），cwd 固定，双侧各跑一遍比 stdout。
- **同族面（2026-10-06 补）：键的「生成侧」与「查找侧」对 `.` 段归一化不一致**——宿主把文件集装进内存 VFS 时用 `dir + "/" + name` 拼键（`dir` 为 `"."` 时得 `"./h.h"`），而解析侧把候选键过一遍 `normalize_path`（丢掉 `""` 与 `"."` 段 ⇒ 得 `"h.h"`）⇒ **只有 `base_dir == "."` 这一种形态失配**；带目录段的路径（`sub/x.c`、绝对路径）两侧都命中，所以**语料一律带目录段就永远测不出**。查法：把同一份"含 `#include "h.h"` + 同目录有 `h.h`"的语料分别在 ① 裸名 / ② `./x.c` / ③ `sub/x.c` / ④ 绝对路径四种形态下跑一遍，**逐形态比"解析成功/失败"**（不要只比 stdout —— 该形态下失败会以"词法错误"形态出现，极易被当作语料问题）。实例：`dump_compile inc.c out/`（cwd 直下、cwd 内有 `hdr.h`）恒 lex-fail，而同一文件用 `dump/inc.c` 或绝对路径即成功；CI 语料路径全含目录段 ⇒ 零闸。处方：键生成侧与查找侧共用同一个归一化函数（`collect_files` 生成键时同过 `normalize_path`），或让 `dirname_of` 在无分隔符时返回 `""` 而不是 `"."`。

### B11 · 「宿主分叉」被套用到多宿主共用实现（另一宿主的既有能力静默丢失）
- **判据**：提交把某分叉登记为「**X 宿主**下的形态限制」，但改动落在**两个宿主共用的函数**里 ⇒ 另一个宿主原本具备的能力一并降级，而它没有任何锚。
- **查法**：对每一条「形态分叉」登记，先答两问——① 这段实现在哪些宿主/入口的调用图上（含另一宿主）？② 另一宿主在改动前**能不能**做这件事（读被删代码 / 查旧提交），有没有用例锁它？两问任一为"能/无锚"即命中。
- **处方**：要么按宿主注入（native 走真实 provider、wasm 走内存表），要么把登记口径改成"全宿主共享"并**给受影响宿主补一条能力锚**（否则下次仍会静默丢）。
- **实例**：协议层从 native-only 包上提到「native + wasm-gc」共享包时，quote-include 的 provider 由 `tokenize_with(<FsProvider>, base_dir)` 换成 `tokenize_with_vfs(<空表>)`；wasm 无 fs 成立，但共用函数让 native 壳一并丢掉了 `#include "..."` 的文件系统解析（oracle 同请求解析成功、本侧回 E1021）。被删的 provider/`dir_of` 复制件前后零锚，`serve_smoke` 只跑 `<stdio.h>`（走内建存根）⇒ 无闸可拦。

### B12 · 照搬时把 oracle 的辅助函数换成语义相近的另一个（同族对互替）
- **判据**：移植 / 照搬某函数时，oracle 调用的**辅助函数**在目标侧被换成"名字不同但用途相似"的另一个 ⇒ 在两者**不重合的输入域**上静默分叉；主流程逐行读起来与 oracle 一致，分叉藏在辅助函数里。
- **查法**：对每条照搬的函数，把 oracle 侧调用的辅助函数名**逐个抄出来**，与目标侧调用名逐一对齐；出现"名字不同"就立即用**独立小工程直接调这两个函数**、打印各自在各输入上的返回值，求出不重合域。**优先查同族对**（解一层 vs 递归、含某类 vs 不含某类）：`base_kind` / `immediate_base_kind` / `base_element_type`；`trim` / `trim_end`；`parse` / `parse_lossy`。
- **与 B1 的区别**：B1 = 同名函数语义不同（对位时误以为等价）；B12 = 语义不同的两个函数改了名字被互换——读码时看不出"替换"这个动作，因为两侧名字本身就不同。
- **实例**：`get_array_snapshots` 照搬 oracle（`memory.rs`）时，元素宽度与取值分支用 `base_element_type`（只递归剥数组、**不解指针**）替换了 oracle 的 `base_kind`（先解一层指针、再递归数组）⇒ 指针元素数组上分叉：`int*[2]` 的 oracle 输出地址数值、本侧全 `?`；`char*[2]` 连元素步进都不同（oracle 1 字节、本侧 4 字节）。
- **处方**：把"辅助函数名对齐"列为照搬验收清单的一项机检（两侧调用名对不齐即登记）；同族函数并存时在头注写明各自语义与适用面。
- **定责顺序（2026-10-11 补）**：发现同族实现**写法不一致**（弹宽 `pop_i32` vs `pop()` 并存、两处分派表分派序不同）时，**先从档案取 oracle 对应段对照再定责**——可能两侧是 oracle 原生两态逐字照搬（同族不一致 ≠ 移植分叉）。把 oracle 同形态报成"本侧引入"会污染病号台账；反例同在：oracle **有**而本侧**无**的分支（8 字节读分支被砍）是漏搬，归真缺陷。

### B17 · 转换 / 运算族按「种类」建表缺符号性对偶（2026-10-11 新增，与 B1 / B14 / B15 同族——那些是"换函数 / 换宽度"，本条是"整族缺对偶"）

- **判据**：指令集 / 转换函数按**种类**（算术 / 比较 / 转换 / 加载）成族实现，符号性对偶只补了**部分族**：i32 侧四则与比较有 U 系对偶（UDiv/ULt…），但**转换族**（无 unsigned→宽类型的 CastU2Q/CastU2D/CastU2F）与 **64 位族**（无 UDivQ/UModQ/ULtQ~UGeQ）整族缺失 ⇒ 该族**所有** unsigned→宽类型转换 / 无符号 64 位算术**静默分叉**（C 完全定义的行为，非 UB）。同族面：隐式转换收口只写**提升方向**漏**窄化方向**（`char c = 200` 存全宽读全宽；内存通道有 StoreMemByte、栈槽通道无——族内不对称）。
- **查法**：对指令集/转换函数全集列「**种类 × 符号性/宽度**」矩阵（有 U 对偶的族 vs 无对偶的族逐格点名，空号与历史死码单列），缺对偶处逐个构造探针——`(long long)4294967295u` / `(double)3000000000u` / `2^63 的除法取模比较` / `char c = 200` 一发一个族。**发射侧与执行侧要分别对矩阵**（两侧可能各缺一半）。
- **实例**：opcode 全集 135 条，i32 U 对偶完备而 Q 族无符号对偶全缺 + 无 U 系转换 ⇒ `(long long)4294967295u` → -1、`2^63 > 0` → 0、`x <<= 40` TRAP；收口函数三处（cast/assign/var_decl）零 char 臂 ⇒ `char c = 200` 读回 200。语料 unsigned 形状零覆盖（A2-b 同族），差分防线只证 signed 面有牙。
- **同族面（2026-10-18 补，P1-2 实证）：常量折叠层整层缺对偶**——求值器值域只有「整/浮」两态（无符号位），比较/除法/右移静默走有符号域、整↔整 Cast 恒等丢 unsigned ⇒ `(0u-1u)>0` 折 0、`(unsigned)-1>0` 折 0、`-1<1u` 折 1（clang 1/1/0）。同族症状：**运行时 VM 面有 U 系对偶、编译期折叠面没有**——指令层补过对偶≠求值器补过，逐层对矩阵。
- **处方**：矩阵当验收清单——补对偶按**族**补齐并连坐全仓穷尽 match（执行臂/发射臂/表驱动），别修一条冒一条；收口补窄化方向时把诊断文案（"可能丢失精度"）与实现逐条对表——**文案声称会丢精度而实现根本不丢，本身就是矛盾信号**。

### B18 · 宿主 VM 的检查性 trap 掩盖狗粮 C 资产自身的 UB（2026-10-15 新增，与 B1 / B12 同族——那些是"照搬换错函数"，本条是"资产把正确性责任外包给宿主 VM 的教学语义"）

- **判据**：随包发布、由 Vitro 自己编译运行的 C 资产（狗粮自举，如 `moonbit/teaching/tools/content_parser.c`）含标准 C 的 UB（有符号溢出 / 负下标）时，在 Vitro 三臂上因 VM 的**检查性算术与访存**表现为**干净 trap**——观感与 fail loud 无异，审阅易判"资产已有防护"；换 Clang（本仓判据源）实跑同一输入，UB 现形：**静默错误结果或段错误**。
- **查法**：对狗粮 C 资产的每个边界输入（超大索引 / 超长串 / 极值计数），**clang -O2 直跑 + Vitro 三臂各跑一次**，三方结论逐一登记；**VM trap ≠ 资产有防护**。实例：`param_notes[<i>]` 槽位累加 `idx = idx*10 + digit` 无溢出防护——Vitro 三臂均 TRAP（乘/加法溢出，干净）；clang -O2 下索引 `4294967296`（2^32）wrap 成 0 ⇒ **静默落入槽位 0**（条目照常发射），索引 `2147483648`（2^31）wrap 成负下标 ⇒ **段错误**；仅当 wrap 结果 ≥ 上限才被既有 `idx >= MAX_SLOTS` 检查挡住（巧合，非防护）。
- **处方**：边界防护写在资产自己身上（位数上限 / 溢出检查累加 → fail loud），不依赖宿主 VM 的教学语义；验收时 clang 侧必须同输入同结论（狗粮资产的"常驻对拍"若只跑 Vitro 臂，此面永久隐身）。

### B13 · 迁移批把"多族 / 多模块聚合"的顺序按自己的组织重排 ⇒ 输出列表序与 oracle 不同
- **判据**：oracle 的聚合函数按固定次序 `extend` 多个族（算法判据各族 / 校验器各规则组 / 字段各来源），迁移侧按自己的文件切分或语义分组**重排**——同一输入**同时命中多个族**时，产出列表的元素顺序与 oracle 不同（每个元素本身逐字相同）。
- **查法**：① 把两侧聚合函数的调用序列并列逐项对齐（例：`algorithm_detector/mod.rs:35-41` 的七行 `extend` vs 迁移侧 `detect.mbt:35-46` 的四个 `for`）；② 构造**同命中多族的输入**——先用聚合内的单项函数分别验证"每个族都命中"，再按各自调用序推列表序。**只命中单族的样本永远测不出顺序差**（A5 同族：样本对两个候选序无判别力）。
- **与 B9 的区别**：B9 是**序列化键序**（JSON 对象成员名）；B13 是**列表元素序**（数组/向量），差在数据形态与比较口径。
- **与 B12 的区别**：B12 是"某个辅助函数被换掉"（单点语义）；B13 是"多个族的相对次序被重排"（聚合结构）。
- **处方**：把"聚合顺序"列为照搬验收清单的一项机检（两侧调用序列逐项对齐）；或迁移侧直接沿用 oracle 的 `extend` 次序，并在头注写明"顺序属输出面，不可重排"。
- **实例**：算法判据聚合 oracle 序 = sorting → search → graph → tree → structures → string → math（+dp 附加），迁移侧排成 sorting → search → **string → tree**；函数名 `bstKmpSearch` 同时命中 tree（`bst_search`）与 string（`string_match_kmp`）⇒ 两侧 `matches` 数组序**相反**（查法：同包临时 wbtest 直调各族判据，按两侧聚合序各拼一次列表、比首元素）。纯单族样本（如 `mergeSort`）两侧逐字一致，故该类差异此前未被察觉。

### B14 · 移植时浮点字段宽度被放大（oracle `f32` → 目标 `f64`）

- **判据**：照搬的 struct 字段 / 中间量在 oracle 侧是 **`f32`**，目标语言侧写成 **`f64`**（反之亦然）。**读码几乎看不出问题**——两侧源码都写着同一个算式、同一组常量，差别只在类型宽度。
- **为什么危险**：分叉**只在「算不出有限短小数」的取值上出现**。两者对源里的十进制字面量（`0.9` / `0.75`）的**最短往返 repr 相同**，所以常量表类字段（边权 / 权重 / 阈值）全绿；而**除法产生的比值**（`count / window`、`a / b`）在 f32 与 f64 下的最短 repr 不同 ⇒ 序列化出来的字符串分叉。**锚样本若恰好取可精确表示的比值（如 `3/4`），对宽度零判别力**（A1-c 同款：样本没落在能区分两者的取值上）。
- **查法**：① 逐字段对比两侧的浮点宽度声明（`f32`/`float` ↔ `Double`/`f64`）；② 对每个浮点字段问「它的取值是常量还是**算出来的**」——算出来的才算候选；③ 对候选比值用脚本枚举两侧最短 repr（f32 侧按 ryu/serde 语义取最短往返，f64 侧取 `repr`）求差集。**只比两侧源码文本必然漏掉**。
- **与 B12 的区别**：B12 是辅助函数被换成另一个（语义不同）；B14 是同一个算式被换了**运算宽度**（语义形式相同、数值结果不同）。
- **实例**：某检测函数的 `confidence` 在 oracle 是 `f32`（`count as f32 / denom as f32`），迁移侧声明成 `Double` ⇒ 比值两侧字符串分叉，而锚里唯一的比值样本是 `3/4`（两侧都是 `0.75`）⇒ 零判别力。同批同一 struct 的 `strength` 字段也是 f32→f64，但取值全是源里写的十进制常量 ⇒ 实测无分叉（**是常量表遮蔽，不是宽度无害**——换一批非常量取值同样会分叉）。
  - **纠正（2026-10-02 复核；原实例所写的 oracle 侧文本有误）**：原实例记 oracle 侧为 f32 最短表示 `0.6666667`，**实测不成立**——oracle 走 `json!`（`Value` 路径），`f32` **已被提升为 `f64`**，wire 文本是 **f64 最短表示** `0.6666666865348816`。那个 `0.6666667` 是照"oracle 是 f32 ⇒ 本侧用 f32 ryu"**推断**出来的，未经原始字节验证；该误述当年直接误导过一次实现（见下条同族面）。**判文本口径前必须先取原始响应字节。**

- **同族面（2026-10-02 补入 B14，不新开编号）**：浮点 wire 文本是**序列化路径**的函数，**不是类型宽度的函数**——宽度两侧全一致也照样分叉。
  - `serde_json` 两条路径产出**不同文本**：`json!` / `to_value` 走 `value::Serializer`，其 `serialize_f32` 是 `Value::from(f32)` = `Number::from_f64(f as f64)`（`src/value/ser.rs`）⇒ 文本 = **f64 最短表示**；而 `#[derive(Serialize)]` + `to_string` 路径走 `ryu::Buffer::format_finite(f32)` ⇒ 文本 = **f32 最短表示**。
  - 照搬时若按"oracle 侧是 f32 ⇒ 本侧用 f32 ryu"实现，得到的是**值对、文本错**：本侧 `0.6666667` vs oracle `0.6666666865348816`。可达比值枚举实测 **26/45 分叉**，只有 `0.5` / `0.75` / `0.25` 一类二进制精确比值同文本。
  - **查法**：① 先判 oracle 该字段的**序列化路径**（`json!`/`to_value` ⇒ Value 提升；`derive(Serialize)` + `to_string` ⇒ ryu 直排），再定文本口径；② 用**原始响应字节**验证——解析成数值再比会掩盖差异（两侧各自解析后"看着都像 2/3"）；③ 端到端锚要挑**非二进制精确**的样本（`3/4` 对两种口径都同一文本，零判别力，同 A1-c）。
  - **反面提醒**：锚若把**推断出来**的文本钉成期望值，就锁死了错形态（A3）——按 oracle 改对实现反而变红。

### B15 · 照搬格式化占位符时位宽语义不重合（2026-10-03 新增，与 B12 / A1-c 同族）

- **判据**：oracle 用格式化占位符产出的文本（`{:04X}` / `{:02}` / `{:>8}` 之类）在目标侧**手写替代实现**（目标语言无同名格式化 API），替代实现把占位符语义读成"恒定位宽"或补位方向相反 ⇒ 只在**部分取值**上分叉：取值超过最小位宽时两侧一致，未超过时一侧补零另一侧不补（或位数不同）。与 B12 的分工：B12 是"换了一个已有的同族函数"，本条是"新写了一个替代实现"；与 A1-c 的分工：A1-c 是数值临界样本，本条是**文本位宽临界**。
- **查法**：① 把 oracle 侧每个格式化占位符逐条抄出，标注它的**最小位宽 / 填充方向 / 截断规则**；② 对每个替代实现，用**跨越最小位宽的三个取值**（小于 / 等于 / 大于 10^位宽）实测两侧输出文本；③ 端到端响应里的**总长度差**是最快的旁证——差值恰等于「行数 × 每行位宽差」时即为本条。
- **实例**：oracle `format!("addr=0x{:04X}", addr)` 对 `0x5018` 输出 `5018`、对 `0x501` 输出 `0501`、对 `0x123456` 输出 `123456`（**最少 4 位**，Rust 语义实测）；照搬侧手写"按 32 位逐 nibble 输出" ⇒ 恒 8 位 `00005018` / `00000501` / `00123456`，**三者全部不等**。该分叉只在"取值不足 5 位 hex"时显现，而端到端锚恰好把 8 位形态断言成期望（A3：锚锁死错形态，按 oracle 改对反而变红）。复现 = `rustc` 打 `{:04X}` 三个取值 + 目标侧直调替代函数比文本。
- **处方**：把"占位符语义（最小位宽 / 填充方向）"列入照搬验收清单逐项核；端到端锚改用**能跨最小位宽**的取值，别用"恰好等于位宽上限"的样本锁形态。

### B16 · 用「全局单表 + append-only」近似作用域 ⇒ 内层同名遮蔽污染外层查询（2026-10-07 新增，与 B10 同族）

- **判据**：解析期要"查某个名字的类型 / 尺寸"（`sizeof(变量)` 折叠、枚举常量求值、断言求值），实现用一个**全文件单表**（每次声明 append / set，**离开作用域不回滚**）来近似作用域。于是**内层 block 里重名同类型的声明会覆盖外层条目**，而该形态之外一律正确（不重名 / 不同层 / 顺序相反）。
- **为什么危险**：与 B10 同款——"近似实现只在特定形态上分叉"，语料里几乎不会有"同名跨作用域 + 在内层之后于外层查询"的组合 ⇒ 全量门禁绿，而用户写出嵌套块就翻车。且修复批常把它当"顺路小功能"接进来，自验样本只取**无遮蔽的单表形态**。
- **查法**：① 造 `int x; { double x; … }` 与 `if (…) { double x; … }` 两种形态，在其**之后于外层**求值 `sizeof(x)` / 用 `x` 求常量，与 Clang 比"编译成功与否 + 折叠值"；② 读实现问三句——表是**单表**还是**作用域栈**？**离开 block 有没有回滚水位**？快照函数是不是只遍历单表？
- **与 B10 的分工**：B10 是**键归一化**两侧不一致（`. `段）；本条是**作用域**近似不完整（同名遮蔽）。共同点：都属"近似实现在边界形态上偏离真值"。
- **实例**：某批为 `_Static_assert` 的 `sizeof(聚合/变量)` 折叠加了"已解析聚合表 + 变量类型表"，两表都是**全局 append-only 数组**（只记 `save/restore` 水位、无 block 级 push/pop）；`_Static_assert(sizeof(x)==4)` 在"外层 `int x` + 内层 `double x`"下取到 8 ⇒ 报「断言失败」（Clang 编译通过），而同一批的锚样本（单层声明）全绿。
- **处方**：表按**作用域栈**维护（进入 / 离开 block 各 push / pop），或查询沿作用域链取最近声明；常量求值的"快照"必须反映**查询点**的作用域，而不是文件末尾的全量表。
- **同族面（2026-10-23 补）：遮蔽/恢复记录扩字段时把「另一族表」的旧值硬编码 None ⇒ 退出作用域把另一张表的同名条目删掉**——作用域栈扩到第二张表（static/普通两族分开记）时，登记条目对不属于本声明路径的字段写死 `None`，而恢复臂按「Some→set / None→remove」无条件执行 ⇒ 同名字被另一族登记过时，退出块即把外层条目 remove。判据 = **三形探针**：外层 A 族+内层同名 B 族+块末回外层读、反串（外层 B 内层 A）、参数形（参数作外层）三形都要打。实证：PR #282 审阅 P1（三形误拒 E0；修复 = old_ 全取 `get(name)` 真值——但仅此不够，见下条）。
- **同族面（2026-10-23 补）：解析链优先级把症状从「误拒」升级为「静默错指且零诊断」**——同名字被上条误删后，读解析若按 local→global→static_local 逐级兜底，被删表垫底时同名字落进 global 臂 ⇒ 不报错、写进全局（比误拒更危险：c=c+1 写进 global 输出 501 零诊断）。且**修掉误拒后链序病显形为块内错值**（内层 static 声明没把 local 表同名条目挤出去，块内读错指外层普通槽/参数槽——修复须登记时对称 remove 另一张表，退出由恢复链对称 set 回）。查法：误拒形态探针旁**必配「同名 global 并存」对照形**。实证：PR #282 审阅 P1 四形（误拒 E0×3 + 静默错指 501）与处置批 p1b/p1c 块内错值。
- **同族面（2026-10-23 补）：static 局部解析排在 global 之后**——无嵌套块形态下函数级 `static int c` 与文件作用域 `int c` 同名，链序垫底致 static 声明整个失效（读写全落 global，静默错值；反向突变定责为存量）。处方在 issue #283 在册：static_local 臂前置于 global 臂，**8 个消费点逐一同改勿修一个冒一个**。

### B19 · 视口媒体查询与容器查询的「互补断点」基准不同（滚动条宽度裂缝，2026-10-24 新增，与 B1 同族——两套判据名义等价、实际基准不同）

- **判据**：同一布局断点同时用 `@media (max-width: N)`（按视口宽，含滚动条）与 `@container (max-width: N)`（按容器 inline-size，不含滚动条）写互补的两侧（如 `≤1179` 与 `≥1180`）。桌面经典滚动条宽度非零 ⇒ 存在 **N..N+滚动条宽** 的视口区间：容器已判「窄」（单栏），媒体查询仍判「宽」（不触达）——依赖媒体查询的那一半样式/定位在单栏形态下不生效。
- **查法**：① 先量 `window.innerWidth - document.documentElement.clientWidth`（滚动条宽，**勿假设 0**；headless/overlay 滚动条可为 0，真实桌面常 15–17px）；② 在断点边界 **±滚动条宽** 的若干宽度下测两侧计算值（`getComputedStyle` 的 `top/display/padding`），不要只测断点两侧各一格；③ 同步测「该宽度下容器查询实际命中的形态」（三栏 grid 是否已塌成单列），两侧基准的判定必须落到同一个元素状态上。
- **实例**：某页把「三栏↔单栏」写容器查询 `min-width: 1180px`，把「toast 移位 / 顶栏高度变量」写视口媒体查询 `max-width: 1179px`；滚动条 15px 时视口 1180–1194 ⇒ 容器 1165–1179（单栏）但媒体查询不触发 ⇒ toast 仍压在单栏代码区。窄档同理：视口 761–780 时容器已 <760（窄档样式生效）而媒体查询未触发（高度变量仍是宽档值）。
- **处方**：断点归一时二选一，**不要混用**；必须混用时，媒体查询上限写成「容器断点 + 实测滚动条宽」并把该值登记为环境假设（overlay 0px vs 经典 15–17px）；注释里写明两套查询各自的基准，别用「等价」措辞掩盖差值。

### B20 · 有状态接口的输出内容依赖拉取形状（批量参数），契约却自称同构（2026-10-31 新增，PR #396 审阅——与 B1「名义等价实际基准不同」同族的协议面变体）

- **判据**：同一 API 同一输入，只改「一次拉多少」的批量参数，**返回内容本身**不同（不是分页切片差异，而是字段级语义差异）——典型根因是跨批状态机的清理/去重判定在批量=1 的退化形态下被跳过（如 `pop()` 后判 `length()>0`，批=1 时恒空）。协议契约文自称「跨批拼接与单帧流同构」时该句即为**未验证声称**。
- **查法**：① 同源码同臂跑**两种极端批量**（单批一次拉全 vs 每次拉 1）做帧级 diff——差异字段分布直接定位语义面（形状：逐帧口径的标注帧占比膨胀到近八成、行中间帧带标注从无到有，单批口径两者皆近零）；② 找下游**真实口径**（前端 worker / 既有调用方实际用什么参数——wbtest 锚往往只测一种批量形态，另一种裸奔）；③ 既有「行末/边界不变量」锚改批量参数重跑（锚只在 `frames:50` 批形态下绿 ≠ 不变量成立）。
- **实例**：`step.next {}`（前端 worker 真实口径）vs `step.next {frames:N}` 单批——同程序两口径的帧级 diff 唯一差异字段即标注字段；根因 = 跨批 pending 的同行清标注判 `payloads.length()>0`（pop 后），批=1 恒空被跳过（复现判据：gateway/serve_step.mbt 跨批 pending 分支；issue #399）。
- **处方**：跨批状态判定改「pop **前**参照」（批=1 时参照即刚弹出的那一帧，两形态统一）；补**批=1 形态锚**（不变量锚参数化跑双形态）；契约文的自称句在锚齐前降级为「目标语义」并登记缺陷。

## C · 死面 / 无生产者 / 不可达

### C1 · 字段声明了但从不被读
- **实例**：某结果结构体的 `abnormal` 字段**从不进入判定** ⇒ 耗尽的异常结果（stdout "" + exit 0）与"程序本无输出"不可区分，可致**假 SAME**。
- **同族面：类型 / 接口声明了字段，但零消费者**（2026-10-04 补）：TS 迁移把 wire DTO 手写成 `interface`，文件头注还写着「字段 = 消费面实际读取集」，实际有相当一部分字段（及若干嵌套 interface）在全库**零引用**，也无任何用例能反证它们 ⇒ 声明面永不腐烂也永不生效，读者还容易把"有类型"读成"已接线"。
  - **查法**：① 对每个声明字段 grep 全库（排除声明文件自身），命中 `0` = 无消费者；② 再答第二问——**它有没有被实测观测到**（写探针直调制品，dump 该字段是否存在 / 是否出现过非空取值），两问皆否即"幽灵声明"；③ 把**声明字段集**与**运行期实测字段集**求双向差（两侧都算，才同时抓"多声明"与"漏声明"）。
  - **与 C2 / C6 的分工**：C2 = 无生产者（写了没人产出）；C6 = 消费者到了 DOM/模板但无消费终点；本条 = 连消费者都没有，而**声明面声称有**。
  - **处方**：无消费者的声明删掉或移入显式标注的「预留（未接线）」块；要保留就把该字段接进冒烟闸的键断言。
- **同族面：样式表规则「有声明、无使用者」**（2026-10-04 补，反向的 C1）：重构删掉 DOM 与渲染模块后忘了删对应 CSS，`class` / `id` 选择器变成永不匹配的死规则——声明面声称生效、实际零消费。查法：对每条待验 CSS 规则抽取选择器里的类 / id 名，全库（排除 CSS 自身）grep 使用者；**正向闸（JS 引用的 class 必须在 CSS 有定义）抓不到反向**（工具类 / 预留态会误报，故正反两向须分别有闸）。实例：某批删掉一个 tab 的 DOM 与渲染模块后，该 tab 专用的一族 `.algo-*` 规则与另一个 `.crs-title` 规则全部留在样式表里，而 JS↔CSS 正向对账闸全绿。
- **查法补丁（2026-10-11 补）：下「零消费」结论前，grep **数据键名字符串**全仓，不是 grep `get("键")` 调用**——消费点常是**闭包动态键**（`map.get(key)`，key 来自上游枚举/循环），按字面量 grep 会漏，产出「N 键零消费」假病（差点把 trap_messages 的 13 个动态查表键误判成死数据；静态键面 45 键全消费）。两步走：① grep 键名字符串 → 有动态命中 → ② 追 key 的来源集合与表键集求差，差集才是真死键。
- **同族面（2026-10-25 补，PR #312 审阅）：冻结清单里的「源哈希」字段写了从不读，且其值随检出行尾翻转 ⇒ 清单与语料的绑定关系实际不存在**。差分闸的冻结清单常带一个「源文件哈希」字段（记录冻结时对应哪份字节），但比对路径只比行为面（退出码 / stdout 指纹 / 内存指纹），该字段**写了从不读**（冻结路径也无条件重算，不按它跳过）⇒ 它既不能判红，也不能证明「清单与当前语料同源」。更隐蔽一层：该哈希若取**磁盘原始字节**（不做行尾归一），值随**检出态**翻转——同一文件在 CRLF 陈旧工作区与 LF 规范检出（`.gitattributes` 锁 `eol=lf`）下算出两个值，冻结时处于哪一态决定全部条目的值。查法三问：① 该字段是否出现在**比对条件**里（grep 比对表达式，无命中 = 死字段）；② 同一文件两态各算一次（CRLF 工作区 vs LF 归一），不相等即检出态依赖；③ 冻结值与规范检出态的算值逐一比，差集规模 = 错配条目数。处方：哈希先做行尾归一再算（与语料装载口径一致），或把它接进比对条件（源字节变了就要求重冻），或从清单删掉——别留一个看似承重实则死掉的字段。

### C2 · 字段只有"读 / 测试赋值"，**没有任何写入方**

- **子条（第十一轮 P2-2，2026-10-09）**：入仓冻结基线的写回路径随 oracle 退役失效 ⇒ 基线变只读死资产（libc_boot_diff --freeze 需已删 exe）；查法 = 逐基线跑一次其刷新命令看是否 fatal；处方 = 补删区后 --freeze-mb 入账通道。
- **判据**：grep 某字段，只有【定义 / 初始化为 `[]` / 读取 / 白盒测试手工赋值】四类，**无生产者**。
- **实例**：`file_ranges`——对应实现在**引擎层的多文件管线**（活跃区侧无该包）⇒ 多文件分支**逻辑已测、生产者未接**，看起来"已生效"。
- **处方**：要么登记"生产者待接线"，要么加闸。
- **同族面（2026-10-24 补）：CSS 变量「单源」只有声明、声称归它管的消费面没接线（假单源）**——token/高度/间距写成 `--x: 65px` 并在多处 `calc(var(--x) + …)` 消费，但被声称由它管理的组件**没有 `var(--x)` 消费点**，组件高度仍由 padding / 内容撑开 ⇒ 变量只是复制值，组件样式一改消费者不跟随。查法 = `grep -rn "var(--x)"` 核声称的组件是否在消费面；再实测 `getComputedStyle` 的真实值与变量值比对（**断言二者不等即坐实，别只看变量定义**）。实例形态：顶栏高度变量 65/63px，实测 66.2px；窄档内容换行时实际 156px 而变量仍 65px，「单源」实为双源 —— 依赖它的 `scroll-padding-top` 与 toast 定位同时失准。

### C3 · 接线臂不可达（"已接 N 臂" ≠ N 臂可达）
- **判据**：预注册表把某名字全量塞进调用表，导致宿主臂成死面。
- **查法**：`dump-compile` 一个逐名调用探针，看该名字发 `CallHost` 还是 `Call 10xx`；再用路由表交叉核对。
- **实例**：`isdigit…isxdigit` / `rand` / `srand` / `abs` 等 14 臂全不可达，但测试"通过"并在锚**幽灵行为**（锚的是宿主实现的随机序列，真实路径走 libc 实现）。

### C4 · 死参数 / 死代码（修复的副产品）
- **判据**：改了实现后，参数 / 变量不再被使用。
- **查法**：`moon check` 的 warning 增量（`unused_value` 族）。

### C4-b · 呈现层「锁死态」无人解锁（2026-10-03 审阅新增；C4 同族）
- **判据**：HTML/模板写死 `style="display:none"` 或等效隐藏态，而 JS 侧**没有任何代码改回它的 display** ⇒ 该区块（常含标题与教学说明）对用户永久不可见。
- **查法**：对每个内联 `display:none` 元素，grep JS 有无对其 `style.display` 的赋值或等价 class 切换；**零命中 = 锁死**。实例：`#array-viz-head`（数组区标题+「指令级中间态」教学说明）写死 none，渲染函数只切了内容容器不切标题——用户永远看不到这段说明。

### C5 · 同族实现里漏改一处
- **判据**：一串同类实现，逐个数"有几个用了做法 A、有几个没用"。
- **实例**：6 个输出通道里 5 个重建、1 个共享引用；3 个分配臂改了 trap loc、同文件的 `free` / `unreachable` 没改。
- **同族面：同一命令 / 同一语义有多个出口，各自独立实现同一段组装，只锚了其中一个**（2026-10-04 补）：一个子命令常有「文本出口」「结构化出口（`--json`）」两套，或「CLI 出口」与「服务/会话出口」两套——它们**各自把手写组装重写一遍**（同一步数序列照抄），而门禁只端到端跑其中一套（通常是有防线的那套）。于是第二套的差异既无锚、也不在差分驱动器的输入面里。
  - **查法**：① 把该命令的**所有出口**列出来（`grep -n "kind\|mode\|json" <命令行解析>`），逐个跑**同一组探针**——探针里必须含「零值 / 缺省 / 空」形态（见 A1-g 同族面）；② 比的不只是 stdout，还有**程序可见的运行时事实**（`argc`/`argv[0]`、堆起始、输入模式、note 通道是否可达）；③ 再问"两套实现各被哪道闸盖着"——只有一套进差分驱动器的，另一套就是纯读码面。
  - **实例**：某 CLI 子命令的文本出口手写「装载 + 运行 + 取 stdout」序列，结构化出口改走会话/网关（另有一份同序列照抄）。零附加参数时：文本出口 `argc=1`、结构化出口 `argc=0`（程序解引用 `argv[0]` 即 trap）；`-i` 类输入在文本出口是 batch（耗尽即 EOF），在结构化出口是 Interactive 且只喂一次 ⇒ 循环读输入的习语输出全丢而退出码 0。两套都能"跑通"，差异只在边界与输入语义上。
  - **处方**：两出口共用同一组装入口（本次实证的教训：把组装下沉成一个函数两出口调用）；或给第二出口补一条与第一出口**同输入同断言**的端到端锚。
- **同族面：N 个同族实现里「副作用写入点」只有一处写对**（2026-10-05 补；与主条"漏改一处"同族，差在**时序**而非覆盖）：同一功能在 N 处各实现一遍，其中只有一处把「**先验证、后落盘**」写对，其余是「先落盘、后验证」——**稳态（全绿）下 N 者行为完全相同**，只在**失败路径**上分叉（其余 N-1 处把脏产物留在盘上，而落盘的脚本自己并不因此红）。
  - **查法**：把同族的**副作用点**（写文件 / 建制品 / 提交 / 推送）列成一列，逐个数"写入发生在验证之前还是之后"；再**构造一次失败**（让验证红）看脏产物是否落盘。只看"跑绿了"永远看不出。
  - **实例**：五驱动共用「固化清单」语义，`vm_diff` 走"全量跑双侧 → 对拍全绿才 `WriteFile`"；另三驱动是"先 `saveDigest` 再对拍"；lexer 更是"只跑单侧、零对拍直接落盘"⇒ 与现场不符的清单照常入库，而 freeze 自身退 0。
  - **处方**：写入下沉到「验证通过」之后（本次处置：`pending + flush`——产物暂存内存，`rc == 0` 才落盘）；同族逐一改完再收工（勿只改报出来的那一个）。
- **同族面（2026-10-11 补）：同包「成对实现点」——同语义两份实现，修了一处漏另一处**。查法：读码时对每个「拦截臂 / 求值器 / 深度防护」，**grep 全包同名语义的第二实现**并排对比（`eval_enum_const` 已迭代化+锚 vs 同包 `const_int_of` 仍递归裸奔——新函数完整复刻了被修掉的栈溢出病；全局 `struct Q;` 前向声明已拦 vs 局部形态漏；聚合拦截臂 `parse_var_decl_stmt` 有 vs `parse_base_type` 无）。一轮实证三连——**修过的病是该包同语义实现点的免费排查清单**。
- **同族面（2026-10-11 追补）：新增 enum 变体时「N 消费点连坐」的 N 按「类型系统」数，漏掉「常量求值族」**。给运算符 / 类型种类加枚举变体（如一元 `+` 的 `UnaryOp::Pos`）时，提交按「解析 / 类型推导 / 代码生成 / 接口面」数列消费点并逐点连坐，而**同语义的常量折叠 / 常量性判定族**（`apply_unary_const`、`is_int_constant_expr`、`const_int_value` 之类——同一"这表达式是不是编译期整型常量"的语义在多个函数各实现一遍）**不在该清单里** ⇒ 真值为合法常量表达式的输入在常量位报错：`enum { A = +5 };` 报「初始化器必须是编译期整数常量」、`case +7:` 报「标签必须是常量表达式」（真值两处均编译通过）。查法：新增变体后 `grep` 该变体名的**全部** `match` 臂与 `is` 判定点，**尤其搜「常量 / const / fold / 折叠」族**；对每点问「该变体走哪个分支、兜底 `_` 会不会把它判成错」。旁证形态：同文件的姊妹函数往往**注释已写该变体、实现却没写**（`const_int_value` 头注写「Literal/Neg/Pos 三形」，实现只有 Neg/Not——E5）。对照：给漏点补上该变体后全量测试仍全绿 ⇒ 零锚（清单与锚漏了同一族）。
- **同族面（2026-10-11 补）：「按格式预取参数」与「按格式消费参数」分两处实现，消费口径错位**——预取层（决定取几个参数、每个几字节）与格式化层（真正读参数）各写一份对 fmt 的解析，两份对**同一 spec 形态**（未知说明符 / 变参 long）的口径不一致 ⇒ 参数错位或错读。**单侧读码的「同构」声称不构成证据**（头注明写"布局同构"、实测 long 取参错位）。查法：对同一 fmt 串端到端跑一遍预取+消费全链，与 Clang 逐参对拍；重点形状 = 未知 spec（预取不推进 vs 消费消耗 1 参）与 64 位实参（步进宽度两份各自维护）。
- **同族面（2026-10-15 补）：新增「入口/后端」时，其分派表与既有入口不同构**——新增一条入口（薄壳 / 新后端 / 新可执行文件）时，作者按"本入口只服务主路径"的心智只实现**主路径那几个子命令**，而既有入口的分派表里有 `help` / `serve` / `dump-*` / `--help` 一类**旁路与自描述子命令**；两份分派表逐项对不上，而"单壳单语言 / 消灭双真相"的声称让读者以为二者同源。查法：**把两份分派表的 match 臂逐项点名求差**（`grep -n '"\w*" =>' <两个入口>` 并排），差集逐条问"这个子命令在新入口落进哪个兜底"。处方：新入口的分派表从既有入口**整表照抄**（差异只在外壳 IO 绑定），或把分派表下沉进共享 lib、入口只传 IO provider。实例形态：新后端入口比原入口少 `help` / `serve` / `dump-tokens|dump-ast|dump-typeck|dump-compile` / `--help|-h` 共 7 个臂 ⇒ 默认臂切到新入口后 `vitro help` 落进 `_ =>` 打印「未知命令」。与 **C5 主条**分工：C5 是"同族实现漏改一处"，本条是"新写的族员**从一开始就没对齐**族规"，两者查法相通（逐臂并排求差）但病灶不同（漏改 vs 未对齐）。
- **同族面（2026-10-15 补）：一批改同族多点时，只给「被 issue 复现的那一处」埋锚**——同批改动落在同语义的 N 个实现点（`scanf` 与 `getchar` 的同一判定前置、`run` 与 `input.feed` 的同构出口、`E→W` 排序在某阶段的多个早退分支）时，锚只覆盖复现路径上的那一个 ⇒ 其余点改坏零判别力。查法：**按"同批改了哪些同族点"列清单 → 逐点做突变注入**，只有清单外的点能全绿才算命中（本条与 A1-f「同函数族锚位错位」同源，A1-f 说的是"锚挂在哪条路径"，本条说的是"**同批修了几个点就只埋了几个锚**"；两者的对照要求一致：必须带"同文件里已知有锚的点改坏应红"作对照，否则只能说整套没牙）。
- **同族面（2026-10-15 处置回执）：run/feed 双出口手写组装**——`serve_execute_run` 与 `serve_execute_run_via_engine` 各自手写七字段出口（含 #91 `output_truncated` 位追加时改两处），本轮处置下沉为 `run_outcome_json` 单源（审阅 P3）。这是 C5 主条「同族实现里漏改一处」的**未爆弹形态**：本次逐字段一致，但下一次字段演进只改一侧就是静默分叉——查法同主条（逐字段并排求差），处方是出口函数化单源。
- **同族面（2026-10-23 补）：聚合体后声明器组 struct/union/enum 三份孪生实现只改一份**——「体后声明器 + 初始化器」在 parser 有三份同构 while 循环（aggregate trailing / enum trailing / 完整路径），修 union 侧（#278）时只补了 aggregate 臂的 init 解析，enum 侧孪生循环同款 `init: None` 漏改（`enum {A,B} e = B;` 报 E2005；struct 侧则因分类层把带声明器形态路由到完整路径而幸免——**两路径不对称是只咬 union 的原因**，读者从病面反推不出第三份孪生）。旁证 = **「X 无 trailing 故不触发」类注释的误读风险**（「本函数不路由 X」会被读成「X 没这个形态」——处置时已改写为「enum 自带孪生 trailing 循环……勿读作无此形态」）。判据：`grep -n "init: None" <parser 全域>` 列全孪生点，逐个点名求差。实证：PR #282 审阅 P2-1。
- **同族面（2026-10-24 补）：给错误通道新增「结构化码」时按测试/基线覆盖到的那几条接线，漏掉其余同族臂**——批次标题写「运行期 trap 立码」，实际只有单测/协议帧打到的那条带码；更隐蔽的是**同批写成文的不变式**（"带码文案首段 ⇔ 结构化码"）在自身上就有反例（文案印着 `(E3070)`、结构码传 `""`）。查法：把所有「文案里含 `(E####)` 的 trap 点」列一列，逐个比对 code 参数；对每个漏点做**补码预演**（补上正确码后全量测试仍绿 = 该码零锚）。实证：`DivQ`/`ModQ`（`long long` 有符号除/模零）走独立臂不带码，补码后 `moon test` 884/884 仍全绿；`stack_buffer_check` 的 strcpy/strcat/scanf 栈缓冲臂文案带 E3070、结构码传 `""`，同法零锚。
- **同族面（2026-10-31 补，PR #403 审阅）：改「方法面 / 条目面」时的计数副本清单会漏掉**两类零闸副本**——UI 常量与人读文档**：提交自己列了「五处计数锚」（错误帧自报文案 / 生成器 rules 表 / 页面计数句 / 帧数 / CLI 内容锚），实测仍漏：① **前端 TS 常量**（方法分组表里的 `METHOD_TOTAL = 26` 类字面量——它只喂渲染、不喂断言，闸读的是另一份）；② **人读文档的方法导览表 + 版本归属表**（该表自述「新字段上帧时必须在此登记」，却在同日头注「已核对」的状态下不含新方法）。查法：`grep -rn "<新条目名>" demo/src scripts docs/current` 与 `grep -rn "<旧计数>" demo docs` 双扫，把命中分成「喂断言 / 喂渲染 / 喂人眼」三类，逐类定连坐；渲染类副本的闸面 = 有没有断言读它（没有就是零闸）。处方：渲染类计数收敛到一个可机判单源（或让 UI 常量从生成物读），并在探测「计数连坐」时把文档表列进清单——**闸绿 ≠ 副本齐**，闸只覆盖它读的那几份。

### C6 · 「消费语句存在但无消费方」（有消费者、无消费终点）
- **判据**：字段被读进 DOM class / 局部变量 / 模板串，但**下游没有任何东西真正消费它**（无对应样式定义、无分支判断、无输出通道），字段值对最终呈现零影响。
- **查法**：对每个"写进 class / 传给模板 / 存进局部"的字段，**追它的消费终点**——class 名在 CSS 里有没有定义？变量在后续分支里有没有被读？**"赋值了"不等于"生效了"**。
- **与 C2 的对偶**：C2 = 无生产者（写了没人产出）；C6 = 有消费者但无消费方（读了没人消费）。两者都表现为"看起来已接线"。
- **实例**：前端 `class="diag ${severity}"` 把 `severity`（error / warning）写进 DOM class，而样式表只定义 `.diag` 基础样式与 `.diag .code` / `.diag .fix` / `.diag .loc`，**没有 `.diag.error` / `.diag.warning`** ⇒ error 诊断与 warning 渲染外观完全相同，severity 对呈现零影响（查法：`grep -n "\.diag" style.css` 只有基础样式；同族检查法 = 把模板里写进 class 的每个枚举值与样式表的类名集合求差）。

### C7 · 判据绑在 AST **节点形态**上，而真输入走的是另一种节点（假阳性 + 同族死分支）（2026-10-10 新增，与 C3「接线臂不可达」/ C4「死代码」同族）

判定分支用节点构造器做**形状匹配**（`Literal(...)` / 某个字段名）而不是**语义**（"是不是整型常量表达式"），于是同一语义的另一条 AST 路径绕过判据：**过严面 = 合法输入被拒（假阳性）**，**过松面 = 该分支永不可达（死码）**。两面常同批出现——同一形状假设被抄到两处，一处表现为假阳性、另一处表现为死分支；按 A1 的"同族臂并排"一次能抓齐。

- **判据 / 查法**：对每个新加的形状匹配，列出**该语义在 AST 里可能出现的全部节点形态**（字面量 / 一元负号 / 二元常量表达式 / 宏展开后形态 / 带后缀后缀），逐形态造 1 行最小探针喂进去，与 Clang 真值对拍（`-Warray-bounds` / `-Wimplicit-function-declaration` 这类 Clang 默认口径就是判据来源）；再对分支内**每个子条件**问一句"有没有输入能走到这里"。**语料只覆盖字面量正形态时，这条判据的两面都测不出来**——必须自造被绕过的形态。
- **实例（同批一处假阳性 + 一处死分支）**：新加"case 标签须为常量表达式"的判据写成"节点必须是字面量"，而 `case -1:` 在 AST 里是 `Unary(Neg, Literal)` ⇒ **合法 C 被拒**（Clang 零诊断），连坐断了模板族编译（教学标注族级对拍 + demo 全族编译两条闸同时红）；同一形状假设被抄进"常数下标越界"判据的**负值分支**（`v < 0`），而负数下标同样走 `Unary` ⇒ 该分支**永远不可达**，静态面漏报（Clang `-Warray-bounds` 报）而提交信息写"负下标同报"（声称面见 E13 同族面）。
- **处方**：判据按**语义**写（常量求值 / 折叠，或至少在匹配里显式并上 `Unary(Neg|Pos, Literal)`），并把被绕过的形态补进语料。

## D · 门禁 / 闸自身不可信

> 共同特征：**你以为的"绿"不代表被验过**。审闸比审代码更值钱。

### D1 · 闸自证两问：是不是闸 / 会不会自愈

> 任何"闸绿了"的结论，先过这两问再采信（原 D1 / D2 / D12 三条合并——D12 本就是这两问的汇总）。
> **编号 D2 与 D12 留空**，以免打断既有引用。

- **问一：它是不是闸**（原 D1）：`grep -c "<脚本名>" .github/workflows/ci.yml`。**0 = 本地工具，不是闸**。实例：某 D 级差分工具长期未接线 ⇒ "运行期正确"全靠手工复跑，回归无人拦。
- **问二：它会不会自愈**（原 D2）：头注明写"红→绿形态"（检测的同时顺手修）的闸，判"某提交上红不红"**每次都要从干净态起跑**（`git checkout -- .` 后再跑，一次定论）——第二次 PASS 不是证据。
- **问四：它的前置在同一 job 的同一序列里先于它吗**（2026-10-05 补；D20 占用了"问三"，本条与之并列）：新接线一道闸 / 新增一个 CI 步骤时，它消费的**产物 / 服务 / 工具链**必须由**同一 job 中它之前的步骤**产生。跨 job、或"后面那步会构建"、或"本地碰巧有"都会让闸**开箱即红**——而红在**新步骤自己的名字**上，极易被读成"新代码坏了"。
  - **查法两问**：① 该步骤消费的每个产物，能在同一 job 的**前序**步骤里找到构建动作吗（`grep -n "moon build\|cargo build\|go build" <workflow>` 取行号，与步骤行号比大小；**只统计同一 job**——多 job 文件里行号顺序 ≠ 执行顺序）；② 缺失时脚本是 **fail loud** 还是**静默降级**（后者更坏，见 D16）。
  - **实例**：新增「frozen digest 新鲜度」步骤插在 `cmd/run` 构建步骤**之前**，而它首条命令即 `vm_diff --freeze`——该脚本对 runner exe 做存在性检查后 `exit 1` ⇒ 步骤一接线必红（干净 clone 复现同一命令即得 `exit status 1`；全 workflow 内 `cmd/run` 构建仅一处、行号在其后）。
  - **处方**：闸自带前置构建（步骤内先建）或移位到前置步骤之后；若该前置在**下一阶段会消失**（如删区后 oracle 不再存在），步骤内须留存在性分支，否则同一道闸在下一阶段又红。
  - **同族面（2026-10-25 补，PR #307 审阅）：前置不止「构建产物 / 服务」，还包括**依赖安装目录**——`node_modules/.bin/<tool>` 是 `npm ci` 的产物，跨 job 挪动步骤时必须连同安装步骤一起挪**。判据：`grep -n "node_modules/.bin/" <workflow>` 取每条引用，与**同 job** 的 `npm ci` / `npm install` 行逐条对齐；同 job 没有安装行 ⇒ 干净 runner 上该步开箱 `exit 127`（`shell: bash -e` 下后续命令直接不执行）。查法两问：① `git ls-files <依赖目录> | wc -l` 是否为 0（0 = 不在版本控制，只能由安装步骤产生）；② 该依赖目录的父 job 里有没有安装步骤。实例形态：静态门禁 job 新增 `.mts` 自测步骤，`tsc`/`oxlint` 走 `scripts/node_modules/.bin` 硬路径，而该 job 只装了 node 未 `npm ci` ⇒ matrix 三片同一步 127 红并拖红 ci-summary，本地因磁盘残留 `node_modules` 全绿。处方：步骤移到已有 `npm ci` 的 job（如 TS 门禁 job），或在同 job 补安装步骤。
  - **查法三（2026-10-05 补，问四同族）：同 job 有构建动作还不够，还要比「产物形态」**。同一包的 debug / release（或不同 `--target`）落在**不同目录**——前序只建了 A 形态而步骤消费 B 形态，等于没有前置。判据 = 把该步骤消费的**绝对路径**与 workflow 里每条 `moon build` / `cargo build` 的 `--release` / `--target` 参数**逐项对齐**，并确认消费路径里的 `debug` / `release` 段与之一致。**只在后序步骤**构建、或形态落在**另一 job**（无 artifact 传递）都算缺前置。
  - **实例（形态不匹配面）**：某消费者脚本把缺省引擎写死为 **release** 产物路径，而同 job 内唯一相关的构建命令**不带 `--release`**（只产 debug 形态）、位置还在该步骤**之后**；release 全量构建则在同 workflow 的**另一 job**（跨 job 不可见）。干净检出时脚本走 `existsSync` 失败分支直接退非零。**定案实验**：移走该 release 产物目录 → 执行同 job 前序那条构建命令 → 产物**不重现**（该命令不连带构建它）；再跑消费脚本 → 报"找不到引擎"且退非零。这类红的成因是"**本地磁盘恰好留着历史 release 产物**"，与问五（自报全绿是手挑子集）常叠加出现。
  - **同族面（2026-10-31 补，PR #403 审阅）：前置被**搬进单测内部**（测试体里调 `ensureFresh` 之类「缺产物就现建」的门禁）⇒ job 层看不见这个前置，干净 runner 上**必红**，而且报错形态会连带吞掉同文件其余锚**。判据：`grep -n "ensureFresh\|buildSync\|execSync(\"moon" scripts/**/*.test.mts`——单测里出现构建动作即命中；再对 `npm run test` 所在 job 查「同 job 有没有对应构建步骤」，没有 ⇒ 干净检出必红。**报错形态的额外代价**：`ensureFresh` 的缺失分支是 `die()`→`process.exit(1)`，在 `node --test` 里等于**整个文件进程被杀**——runner 只报「该文件 test failed」一条，同文件里其余锚（包括本可证明有牙的新锚）**结果全部丢失**，日志里连 die 的原因都只在 stderr 首行。查法 = 在干净 worktree（无 `_build`）单跑该文件，看 `tests` 计数是否退化成 1。处方二选一：① 纯函数化（catalog 等产物数据由调用方注入，测试不构建），真拉取断言留给**有产物的 job**（catalog-check / demo）；② 按仓内既有约定加产物存在性 guard（`HAS_SERVE` 形态）并登记未覆盖——但注意仓内 CI 纪律是「环境缺口静默通过就是假绿」，所以①优先。**审阅侧教训**：提交信息里的「npm test 626/626」是**本地有产物**的成绩，与干净检出不是同一命题。
- **问五：自报的"全绿"是**手挑子集**还是**门禁全集**？（2026-10-05 补；与 C5 同族——一个根因的多处同形点，此处是"多处同形点里的**验证面**被裁到一处"）：结构型提交（目录删除 / 重命名 / 大迁移）的提交信息里"X 全绿 / 验收通过"极常指**作者手挑跑过的那几条**，而非 CI 步骤清单里的每一条。删掉一个目录后，**凡显式传旧路径、或自带一份独立的 root 探测 / 真值源路径**的步骤都会红，而它们与作者跑的那几条往往不同。
  - **查法**：① `grep -n "run: go run\|go run ./scripts" <ci.yml>` 取**全部**被调脚本——这才是验收面，逐条（或按其前置成本抽样）跑；② 对每条被调脚本再 `grep` 它引用的**目录/文件路径**，与本次结构变化逐个比对（`comm` 式差分）；③ 特别留意**同族拷贝**：`capi.ProjectRoot()` 之类被抄成 4–5 份独立实现的根探测——改一份≠改全族（C5）。
  - **实例**：一次 `native/` 物理删除批自报"五驱动 golden 全绿 + vet 全绿"，实测 CI 步骤清单里另有 **12 条红**（三驱动仍传 `native/tests/cases/$d`；四份独立 root 探测仍认 `native` 标记；两生成器直读 `native/**` 源；testcount 文档数未连坐；facts/gen_svg/host_contract_map 各红一处）。作者挑的正是"已经改过路径"的那几条。
  - **处方**：提交信息里凡出现"全绿"，须**点名验证集合**（"CI 步骤 1..42 全跑"或"仅 X/Y 两组"）；审阅侧把 `ci.yml` 的脚本全集当清单逐条过，**不接受"跑绿了的几条"当验收**。

### D3 · 缓存 key 里没有的东西最危险
- **判据**：缓存 key =（源码 + 工具链版本 + 参数），**不含工作区状态 / 环境**。
- **后果**：本地永远回放同一答案，把竞态冻结成"KNOWN"。
- **手法**：**用 Python 复刻 key 生成式，就能把缓存条目反查回用例名**。

### D4 · 超时 / 异常结果被当确定性结果
- **实例**：超时路径走 `Kill()` ⇒ 子进程返回"非零退出码" ⇒ 被当作"程序真的失败"落缓存。注释自称"超时 = 环境异常可重试"，实现未区分。第二次跑**秒回同一结论**即为已缓存。

### D5 · 归一化吃掉了合法输出
- **判据**：归一化函数剥掉的行前缀，同时是程序输出的合法前缀。
- **实例**：某归一化剥 `// ` / 两空格 / `Warning` / `Error` / `Finished.` 开头的行 ⇒ 两侧同被剥 ⇒ **假 SAME**。
- **手法**：写同包探针直调该函数，构造"两侧差异行均以被剥前缀开头"的输入看归一后是否 `相同=true`。

### D6 · 闸的真值来自缓存制品 ⇒ 是复述，不是对账
- **判据**：闸声称堵住"文档与真值一起错"的盲区，但它读的"真值"是 `status: cached` 的制品。
- **必需**：闸内**强制新鲜度**（自己跑采集，或要求 `provenance=run` 且 `as_of` 落在本轮）。

### D7 · `facts` 类审计的四个结构性盲区
1. **只比「文档 ↔ facts」，看不见「facts ↔ 真值」**：两者同为陈旧值就一起绿 ⇒ 凡"某数字在文档里"类结论，**必须自己重跑采集命令**。
2. **不把 `unavailable` 判红**：CI 上真值校验面可能小于本地，且**绿 = "没校验"而非"校验过"**。
3. **Frozen 桶优先于 Manual / Suspect**：命中**行内任一日期**即冻结 ⇒ **"带日期的分解式现值行"对两条通道都隐形**。
4. **豁免白名单吞 error**：加载豁免表时丢弃 error ⇒ 头注声称的"条目指向不存在文件即红"**从不打印**；被豁免文档数字干净时**静默通过**。测白名单要**双向**。
- **假阳性口径**：md 通道 =「Context 正则命中行 × 行内 `\d{2,6}` 落 Lo/Hi」，**不懂"是否在陈述现值"** ⇒ 会把行内的行数、处数、版本号误判成漂移。**禁机械替换，改口径或改句子**。

### D8 · 门禁覆盖面比你以为的窄
- **默认 target**：CI 的测试步骤若不带 `--target native`，native-only 包的锚**全不在门禁内**。核对：两种情况各跑一次比总数。
  - **同族面（2026-10-07 补）：怎么知道某包是 native-only**——`moon test -p <pkg>`（不带 target）对该包直接报 `Error: Selected package(s) do not support target backend 'wasm': <pkg> ([native, wasm-gc])`，**该包的锚根本没跑**（不是"跑了绿了"）。⇒ 审「新增锚」时先对**锚所在包**跑一次裸 `moon test -p <pkg>`：报上述错即知它只在 `--target native` / `--target wasm-gc` 下被覆盖，须确认 CI 有对应 target 的**独立步骤**（本仓由 `moon test --target native` 步骤承接）。同族：`moon test`（全量、默认 target）的总数**不含**这些包，故"总数全绿"不能推出这些包的锚跑过。
  - **同族面（2026-10-17 补）：默认 target 下的「静默整包跳过」与"报错跳过"是两件事**。上一条说的是 native-only 包在裸跑时**报错**（看得见）；本面说的是 `supported_targets` 不含默认 target 的包（如 gateway 这类 `+js +native +wasm-gc` 的协议层）在裸 `moon test` 下**一声不响地被整包排除**——总数照常打印、措辞不变，只有"总数 = 各包之和"时才看得出缺口。查法：`moon test -p <pkg>` 裸跑，若报 `do not support target backend 'wasm'` 即该包不在裸总数内；把**裸总数与该包的 native/js 计数相加**与 CI 的 `--target native` 步骤总数对账。后果：提交信息里的"N/M 全绿"（裸口径）可以结构性不含该包的**全部锚**——若该包同时编译失败（未连坐改名等），裸口径仍全绿，而 CI 的三条 `--target` 步骤全红。处方：新增/改动的包一律按"锚所在 target"复跑，并在提交信息里点名口径。
- **只扫某些目录**：目录扫描类闸（如源码卫生检查）可能只覆盖活跃区 ⇒ **根目录 md 不在覆盖内**，其问题会长期隐身且使后续 diff 不可见。
- **只比产物不比运行期文本**：产物差分不覆盖运行期 stdout / 诊断文案。
- **只比"去重后的首现序列"**：端到端对拍器为压噪声，常按"每 `(phase, desc)` **首现**"去重后再比 ⇒ **同一标注的重复次数、以及非首现帧的取值差，全在覆盖面外**。读闸先问一句"取键函数里去重了吗"，再用"只改坏非首现帧"的注入验证（首现不动 ⇒ 闸全绿即坐实盲区）。实例：算法标注族级对拍器比 `(phase, desc)` 首现序列（82 模板 × 28 算法双向一致），逐帧全量面**不在其覆盖内**，需另用探针补比。
- **文本抽取闸的抽取面会静默塌缩**（2026-10-02 补）：基于正则 / 字面量抽取的文本对账闸，被检代码**一换写法**（字面量→变量、匹配链式调用→`querySelector` 等抽取器不认的形态）抽取面就归零 ⇒ 同一 bug 字面量红、变量静默过；空输入文件更是天然全绿。**闸没有任何"各路命中数下限"守卫**。查法：构造"同 bug 的变量形态"与"空文件"各跑一发，看是否都绿。处方：硬编码**各路有效位点数下限**（低于即红，demo 闸实测基线 1/3 处取值）+ 不可解析位点计数打印；下限触发于大重构时按新基线更新（良性红）。实例：demo UI 字符串契约对账闸，`el.classList.add(cls)`（cls="active"）形态静默通过、同 bug 字面量红——加 class/id/var 三路下限（3/30/60）后塌缩即红。

- **「字段级冻结」闸的请求序列天然不含某字段的非平凡取值**（2026-10-03 补）：闸以**固定请求序列**驱动双宿主比对，若序列里没有任何一帧能让某字段取到**非空 / 非 ASCII / 非默认**值，该字段实际上从未被比对过——而闸的名字、文档与规则资产都写着"字段级冻结"。查法：对每个被声称冻结的字段，回序列里找"能产出它非平凡取值的帧"，找不到即该字段在覆盖外；再核**闸的规则资产（rules.json / 豁免表）有没有登记这条未覆盖面**（没登记 ⇒ 读者会以为已冻结）。与上一条同族：上一条是"抽取器认不出形态"，本条是"序列根本不产生该形态"。

- **同族面（2026-10-09 补）：出口级新增锚遍历的是「静态数据产物」，而该数据面天然不含触发形态** ⇒ 锚恒真、永不自红（与主条分工：主条是"请求序列不产生该形态"，本条是"**数据产物本身就没有**该形态"，且锚的存在被当成"该出口面已钉死"的证据）。查法：① 把被保护的实现改回旧的错形态或整体 no-op → 跑该出口锚 → **仍绿即空转**；② 再问"该数据面里有没有一条记录能取到触发形态"——找不到 ⇒ 该锚只保护未来新增数据、不保护当前实现。处方：出口锚换成"构造一条含触发形态的输入"的直调锚，或让锚显式断言"扫描到的非平凡取值计数 > 0"（否则空转即红）。实例：`diag` E4 出口为"控制字符必须 `\u00XX`"新增的 `e4_export_no_raw_control_bytes` 遍历 `export_catalog_json()`——把 `@util.json_escape` 的控制字节转义整段关掉（`if code < 0x20` → `if false`）后该包 21/21 仍全绿（catalog 的 icon/title/explanation/common_causes 全不含 < 0x20 且非 `\n\r\t` 的字节），而同批 util 包自身的直调锚当场两红 ⇒ **出口面零覆盖**，原提交所写"红锚证红"用的是另一条入口。

- **闸语义换法（对账 → 发射）会静默丢掉「盘上/库中产物与生成器一致」这一面**（2026-10-04 补，与上一条同族）：生成器同时具备「`-check` 读盘逐字节比对」与「裸跑就地写」两种模式时，把 CI 步骤从 `-check` 换成裸跑 = 用「生成器**内部**断言」替换「盘上产物**对账**」。前者只判**源与源**之间是否自洽（分组并集、全集对账），**完全不看盘上那份产物**——所以手改 / 陈旧 / 已提交的旧产物都能静默通过。查法：① 手改盘上产物一行（模拟手改或陈旧）→ 跑新的 CI 步骤 → **退出码仍 0** 即坐实；② 再叠问一句"该产物**是否仍入库**"——仍入库 = 双重失效（库里有陈旧副本 + 无闸比对），而"产物不入库 + 消费前现场发射"的标准形态**不适用本条**（现场发射时盘上那份本就是临时的）。处方：发射到临时文件再与盘上逐字节比对后才落盘；或保留一个 `-check` 侧步骤；或发射后跑 `git diff --exit-code -- <产物>`。**注意**：生成器**内置断言有牙**（注入源漂移会红）与「产物对账存在」是两件独立的事，前者绿不能推出后者。

- **抽取面「静默归零」的两个新触发面**（2026-10-04 补，与上一条同族）：上一面是「字面量→变量」（**值**换了），下面两面是**值没换、写法/来源换了**。
  - **(a) 被检代码换了语法形态**：抽取正则按旧语言写法写死，源码一迁移（JS→TS、加泛型 / 类型断言、链式调用改 `querySelector`）⇒ 该形态的位点整批消失，而闸的输出措辞不变。查法：把闸的抽取正则**原样**搬到迁移前后两份源码上各跑一遍、求命中集合之差（差集非空即塌缩面）；再注入该新形态的**幽灵值**看闸红不红，**同位置的旧写法对照必须红**。实例：demo UI 字符串契约闸的「取 id / 类名链 / 变量绑定」三路正则只认 `$(` / `getElementById(` / `querySelector(`，对 `$<T>("id")` 与 `($("id") as T)` 两形态一律不匹配——聚合层面（id 集合）仅因同一 id 在别处仍有裸 `$()` 调用才侥幸未塌，但「位点数下限」这类逐路守卫正靠不住。
  - **(b) 多来源抽取里某一路恒为 0 命中**：闸把两个来源合并抽取（如 HTML 的 script 标签 + 入口模块的 import 图），其中一路因**路径前缀 / 引号形态假设**恒空（只匹配 `src="./x"`，而 HTML 写 `src="x"`）⇒ 它声称覆盖的那一路实际零覆盖，且"某来源贡献 0 条"不触发任何报错。查法：**逐路打印命中数**（不是只打合计），并对每路做「删掉该路所指的某个资源」注入看闸红不红。实例：部署 workflow 里的「组装资源存在性」内联自检，HTML 一路贡献 0 条，删掉 HTML 裸 `src` 指向的那个脚本后自检照旧报「全部在位」。
  - **处方（两面共用）**：抽取面**逐路打印命中数 + 逐路设下限**（低于即红）；资源存在性类断言**别复用抽取结果**，直接列期望路径清单逐个 `test -e`。
- **抽取器「过采集」：条件参 / 修饰子句里的字符串字面量被当成"值"**（2026-10-10 补，与上一条同源、方向相反）：上一条是抽取面**塌缩**（少收 ⇒ 静默），本条是**多收**（误报 ⇒ 闸红且指向不存在的问题）。典型形态：类名 / 属性名类闸按 `\.(classList|className)\.(add|remove|toggle)\(([^)]*)\)` 抓调用括号内**全部**引号字面量，于是 `classList.toggle("cls", v !== "off")` 里的 `"off"` 被判成类名。查法：给该闸喂一条"条件表达式里含无关字面量"的形态（**双向证**：把字面量换成另一个写法 ⇒ 绿；还原 ⇒ 红）。处方：按**位置**抽参（`add/remove/toggle` 只取首参、第二参按布尔表达式忽略），或把条件先算成布尔变量——后者是被检代码侧的正解，前者是闸侧的正解，两者都做最稳。**注意**：触发它的新代码本身是对的（闸错在被检代码没错时红），报告时要分开写"闸的盲区"与"引入者的责任"，别把它们混成一条。
- **双臂对拍的两个结构性盲区**（2026-10-11 补）：① **两臂共同缺陷不可见**——对拍只抓分叉，两侧同病逐字节一致时恒绿（教学文案错值族两侧同病 ⇒ vm_diff 永不红；此类面只有 Clang 真值探针能抓）；② **薄壳 / 独立 exe 不在对拍面**——双臂闸只调总入口（`vitro.exe`），同仓的 `compile.exe` / `step.exe` 薄壳断链（漏调注入函数）时对拍零判别，spec 的「薄壳与总入口逐字节一致」契约实际无人守。查法：对每个"多入口同契约"面，把**每个入口**分别过一遍同一探针；审 spec 逐字节声称时先 `grep` 防线脚本里实际调了哪几个 exe。

- **处置回执（2026-10-15）**：上面两条（310/311）当日即被下一轮实测复证——CI 恒全量首跑暴露 js 分派表缺 7 臂（`help`/`serve`/`dump-*`/`--help|-h` 全落未知命令），且因 #93 修复三文件被前一笔误删（测试数 45→44 的下降未察觉），黑盒 44/44 假绿。两起叠加实证「前置 stat + 标注 contains ≠ 语义对拍」。已修：分派表整表照抄 + smoke B 组三臂逐行对拍 + 「测试数变少也是漂移」入人工检查面。

### D9 · 被判程序的工作目录
- **判据**：`grep -n "exec.Command" -A3 <脚本>` 看有没有 `cmd.Dir`。**只隔离 exe 输出目录 ≠ 隔离程序 cwd**。
- **后果**：被测程序在仓库根跑，语料里的 `fopen("test.txt")` 等真读写仓库根；若这些文件名被 `.gitignore` 覆盖，`git status` **永远干净**，副作用完全隐形；并发下互相覆盖 ⇒ **同源同编译器不同结论**。
- **两态对比实验（必做）**：① 现状（游离文件在 + 缓存热）；② 干净起点（移走游离文件）+ **清空缓存**。同一份源码跑同一批用例 ≥2 轮。

### D10 · 白名单条目的"理由"是待验断言
- **手法**：清空 known 打印真实差异、与登记 digest 对比，判它是**不变式**还是**竞态快照**。
- **实例**：某条目的 reason 写"另一侧无此文件"，实测文件就在仓库根，差的是"读到了兄弟用例写的残留内容"。
- **同族面（映射表类对账闸，2026-10-03 补）**：把两条测试的"覆盖关系"写成**手工映射表**（`rust_test → mb_anchors`）时，闸能机判的只是"表覆盖齐全 + 引用存在"，**判不了映射语义**。查法：任取一条 `anchored` 条目，把它的锚换成另一个**实存但无关**的锚名，跑闸——仍绿即坐实。含义：`missing=0 / 无洞` 只等于"表填满"，**不等于"语义全覆盖"**；头注与文档措辞应写"映射无洞 + 引用无陈旧"，别写"全覆盖"。处方：能机判的部分（1:1 形态要求锚名与测试名对齐 / 同一锚不得被多条 `anchored` 复用）补断言，跨包 `merged` 类仍需人工逐条核。
- **同族面（登记表类规格文件未随真源迁移连坐，2026-10-05 补）**：仓内有一类"登记表"规格文件（单源清单 `single_source/rules.json`、脚本总清单、AGENTS 包表、差异台账 `ledger.json`…），逐条记"概念 × 两侧单源位置 × 同步方式"。真源位置迁移时（源从 A 路径搬到 B 路径、A 降级为过渡对账臂），**登记表条目不会被任何闸提醒**——其 `registered` 类判定只校验"声明的两侧路径存在"，A 仍存在（只是降级）⇒ 全绿，而条目里的"源位置 / 同步方式"已与当前实现脱节。查法：把一批里**迁移 / 重命名 / 降级**的路径或概念名逐个 grep 进每个登记表，回读命中条目的"源位置 + 同步描述"是不是当前形态；再问一句"这条被哪道闸守着"——答案若是"只验路径存在"即命中。实例：一批把生成器输入从冻结区 `.rs` 迁到外置 JSON、`.rs` 留下作过渡对账臂，单源清单对应条目的 `rust_source` 仍指向那个 `.rs`、`sync` 仍写"从 .rs 生成"，`-check` 绿（registered 只验路径存在），而该批的连坐清单只列了手册与脚本总清单。处方：真源迁移批的连坐清单应**一次列全全部登记面**（避免"改一个冒一个"）；能给登记表加"真源路径落在 legacy / 过渡白名单内即红"的机判最好。
- **同族面（迁移批的引用面只同步了「文档面」，漏了 agent 手册面，2026-10-05 补）**：一次目录删除 / 重命名批的"引用面清理"通常按 `docs/**` + 根 README/AGENTS 做，而 **agent skill 手册（`.agents/skills/**/SKILL.md` 及其 `references/`）不在该清单里**——它们同样是 markdown、同样含"往 X 目录加用例 / 跑 Y 命令"的**可执行指令**，却零闸扫描（不必编译，也跟着不进 facts 的 md 通道的活链接口径）。查法：把本批迁移掉的每个旧路径，除 `docs/` 与根 `*.md` 外**再 grep 一遍 `.agents/`**，并**区分两类**——"历史叙述 / 退化注记"（可留）vs **反引号内的路径或命令**（可执行指令，必须改）；再把它与**提交信息里"引用面已同步"的声称范围**对齐。实例：一次目录删除批的收尾提交自述"某 skill 引用面已同步"，diff 实为一行；同一 skill 的 `description` 与正文仍有多处指向已删目录，其中一条命令的 `cwd` 已不存在。注意口径分层：**"全仓 markdown 活链接 0" 这类声称只覆盖链接形态**，反引号里的指令路径不在其内——声称与实测"都成立"却仍留坑。

- **同族面（2026-10-17 补）：对账闸的告警文案会把处置引向"删登记"**——登记/边表类闸报 `过期边（已无此消费，须清理）` 时，"已无此消费"的**真因常常在消费侧**（消费方改名后未连坐、或消费点本身编译不过导致引用形态不被识别），而文案只给了"清理登记"这一条出路；照文案办 = 把登记删掉掩盖真因，下一次真正的消费恢复时又红。查法：拿到过期边先 `grep` **消费侧源码**里该符号的引用形态（是否 `@pkg.Sym` 限定、所在文件是否编译得过），再决定是补消费侧连坐还是删登记。实例形态：一笔提交为"新上提的符号"补登记边，而消费侧仍写着未限定的裸标识符（编译不过）⇒ 边自落地即"过期"，同一批的 `moon test --target <该包的目标>` 也编译失败，两条红同一个根因，而文案把人往反方向推。
- **同族面（同一登记事实有多个登记面，提交只补了其中一个 ⇒ 闸仍红）（2026-10-10 补，与 C5 同族）**：新增一个跨包可见符号（`pub fn` / 新包）时，需要同步的"登记面"通常**不止一处**——本仓至少三处：（a）接口面 `.mbti`（`mbti_sync -check` 守）、（b）闸白名单 / 边清单（`moonbit_surface -check` 守）、（c）包依赖分层（`pkg_deps -check` 守）。改了实现、跑了**自己顺手的那道闸**（常见是 `mbti_sync`，因为它由 `moon info` 重生成时自动带出）就以为收口，另两道无人跑 ⇒ CI 红。查法：新增符号后把**每一道与该符号相关的闸**各跑一次（用 `grep -c "<符号名>" scripts/moonbit/surface_allowlist.txt scripts/moonbit/surface_edges.txt` 之类直接对账登记文件），别只跑你改过的那道；审"修复批"时同样核——提交信息写"登记已归位"不等于闸绿。实例形态：一条提交新增 host 包 `pub fn`，另一条提交信息写"该符号漏账一行已随批归位"，实为只写了 `.mbti`；`moonbit_surface -check` 在 HEAD 上仍报该符号"漏收"、exit 非 0，而 CI 有该步骤的独立 run。处方：新增符号的连坐清单应**一次列全全部登记面**，最好让 `surface` / `pkg_deps` 的报错文案直接点名"要在哪个文件加哪一行"。
- **同族面（"实践不可达 / 实践等价"式后果断言未实测，2026-10-29 补，#375 审阅）**：豁免条目常拿**后果断言**当理由（"可达面只剩 X ⇒ 实践不可达"、"该突变与实际行为等价"）。这类断言**没有任何闸会验**，代价却是**把一条真实零锚面永久豁免**（闸从此不再报它，也就不再有人补锚）。查法固定为双向实测：① 按理由描述**构造合法输入**（真值侧用 clang 判合法）跑干净树 ⇒ 取真值行为；② 同一输入跑**突变树**（用被豁免的那条突变）⇒ 无差异才算等价；有差异即理由不成立，处置改为**补锚**而非豁免。实例：某条目写"列级判据的 `&&`→`||` 只在缩进原型下可达、实践不可达"，实测同行"先定义后调用"的**单行合法 C**（clang 无诊断）在突变树上误报 E3058 ⇒ 可达面是日常写法；补一条同行正例锚后该突变即被杀，豁免条目可直接删。

- **同族面（驱动侧 known / 豁免条目被删，而「台账引用侧」未同步 ⇒ 双向对账闸红；方向与上一条「路径迁移未连坐」相反）（2026-10-10 补，与 D19 同族）**：一条差异另有原因转绿后，修者把该例从**驱动侧** known 白名单（`clang_direct/known_direct.json`、`vm_diff/known_diffs.json`…）删掉，却忘了**台账侧**（`diff_ledger/ledger.json` 对应条目的 `anchors.<防线>_known` / `detectable_by_defense` / `source_docs`）仍列着它 ⇒ 台账反向对账报「引用不存在的豁免条目」并非零退出。**两个方向都要查**：删驱动侧条目 ⇒ grep 台账侧引用；删台账条目 ⇒ grep 驱动侧 known。**查法**：删/增任一 known 条目后，把 `grep -rn "<用例名>" scripts/` 的输出逐面回读（台账 `anchors` 的三个防线数组 + `detectable_by_defense` + 驱动侧 known 文件 + 源文档），任一残留即红。**实例形态**：某批把教学 lookalike 例从 clang_direct known 删除（该例随 stderr 分离转绿），而台账对应条目的 `clang_direct_known` 数组仍列该例（`vm_diff_known` 数组侧却是对的——**同一台账条目内两个防线数组不同步**，更隐蔽）；该批的"验收"清单里**没有 diff_ledger 这一步** ⇒ 自报"全绿"是手挑子集（D1 问五同宗）。**处方**：known 条目的增删与台账引用视为同一操作，连坐清单一并列全；台账闸的报错文案已能点名悬空条目，**验收清单须包含它**。

### D11 · 同族防线的强度不等
- **判据**："两个防线都绿" ≠ "两个都有牙"。
- **手法**：用静默 exe（`int main(){return 0;}`）顶替被测二进制（**记得还原并 `md5sum` 对账**），看各防线是否都能红。

### D13 · 格式闸要复刻 CI 口径
- **判据**：CI 的 fmt 步通常是"跑格式化 + `git diff --exit-code`"，**不是** `--check` 子命令；后者在本机可能 exit 127。
- **正确查法**：记下 fmt 前的脏文件集合 → 跑格式化 → **新脏出来的就是漂移文件** → **只 `git checkout -- <新增脏文件>` 复原**（绝不用 `git checkout -- .`）。
- **同族面（2026-10-25 补，PR #312 审阅）：多语言双跑迁移期 ⇒ 改错载体 = 零效果且闸不报错**。判定型闸迁到新语言时仓内常**两份并存**（旧语言版作回退面 + 新语言版作现役面），CI 只跑其中一份；改批若改在**不被 CI 消费的那一份**上，效果为零——真值侧的闸照常判，而改动所在那份甚至不被任何门禁执行 ⇒ 无报错、无痕迹。查法：① 从 `ci.yml` 取该闸的**实际调用行**（`grep -n "<脚本名>" ci.yml`）确认哪一份被消费；② 对被改的那份问「它在本轮会被谁执行」——无消费方即改错载体；③ 被改那份若带「回退面 / 不再随行为变更维护」头注，则**连维护它都是违规**（应改现役面，或按纪律把回退面删掉）。实例形态：facts 闸 Go→.mts 迁移后 CI 已切 `.mts`，一批把「带宽上限放宽」改在了 Go 版规则表上 ⇒ 现役面带宽仍是旧值，真值越界判红（`真值 785 越出带宽 [500,750]` exit 2），而 CI 侧的 facts 步**不带 `--run`** ⇒ 该键在 CI 恒 unavailable ⇒ **CI 全绿、只有本地 `--run` 路径红**；两侧都改则属两版长期并存的僵尸双轨。

### D14 · 表头计数与表体行数不一致
- **查法**：清单类文档，逐行数表体，与标题里的计数对账。
- **实例**：标题写"N 个，全部接线"，表体实际行数是另一个数（且"全部接线"为真、标题数是陈旧的）。

### D15 · 闸的判定依赖**未固定版本的运行时/工具链**
- **判据**：闸的断言（或被测 API 的行为）在**两个运行时版本的语义差**上翻转；而 CI 没有 pin 该版本（无 `actions/setup-node` / `setup-python` / `rust-toolchain` 之类）。**本地绿 ≠ CI 绿**，且同一台机器换 PATH 上的解释器就变红。
- **查法**：① `grep -c "setup-node\|setup-python\|dtolnay/rust-toolchain" <ci.yml>`——**0 = 判定随 runner 默认版本漂移**；② 把候选版本各跑一遍同一产物 + 同一脚本（本机常同时存在托管版与系统版，`which -a` / 显式绝对路径），比较退出码；③ 断言涉及"规范演进中的 API"时（如实例中的 `WebAssembly.Module.imports` 对 string-constant 的可见性），**去字节层取证**——自己解一遍产物（ELF/PE import 表、wasm import 段），别用高层 API 的自报数当"事实"。
- **处方**：断言改成不随版本翻转的口径（按 module/name 过滤，只判"功能性 import"）；CI 加版本 pin；文档/提交信息里的数字按字节层真值写。
- **实例**：wasm-gc 宿主冒烟断言 `WebAssembly.Module.imports(mod).length === 0` 与提交声明的"产物零 imports"：node 22（V8 12.4）列出 2174 条 `module:"_"` 的 string-constant import 且 `instantiate(mod, {})` 抛错（exit 2）；node 25（V8 14）则隐藏它们并自动满足（16/16 PASS）。产物 import 段实测 ≈2180 条 ⇒ "零 imports" 只在高层 API 的新版语义下成立。

### D16 · 依赖解析静默降级 ⇒ 对着"错制品"全绿

- **子条（第十一轮 P2-1，2026-10-09）**：闸/声称的真值取自**外部活仓库工具**（jsonmbt build 形态演进）——「字节全兼容」类声称不稳；查法 = 声称前后各跑一次该工具比对（双版本再生均 DIFF ⇒ 非工具演进、声称当时即错）。
- **判据**：一套测试 / 门禁对「源码工作树」与「已发布制品」能给出**同一结论**，而实际解析到哪一个取决于某个配置文件是否生效。该配置缺失（或 cwd 不对）时**静默换源**：不报错、不改措辞、**输出逐字相同**，还可能更"干净"（任务数更少）。
- **查法**：先问"这条门禁判的是工作树还是制品？"，然后打印**解析树**（`moon tree` / `go list -m` / `cargo tree`）确认实际源；再**把该配置文件临时移走跑一遍**（注入），看是否静默换源仍绿，两态的输出差分就是这道门禁的真实判别力。
- **实例**：依赖本地工作树的 moon 工程，`moon.work` 在 ⇒ `moon tree` 出 `-> vitro/engine@0.7.0 (local <工作树>) [workspace member]`、70 任务；移走 ⇒ 解析到 registry 制品（无成员标注）、**任务数骤降（70 → 28）、`moon check` 0 errors、`moon test` 仍全通过且打印逐字相同**。
- **后果**：「改上游就当场爆红」这类**拦截力声明**，前提是解析锚存在；没有锚时它只是纸面承诺——上游改了帧语义，本仓测试照样对着旧制品全绿。
- **处方**：加**解析断言**（日志必须含工作区成员解析行 / 解析出的路径必须等于工作树），**不接受"跑绿了"当证据**；同类同形：monorepo 里 `workspace:` 协议漏配、`replace`/`patch` 未生效、`node_modules` 软链指向已发布包。
- **同族面：「缺依赖自动降级」型闸**（2026-10-05 补；与主条判据同构——**解析到哪个基准不影响结论**）：闸在其**真值源缺失**时自动切换到**较弱的比对基准**并**照常判通过**，于是"真值源健在"与"真值源已消失"两态给出**同一条结论**。设计上往往是有意的（为"真值源退役后零改动存活"），危险在于**退役之前**它把"真值源坏了 / 没构建 / 被清理"一并掩盖成绿灯。
  - **查法**：**把真值源临时移走**（`mv <bin> /tmp/`）跑一遍**默认调用**，看退出码 + 输出措辞 + 是否只写在 stdout；只看"绿"永远看不出。**判据**：降级若只打 stdout 一行、不动 stderr、不非零退出，即为静默降级。
  - **实例**：五个差分驱动在 oracle exe 缺失时自动切 `--golden`（冻结基线）并 `PASS rc=0`——在"删区之后"是预期行为，在"删区之前"则把"oracle 构建失败"掩盖为通过；实测移走 oracle 后三驱动各自只打一行提示即退 0。
  - **处方**：降级必须打 **stderr 醒目警示**并声明"结构裁判已切换"（本次处置即此：`[裁判切换]` 前缀 + 正确性主锚声明）；CI 侧另补一条**真值源存在性断言**（在退役之前），别让“降级”成为异常的唯一出口。
  - **同族面（2026-10-06 补）：降级链的下一环是「陈旧制品」——后端 exe 无新鲜度门禁**。`scripts/bin/vitro` 的 wasm 臂在 node < 25 时降级到 native 臂，而 native 臂直接 `exec cmd/vitro/vitro.exe` —— 该 exe **不随源码自动重建**，若陈旧则对**本批已修的形态**给出**错误的编译失败**。实测：同一 `struct{… union{…}; …}` 输入，含本批修复的 `cmd/run/run.exe` → `// EXIT 6`（== Clang），而陈旧 `cmd/vitro.exe`（早于本批提交时间）→ `// COMPILE-ERROR E2005`；重建后即转 `EXIT 6`。查法 = 比对统一入口消费的 exe mtime 与 HEAD 提交时间；或见「同一文件在统一入口与直跑 runner exe 上结论不同」即先疑制品陈旧。对照：`vm_diff` / `clang_direct` 自带「mtime 触发 + 构建复核」新鲜度门禁；统一入口 native 臂当晚由 `9bd91941` 补了 **stderr 大字告警**（不阻断、只扫 `cmd/host/parser/typeck/lexer/codegen/vm` 7 目录）——本条盲区在告警面**内**的源码上已收口，残余面 = ①告警不阻断（读漏 stderr 仍会带旧结论走）+ ②7 目录之外的源码（gateway/memory/time_travel 等）改源不触发告警。这是 D16 主条「对着错制品全绿」在**降级臂**上的镜像：不是静默切基准，而是静默用旧代码下结论。
  - **纠正（2026-10-07，经用户批准；来源 = 审阅亲跑 `scripts/bin/vitro` 门禁告警实测在案）**：本条原写「统一入口 native 臂**无**」——写作时点属实，但同日 `9bd91941` 已加告警门禁，「无」的绝对表述过期；盲区收窄为上述①②两面。后续审阅引用本条以收窄后口径为准。

### D17 · 非源码资产（静态页 / 前端 JS / CSS / 部署 workflow）不在任何闸的扫描面内
- **判据**：仓内新增一类"人写、非编译输入"的资产（静态 HTML/JS/CSS、模板、workflow yml），而门禁族全是"扫源码目录 + 比编译产物" ⇒ 资产里写错的**字段名 / 硬编码数字 / 产物路径**没有任何闸会红。
- **查法**：① `grep -c "<资产目录>\|<新 workflow 名>" .github/workflows/ci.yml` ⇒ **0 = 未接线**；注意这查不到"独立 workflow 自身无 lint"（如 actionlint 缺失 / YAML 语法无校验）。② **注入实证**：把资产里一处消费点改坏（如前端读后端帧的字段名 `out.total` → `out.totall`），跑全部**可能**覆盖它的闸；全绿即坐实无锚。
- **后果**：页面靠人肉点开验收；后端帧字段改名 / 文档数字更新后，前端静默渲染 `undefined` 而门禁全绿。
- **处方**：给资产配一条**冒烟闸**（喂同一份预置用例数据跑一遍消费逻辑，断言"消费的字段在帧里存在"+"预置真值与实跑逐字节一致"），而不是指望人记得；部署类 yml 另加 actionlint，或在 CI 里把 yml 里出现的关键路径 `test -e` 一遍。
- **实例**：`demo/` 单页（index.html / app.js / cases.js / style.css，浏览器直调 wasm-gateway）注入 `out.total` → `out.totall`（页面会打印 "undefined 字节"）后，`source_hygiene` / `facts check` / `testcount` / `moonbit_surface -check` **四道全绿**；`grep -c "demo/" ci.yml` = 0；根因是 `source_hygiene` 只扫 `moonbit/`，全仓无 HTML/JS lint。
- **同族（可并查）**：README / 文档里**为外部读者承诺的链接与在线地址**同样零闸——`curl` 才能知道它是 200 还是 404，`facts check` 只比"文档 ↔ facts 的数字"，不查外链可达性。
- **同族面（2026-10-10 补）：多主题 / 多变体的渲染一致性零闸，且缺陷常只在一个变体暴露**。判据：`git grep` 出所有「**拿语义令牌色当遮挡色 / 挖空色**」的写法（典型 `box-shadow: inset … var(--x)`、`background: var(--x)` 盖在另一色上），逐个问"该令牌在**每一个**变体下是否**不透明且等于该处实际底色**"。只要有一个变体的令牌是半透明（如玻璃主题把面板底色定义成 `rgba(255,255,255,0.06x)`）或与叠放底色不等，遮挡即失效、形态在**那一个主题**下变成另一种。人肉点开验收通常只落在默认变体上 ⇒ 连"看一眼"都漏。查法：改样式后**逐主题/逐变体截图对拍**（同 DOM、逐主题渲染同一区段），或直接把写法换成**不依赖底色**的实现（伪元素 / 边框 / 双元素）。实例：旧栈 style.css（F4 退役件，2026-10-17）课程树打勾环用 `box-shadow: inset 0 0 0 2.5px var(--pane)` 在环内挖中缝，而 glass（深夜书房）主题的 `--pane` 是 `rgba(255,255,255,0.065)` ⇒ 缝挡不住 `--ok`、打勾环糊成实心绿点，与其余四主题（`--pane` 全不透明）形态不一致；用户实报，全仓无任何闸会红。

### D18 · 对账闸只锁字段子集 ⇒ 同一制品的旁证字段成为静默漂移面
- **b. 守护变量空转（2026-10-03 审阅新增，D21 同族）**：闸的代码里**算了某个守护值（计数/长度/校验和）却从不把它放进任何断言** ⇒ 注释自称"数字漂移即红"实际永不红。查法：`grep -c <变量名> <脚本>` == 1（只出现赋值处）即空转；唯一可靠处方 = 把值接进 check（或删掉假装存在的守护）。实例：demo_smoke 的 `methodCount` 只赋值不参与断言，页面方法面计数 16 漂到 21 两批无人拦。
- **判据**：闸的校验函数（schema / 枚举 / 双向对账）只覆盖制品（JSON / 表）的**一部分字段**，其余语义字段（`detectable_by_defense`、`notes`、`rationale`…）**写了但不进任何判定** ⇒ 它们与已校验字段（如 `anchors`）互相矛盾时，闸照样绿。
- **查法**：读闸的 `validate`，列出制品**全部字段** vs **被校验字段**，**求差集**；对差集里每个"语义字段"问一句"它跟已校验字段能否相互矛盾"。
- **实例**：`scripts/diff_ledger` 校验了 schema / 枚举域 / 17 键 / anchors 双向对账，但 `detectable_by_defense` **域开放**（含 `memory-verify-wbtest`、`libc_single_source` 等非三防线值）且与 `anchors` 无一致性断言 ⇒ 某条目写 `["shadow"]` 而 anchors 只有 clang_direct + vm_diff（shadow 空）时闸全绿。
- **处方**：给差集里的每个语义字段补**域枚举** + 与已校验字段的**一致性断言**（如 `detectable_by_defense ⊇ {名 | anchors[名] 非空}`）；注入一条违规验证会红。

### D19 · 豁免 / SKIP 表里的"僵尸条目"：销项漏删 ⇒ 断言被永久跳过
- **判据**：豁免表（`serve_smoke/moonbit_exemptions.json` 之类）按"断言名精确匹配"跳过断言。条目**理由过期**（写"某族未接"而该族已接）时，断言本身可能**早已能 PASS**，却仍被跳过 ⇒ 该面实际不受检，且"销项"动作看起来做完了。
- **查法（必须两态对跑，单跑看不出来）**：① 原样跑一遍记基线（`PASS n / SKIP m`）；② **删掉一条豁免条目**再跑——**真豁免** ⇒ 该断言 FAIL；**僵尸条目** ⇒ 该断言 **PASS**（记下来）。逐条做，或让脚本机械做两态对拍。**表内注释"PASS 也豁免（防僵尸条目）"这类承诺，只有机判才算数。**
- **与 D10 的区别**：D10 是"差分 known 白名单的理由是待验断言"（要去比 digest / 打印真实差异）；D19 是"豁免条目**连跑都没跑**"——删条目看红不红即可，不需要重采真值。
- **处方**：给脚本加**僵尸豁免机判**（带豁免 / 不带豁免各跑一次，`SKIP 条目删后仍 PASS` 即红）；至少在销项批里把**同族条目**列全再核（C5 同款）。
- **实例**：一次"step 族 + 栈帧销项"里，豁免表仍留两条理由为"同上（S8）"的条目；删掉后该断言**真跑且 PASS**（这就是僵尸判据），而同表 `ping 携带 ABI 版本` / `capabilities 携带 engine_version` 删后**真 FAIL**（合法豁免，形态差非缺陷）。⇒ 同族 4 条里 2 条是僵尸；漏删的 `栈帧区域带 alloc_by=call / alloc_line（C2）` 与已删的 `栈帧区域带函数名（C2）` 同族（C5 形态）。

### D20 · `-check` 生成器「写-读-比-还原」在早退路径上不还原 ⇒ 闸自己破坏工作区

> **与 D1 同族**：D1 问「它是不是闸 / 会不会自愈」，本条是同一自证问题的**问三——跑它会不会改坏我的工作区**。

- **判据**：生成器的 `-check` 实现常写成「先把再生成内容**写**到产物路径 → 回读**比**较 → 不一致才**还原**」（为了绕开 `moon fmt` 之类的规范化步骤）。只要在**写之后、还原之前**存在任何早退路径——读不到某个产物、格式化工具有外部依赖、写出与还原之间抛错——**已写入的那些产物就被留在未规范化的形态**，`git status` 出现非预期改动。
- **查法（一条命令即可判）**：**移走该生成器的某一个产物**（`mv <产物> /tmp/`）→ 跑 `-check` → `git status --short` 看**其它**产物有没有被改写。正常应零残留（`-check` 的契约是**只读**）。
- **处方**：把「写」推迟到全部校验通过之后；或写临时文件再 `rename`；任何失败路径都必须走还原（含 `err != nil` 的读失败分支，不只是"对比不一致"分支）。
- **为何门禁没抓到**：`-check` 自己**就是**那道闸——它在红的时候顺手改了文件，而 CI 只读退出码、不读工作区。所以"闸红"与"闸改坏了树"是两件独立的事，必须分别验。
- **实例**：某新生成器的 `-check` 在「产物缺失」分支直接 `fatal` 早退，未还原已写入的其它产物；把其中一个 `.mbt` 移走后连跑，稳定复现"另一个 `.mbt` 被覆盖成未过格式化的原文"，而退出码是正确的 1（看起来一切正常）。
- **同族面（2026-10-07 补；主条是"内容被改写"，本条是"内容没变但 mtime 被刷新"）**：`-check` 的"写新内容 → 回读比对 → 内容一致则不还原"流水线，在**正常路径**下也把产物**重写一遍**（内容幂等、`git status` 干净），但**mtime 必然刷新**。只要下游存在**依赖 mtime 的闸**（新鲜度门禁：`find <源> -newermt @<产物 mtime>`），它就会把"生成物被 -check 摸过"误读成"源已改" ⇒ 假警告逼人重建（分钟级）或逼人不信该警告（狼来了）。
  - **查法**：对任一 `-check` 生成器，取产物 `stat -c %Y` 与 `md5sum` → 跑一次 `-check` → 再取一次：**md5 不变而 `%Y` 变大**即命中（一条命令即可判，不必读实现）。
  - **与主条的分工**：主条看**内容**（早退不还原 ⇒ 工作区被破坏，`git status` 有脏）；本条看**元数据**（内容幂等 ⇒ `git status` 干净，只有 mtime 动）——**"git status 干净"不能推出"-check 无副作用"**。
  - **处方**：`-check` 全程写临时文件再 `rename`，或先比后写（比得上就一个字节都不落盘）；下游新鲜度门禁的判据同时纳入**内容哈希**，不要只认 mtime。
- **同族面（多级杀阵 / 多级判定型闸：一级判定后**立即还原源码** ⇒ 二级判定读到干净树，2026-10-29 补，#375 审阅）**：两级判定的实现常写成「写突变 → 跑一级（单测）→ **还原源码** → 一级绿才升二级（差分 / 端到端）」。还原只要提前一行，二级就永远对着**原样树**跑：① 二级**恒绿 ⇒ 二级杀阵结构性不可达**（"零锚面"被误报成 survived，报告里的 killed-by-二级 恒为 0 是签名而非"这轮恰好没有"）；② 反过来若干净树上二级本就红（golden 漂移 / 环境缺件），**每个一级幸存者都会被误判成"二级击杀"**（真零锚面被静默掩盖）——两个方向的错都不会有人察觉，因为两级判定各自的输出都"正常"。**查法一条命令即可判**：在二级判定**前一行**记录磁盘上该行的内容（`fs.readFileSync(abs).split("\n")[line-1]`）跑单突变体——看到**原行**即命中；另须显式校验"干净树二级判定为绿"（否则上面第 ② 面已中）。**处方**：还原挪到二级判定**之后**（`try/finally` 兜全路径）；两级各给一条 J9 **正向**证据（二级至少要有一条真的击杀记录），不能只给一级的。
  - **实例**：`scripts/moonbit/gen_stubs` 的 `-check` 在 `os.WriteFile(产物)` 之后才比（写入无分支保护），实测同一份源连跑两次 `md5` 不变而 `mtime` 前移；`scripts/bin/vitro` 的新鲜度门禁随即报「native exe 陈旧（源已改：stubs_gen.mbt 等）」，而该产物对应的源码其实一个字节都没动。
  - **同族面（2026-10-07 补；主条是"内容被重写"，本面是"扫描面包含了**不参与产物**的输入"）**：新鲜度门禁判"源比产物新"时，扫描口径若是**后缀匹配**（`strings.HasSuffix(name, ".mbt")`），会把 `*_wbtest.mbt` / `*_test.mbt` / `*_bench.mbt` 一并纳入——而**测试文件不参与 `moon build` 产物**。⇒ 只改一个测试锚也会被读成"产物陈旧"，触发构建复核（内容其实没变，moon 判 no-work）；单次代价取决于复核走哪条工具链（叠加 `04` 的 B6 ⇒ 可能是分钟级）。查法：对任一新鲜度门禁，`grep -n "HasSuffix\|WalkDir\|filepath.Ext" <门禁源>` 看后缀清单是否把测试/基准文件排掉；或造一个"只 touch 一个 `*_wbtest.mbt`"的输入，看门禁是否报"产物陈旧"。处方 = 扫描面显式排除测试/基准后缀（或改用"参与构建的源清单"单源）。

### D21 · 自证闸的通过条件与它打印的路数 / 计数不一致（2026-10-02 补）

> "看着覆盖了、实际没判"——`-selftest` 的**打印**里有某路的计数，但**通过条件**不含那条路。

- **判据**：读自证分支的判定表达式（`if kinds[...] < 1`）与打印格式串**逐路对照**——打印了 `id=%d` 判定里却没有 `kinds["id"]`，即命中。
- **查法（逐路打坏）**：把每一路的判定分别注入废掉（`if !x[y]` → `if false && ...`），跑 `-selftest`——**仍绿**的那路就是没判的。这是唯一可靠的验证（读代码对照会被同类项淹没：zombie 多张表共用一个 kind 计数，单表失能另一表撑住 ≥1）。
- **处方**：通过条件覆盖全部打印的路数；多张规则表共用一个 kind 时，下限提到"表数"（两表雷 ⇒ ≥2，单表失能即红）；措辞与实际项数对齐（"三路"实为四类就写四类）。
- **实例**：demo UI 对账闸的 `-selftest` 打印 `id=%d` 但判定只有 class/var/zombie——注入废掉 id 路仍 exit 0；且 zombie 计数 ≥1 由两张规则表的雷共同撑住，废掉单表判定也仍绿——修复后四类各 ≥1 + zombie ≥2（两表各一），逐路打坏六发全红。
- **自证分支的覆盖面 ≠ 头注 / flag 描述声称的覆盖面**（2026-10-03 补）：自证入口（`--selftest`）的头注写"篡改帧 / 删基线必红"，而实现只测了管线辅助函数（正则 mask 生效 + 非法输入拒绝）⇒ **篡改基线时主流程红、自证入口仍绿**——"自证通过"被误读成"比对逻辑也验过"。查法：把该 flag 的说明**逐场景**构造出来跑一遍自证入口，仍绿的那条即未覆盖（与主条的"打印路数 ≠ 判定路数"是同一病的两个面：主条看输出，本条看**宣称**）。处方 = 自证里对每个声称场景做一次真注入，或把 flag 说明收窄到实际覆盖的场景。
- **同族面（2026-10-06 补）：断言块在 `fatalf` / `check` 失败后**仍无条件**打印 `ok …` 行（缺 `else` / 提前 `continue`）**。退出码**正确**（失败计数 > 0 ⇒ 非零退出），所以"闸红不红"这一层没错——错的是**日志可信度**：同一段输出里 `FAIL: …` 与紧随的 `ok  …（同形）` 并存，措辞自相矛盾，reviewer / agent 极易把紧跟的 `ok` 读成"这条过了"。查法：逐个断言块看 `fatalf` 之后有没有 `else`（或提前 `continue` / `return`）——没有即命中；再在**已知会红**的输入（如把被测物换成静默 exe / 注入一处篡改）下跑一遍，看是否 `FAIL` 与 `ok` 两类行并存。实例：双臂对拍闸的 fixture 对拍组 / 语料对拍组 / launcher 组（`fatalf` 后接裸 `fmt.Printf("ok …")`；语料组更是 `pass++` 无条件自增 ⇒ "前 N 例同形"恒打印 N），失败时两类行并存；**同一文件的 rc 契约组因用了 `else` 而正确**——同族内写法不一致本身就是信号。处方：`ok` 行移进 `else`；计数只在未红时自增；措辞把"跑了 N 例"与"N 例同形"分开。

| E13 | **工具行为声称未实测**（E9 同族；2026-10-05 新增）：文档 / 注释 / 提交信息 / issue 里断言某条**工具或平台行为**（"默认 clone 不拉该分支"、"该命令不改工作区"、"产物不入库"、"这个文件不会进包"），而该行为**取决于默认值或仓库配置**，从没真跑过 | 对每条工具行为声称做一次**最小实跑**，或直接查**生效配置**：`git config --get remote.origin.fetch`（默认 `+refs/heads/*:refs/remotes/origin/*` ⇒ **clone 会拉全部分支**，含 orphan 快照分支）；`git clone` 后 `git branch -a` + `git cat-file -t <sha>` 验证对象是否真在本地。**别名 / 包装命令不算**，要跑真命令 | 实例：orphan 快照分支的 README、issue 与提交信息**三处同称**"默认 clone 不拉本分支"，实测 `git clone` 后该 remote 分支与对象俱在；同批"体积 69MB"也未标口径（**未压缩内容 58.7MB vs pack 增量 4.7MB，差 15×**，而"clone 重量"正是当初否决全文入库的理由） |
| E14 | **「逐类等价」声称漏了执行载体维度**（E2 同族面；2026-10-30 审阅演化）：提交信息声称「N 处替换与原形态逐类等价」，等价性只比了**脚本文本**，而**执行载体**（shell 解释器版本、超时、env 作用域）在 diff 里看不见却破等价 | 声称等价前逐处取**载体字段**：`shell:`（`pwsh`=7 vs `powershell`=5.1——5.1 的 `Get-Content` 默认 ANSI 解码、`irm` 走 IE 引擎）、`timeout-minutes`、`env:` 作用域——替换面（如内联三行 → composite action）**必须逐字段对表**，不只对命令文本 | 实例：12 处 `shell: pwsh` 的内联安装收敛进 composite action 后写成 `shell: powershell`——提交声称「逐类等价」，实际解释器从 7 降到 5.1（当天无实害：pin 文件纯 ASCII；但 pin 加注释/非 ASCII 即静默错值） |

- **E2 同族面（2026-10-06 补）：提交自述的「修了 N 处 / 全量重刷 M 例」与实测对不上——且**必须取该提交自身的字节**核对，不能看工作区**。两种触发面：
  - **(a) 点名修 N 处，实测只到 M 处 / 修了又破**。对提交信息点名的**每个文件**逐项取态：`git show <c>:<f> | tail -c 1 | xxd -p`（末行换行）、首缩进行前导空格数（缩进）——**并且要把相邻提交也取一遍**，因为"修好的那一项常被下一笔重写回旧形态"。实例：一笔自述"P3-1 editorconfig 5 文件"（1 个缩进 + 4 个末行换行），逐文件取字节实测只有 2 项到位；其中 1 项在下一笔被写回旧态（`0a`→`7d`），另 1 项**从头到尾没动过**（前后两笔都是 `7d`）。查法一句话：**声称的清单 ≠ 逐项取字节**，且要跨提交对比。
  - **(b) 声称「全量重刷 M 例」，而 M 恰好等于某个**子集**的大小——反查是否存在**第六个语料 / 第二个入口**不在 M 里**。冻结清单类资产的"全量"依赖**调用侧枚举**：驱动脚本被 CI 用**多条命令**调用时（一条跑骨架、一条跑四语料），作者按记忆刷"四语料"就会漏掉骨架那条。查法：把提交自述的例数与**各语料逐段** `changed` 计数对账（`json` 解析后逐语料求 `result_sha` 差集）——段计数全为 0 的那一段就是漏刷；再跑一次那条命令确认它红。实例：自述"三驱动 golden 全量重刷 595 例"，与四语料 364+80+138+13 = 595 **逐位吻合**，而 `codegen_skeleton` 段 `changed = 0` ⇒ 干净检出复现 `FAIL——12/13 差异`，对应 CI 该 run 的 failure。判据：**提交给的例数要能被拆成"各语料之和"，拆不出余数才是真全量**。
  - **(c) 声称「端到端就绪 / 即亮 / 数据就绪」，而链路里有一层根本没接线**（2026-10-09 补，与 C1「声明了字段但零消费者」同族——本条是它的**声称面**）：改的是**上游层**（引擎发布帧 / 协议字段 / 产物字段），提交信息与 CHANGELOG 却按"下游早已备好"的口吻写成"即亮/就绪"，而下游那层只有**类型声明**、零渲染/零读取。查法：对每条"X 就绪 / 前端即亮 / 端到端可用"声称，**逐层 grep 消费者**（拿字段名在下游目录全量 grep，排除声明文件自身），零命中即假；**强证据 = 上游/下游该文件里往往有一句自认注释**（"声明 ≠ 消费 / 该字段当前无消费者 / 预留给后续批"），它把"未接线"写成了已知事实，只是没被提交信息采纳。处方：声称收窄到本批真正动过的层（"帧已携带 hint"），把下游接线登记为待办；或本批顺手补一条消费点。实例：一笔修 `serve_step` 让 trap 帧真发布（含 `root_cause_hint`）的提交，声称"demo 死因卡数据就绪 / 前端条件渲染早已备好 / issue「引擎修复即亮」达成"——而 `demo` 全目录对 `root_cause_hint` **零消费**（只有 `types.ts` 的字段声明 + 同文件第 5-9 行明写"八字段当前无前端消费者，为后续接线批的预留声明"）⇒ 引擎侧修复为真、`即亮` 为假。
  - **(d) 验收数字取自「中间态」——同批既加守卫又改被守卫的数据，守卫在最终态当场引爆**（2026-10-10 补）：提交信息里的门禁数字（"N 闸全绿 / 某 diff 零翻")往往在**改完实现、还没填/改数据**的那一刻采的，而数据或守卫在**同一提交里**随后又被改了一笔；作者不会再跑第二遍 ⇒ 提交信息与 HEAD 自相矛盾。查法：**不要复跑作者点名的某一条闸就收工**，要按"本批动了哪些闸的输入面"**批量复跑**（尤其"新增守卫 / 新增断言"与"手工数据表"同时出现时），并把实测与提交信息逐项对账。实例形态：一笔提交新增了"参数类型码元表手误即当场 abort"的守卫，同笔又把某函数表值手改成非法码元（`"PI"`→`"PX"`）——该守卫的正确性**当场被自己的数据触发**，`typeck_diff` / `vm_diff` / `clang_direct` 三处同时红，而提交信息仍写"三处零翻"，且 `moon test` 因无测试覆盖该函数而全绿（**组合信号**：单测绿 + 差分红）。判据：**同批出现「新守卫 + 手写数据」⇒ 必须重跑该守卫覆盖的全部闸，而不是只跑单测**。
  - **(e) 声称「已再生」而实为手改 `@generated` 产物**（2026-10-17 补，与 D20「写入无分支保护」互补——那条讲闸自己改坏树，本条讲人改掉闸的输入）：提交信息写"真源同步 + 产物再生"，实际是**手工编辑**了标注 `@generated` 的文件，于是盘上内容带上了**生成器根本产不出**的行（真源里没有的字段/值）。查法一条命令即可定案：跑生成器本体（裸跑，非 `-check`）→ `git diff -- <产物>`——**只差一行且那行的内容在真源里 grep 不到 = 手改**（跑完记得 `git checkout -- <产物>` 还原）；`-check` 子命令只会给"与现场生成不一致"的结论，不给"差在哪"。叠加判据：手改行常**超前于实现**（文档写了还没实现的能力，真源与产物同批出现该文案而实现侧 `grep` 零命中）。处方：产物一律走再生命令；真源里要写的东西必须是**当下已实现**的形态（否则先落实现、或先不写）。

- **E6 同族面（2026-10-03 补）**：格式约定的**权威是 `.editorconfig`，不是同目录邻居**——邻居常是混合态（机器生成的不带末行换行、手写的带），拿邻居判"惯例"会把违规判成合规。查法：先 `cat .editorconfig` 取 `insert_final_newline` / `indent_size`，再对**改动前后两个版本取字节**比对缩进与末行（别只对工作区取态）。实例：一批把三个既有 JSON 从 2 空格 + 末行换行重排成 1 空格 + 无末行换行（同批新建的资产同款），与 `.editorconfig`（`indent_size = 2` / `insert_final_newline = true`）冲突，且没有任何闸拦——`source_hygiene` 只扫活跃源码目录；后果是内容只增两条、diff 却涨到全文件级噪声，且编辑器按 `.editorconfig` 一保存就会再翻一遍。
  - **复发实例（2026-10-05）**：同形态**第二次**发生——一批把 `known_direct.json` 从 2 空格重排成 **1 空格**（全文件级 diff），并删掉 `scripts/diff_ledger/ledger.json` · `scripts/moonbit/single_source/rules.json` · `scripts/vm_diff/golden_digest.json` · `scripts/vm_diff/known_diffs.json` **四个 JSON 的末行换行**；权威段是 `.editorconfig` 的 `[*.{json,toml}] indent_size = 2` + `[*] insert_final_newline = true`。**机判命令（逐文件、带父版本对照）**：末行换行 = `git show <c>:<f> | tail -c1 | xxd -p` 与 `git show <c>^:<f> | tail -c1 | xxd -p` 比 `0a`；缩进 = 取"第一个以空格开头的非空行"的前导空格数。**处方至今未落实**（`source_hygiene` 只扫 `moonbit/`、gofmt 只管 `.go`、无 JSON 格式闸）⇒ 该形态每批都会复发，审阅时按机判命令一次扫全批改动的 JSON。
  - **复发实例（2026-10-06）**：同形态**第三次**发生——一批新增/重写 **serve_smoke 豁免表**（`moonbit_exemptions.json`）时把整个文件从 2 空格缩进重排成 **1 空格**（全文件级 diff，内容只多一个 `wasm_assertions` 段）；权威段同 `.editorconfig` `[*.{json,toml}] indent_size = 2`。**机判（本批新增项）**：缩进 = `awk '/^ /{match($0,/^ */); print RLENGTH; exit}' <f>`，期望 2。**判"本批违规"必须带父版本对照**：同批改动的另一 JSON（teaching golden）也是 1 空格，但取 `git show <c>^:<f>` 便知它**改动前就是 1**（历史遗留，非本批责任）——只看 HEAD 会把旧账算到本批头上。
  - **复发实例（2026-10-06，第 4 次）**：紧接着上条的同日另一笔**修复提交**把 `scripts/clang_direct/known_direct.json` 从 2 空格整文件重排成 **1 空格**（内容只删 1 个 known 条目，diff 却是全文件级）；机判 `awk '/^ /{match($0,/^ */); print RLENGTH; exit}' scripts/clang_direct/known_direct.json` = 1（期望 2），父版本 = 2 ⇒ 本批引入。讽刺点：**修 bug 的批自己引入格式违规**，而同批其余 6 个 JSON 均保持 2 空格——**同族内写法不一致本身就是信号**（与 A1 的"同族臂并排看"同理）。

- **E5 / E9 同族面（2026-10-04 补）**：
  - **E5 面：头注写的是「计划做的机制」，不是「实际做的机制」**。迁移批里常见头注先描述理想方案（"用 X 机制补齐 Y 缺口"），实现却退成另一条路（打一行 `@ts-expect-error` / 直接不写），甚至**压根没做**——头注却已按"已做了"的口吻落笔。查法：对每个被改动的头注做一次全库 grep，逐条回读"它描述的机制在代码里找得到吗"（找的是机制，不是关键词）；同族还包括**章节注释被切分时留在错误文件里**（注释归属一个模块，代码搬到另一个模块）。
  - **E9 面：重大让步 / 裁定只落在提交信息里**：关掉某项严格检查、某闸"清零后再接线"、某防线暂缓——写在 commit message 与代码行内注释里，**规格层（文档）零登记** ⇒ 下次审阅只能翻 git 历史才知道"这是有意为之，不是漏了或忘了"。查法：对提交信息里每条"裁定 / 知情让步 / 待办"，**同时 grep 文档与代码两边**；只有提交信息命中即命中。处方 = 让步登记进语境层文档（本仓三层文档纪律的"裁定"层）。
  - **E9 面：声称的「机械 git 操作」根本没发生**（2026-10-04 补，与 E2 是"动作 vs 数字"的分工）：提交信息 / 头注写"已 `git rm --cached`"、"已脱库"、"已移出仓库"，而该路径**仍在版本控制内**。查法：① `git ls-files <path>` 非空 = 仍跟踪；② `git show <commit> -- <path>` 看它是**删除形态**（整段 `-`）还是**修改形态**（含 `+`）——修改形态即 RM 未发生（常见成因：`git rm --cached` 之后又被 `git add -A` 收编）；③ **别用 `git check-ignore -v <path>` 反证**——对已跟踪路径它恒空，会把"规则没覆盖"误判成"已被跟踪"消失。叠加后果：`.gitignore` 条目对已跟踪文件**完全无效**，且产物头注里的"产物不入库"承诺变成**文件内的假陈述**。处方：改机械操作类声称的验收方式为"跑 `git ls-files` 看结果"，而非"看提交信息有没有写"。
  - **E9 面：新写入文档的「命名/内容不变式」不设机判，同批改名即自违**（2026-10-24 补）：批次为键名/字段名立规则（如"键带 `E####_` 前缀 ⇔ 渲染文案首段带同码；无码文案不带前缀"），只写进真源头注与 CHANGELOG，未加契约锚；同批把 `E_div_zero_inspect` 改名成 `E3088_div_zero_inspect`——该条正是"提示段"且文案无码，**规则在自己文件里就有反例**。查法：对每条新成文的命名不变式写 5 行脚本全量核（键正则 ↔ 文案码正则双向），再看仓库里有没有对应锚；零锚 + 有反例即命中。处方：规则要么降级为"仅主文案段"，要么给真源解析器加机判（`teaching_gen_check` 的负例族是最省事的落点）。

- **E11 同族面（2026-10-04 补）：工作流 / 管线「引用的仓库内脚本未入库」**——E11 是"手册引用的资产在库外"，本条是同一病的**可执行面**：CI 步骤（或组装 / 部署脚本）里写死 `go run ./scripts/<新工具>`，而该脚本只存在于某个工作区的未提交副本 ⇒ 本地跑绿、CI checkout 后目录不存在直接失败（且失败点落在新增步骤，易被误读成"新代码坏了"）。查法（两条都要）：① `git ls-files <脚本目录>` 是否为空；② `git log --all -- <脚本目录>` 是否为空（空 = 从未入库，排除"曾入库后被删"）。同批常伴随**文档连坐先落**——脚本清单已把它登记为"✅ 已建"，形成"登记了但不存在"的假状态（E9 叠加）。处方：把"workflow 引用的每个仓库内路径存在且入库"做成一条对账闸，别靠人记得。
- **E11/E13 同族面（2026-10-07 补，审阅处置批入账）：手册自身改写引用面时按脑测填迁移目标**——迁移 / 退役批同步 `.agents/skills/**` 的可执行指令时，**替换目标**（新目录形状 / 新参数面 / 新门禁的有无）未经 `ls` / 实跑即落笔，产出「形状合理但不存在 / 不属实」的指令。与 E11 分工：E11 是"引用的资产本来就不在库"；与 E13 分工：E13 是"工具行为声称未实测"——本条是**改写动作本身**同时引入两类犯规的复合（脑填路径 = E11、脑填行为 = E13），且犯在「同步引用面」这道本应消灭旧路径问题的工序上。查法：改写引用面后，对**每条新写的路径 / 参数 / 行为断言**逐条 `ls` / 实跑再落笔（"路径形状合理"不是存在性证据）；可机判面交给引用路径存在性闸（`scripts/skill_path_check`，2026-10-07 接线 hygiene）。实例：一次删区同步批脑填 `corpus/cases/` 中间层（实测 7 个 suite 直铺、无该层）、给不认 `-o` 参数的壳保留 `-o`（静默忽略、零产物零告警）、把已有 stderr 告警门禁写成"无门禁"——审阅亲跑三条全抓获。

- **E13 同族面（2026-10-10 补）："同报 / 已对齐 Clang -Wxxx"的断言只覆盖了语料里**存在的那一种形态**。查法：把提交信息里每条"同报 / 全对齐 / 双向"断言翻成一条**最小反例探针**（换符号 / 换节点形态 / 换标量宽度），跑 Clang 真值对拍；对不上即声称面漏。与 C7 分工：C7 是代码面（判据形状），本条是声称面（断言范围）。实例：提交信息写"常数下标静态越界对齐 `-Warray-bounds`，负下标同报"，实测只有**正**字面量命中，`a[-1]` 静态零警告（Clang 报）——断言取自"语料能跑出来的那一侧"，被绕过的形态既没进语料也没进探针。

- **D8 同族面（2026-10-14 补，用户审阅提名入档）：存在性闸的相对路径引用按仓库根解析，skill 内相对目录与仓库根一级目录撞名即假红**——实例：`skill_path_check` 把 SKILL.md 里的 `assets/xxx.py` 按根解析，而仓库根恰有 `assets/`（icons-preview.svg）⇒ 4 处假 MISSING；仅当 skill 资产目录名与根一级目录同名才触发（`references/` 不撞名故绿）。查法：`grep -rn "assets/" .agents/skills/*/SKILL.md` + 对比 `ls <repoRoot>` 首段。处方：闸对根解析 miss 的路径回退按**引用文件所在目录**再试（本仓已修——`skill_path_check/main.go` fallback 臂）。

- **D10 同族面（2026-10-14 补，用户审阅提名入档）：新增 skill/文档时，生成物连坐面不在 checklist**——实例：`#73` 线新增 `vitro-llm-corpus-probe` skill 后 `gen_svg -check` 红（agent-skills-overview.svg 只画 7 个实际 9 个），且两个已推提交自报「gen_svg 全绿」系手挑子集（D1 问五）。查法：新增/改名 `.agents/skills/**` 后必跑 `node scripts/gen_svg/main.mts -check`。处方：把该闸挂入「新增 skill 批次连坐清单」（ci_checklist 已在 CI 每跑覆盖——本地批次验收清单补记）。

- **A1-g 同族面（2026-10-14 补，用户审阅提名入档）：改值型修复只验值面不验诊断面**——实例：designated 全局值对了（sparse fill 对）但（a）symbols 表没进（P1-b 教学文案降级）（b）W3005 假阳性留着（文件作用域混合形态警告+fix_suggestion 张冠李戴）；语料锚只写合法形态（A2-b 形状单一）⇒ 误收面零覆盖。查法：修复后对同一输入比 clang 的**诊断集合**（不只比 stdout/退出码）——`compile` 输出的 W/E 行逐行对；语料补「须报错」形态（双侧编译失败等价 SAME 先例）。处方：修复验收清单从「值对」升「值对+诊断集合对+语料含负例」。

- **E2 同族面（2026-10-13 补，审阅报告提名入档）：「裸 / 全量」双行计数只改一行**——同一文档相邻两行声明同一真值的两个口径（如 `moon test` 裸 750 行 + `--target native` 全量行 = 裸 + native-only），连坐只改了裸数、全量行按旧裸数写的和数原地不动 ⇒ 文档内部自相矛盾且 CI 网关红。成因：改数字时按 grep 命中逐处改，而全量行的数字（如 870）与被改数（746→750）**字面不同**、grep 同数字抓不到它。查法（机判单点）：`node scripts/moonbit/testcount/main.mts`（README.md / README.mbt.md 的双行自洽性网关——改任何测试数后必跑）。实例：a4860bed 把裸 746→750 连坐了 5 处，相邻的全量 870（=746+124 旧和）漏改，真值 874；提交信息自称"gen selftest 全绿"而 testcount 实红——**"自称全绿"与"网关红"并存本身是 E2+E13 叠加信号**。

- **D8 同族面（2026-10-23 补，PR #281 审阅）：课源锚点/写死下标类缺陷的测试只冻结字符串、不对真实帧流求值** —— 分镜锚点（vitri-scenes v2 的 `@arr_change:N` 等）与课内正文帧表是同一真值的两个载体；若测试只断言锚点**表达式字符串**（连错的序数也一起冻成期望值）而不在真实帧流上 resolve 对账，锚点序数错位全程假绿。查法：锚点类内容**必须在真实帧流上求值并与课内表格逐幕对账**（拉语句级/指令级双粒度帧流跑 resolveScenes——`cmd/serve` exe 产帧流或 CLI step 流 coalesce）；只锁字符串形态的测试是结构面锚不是语义面锚，两者都要有。实例：bubble_sort 六幕按「每轮 4 变」线性外推序数，幕 03/04/05 与正文表错位三帧段，pure 测试 42/42 全绿（只冻字符串）。
- **E2 同族面（2026-10-15 补）：和数连坐而分量未重采**——分解式数字（裸数 + 分量 + 全量和数）连坐时只按新裸数**重算和数**（如 776+125=901，算术自洽），而**分量未逐包重采** ⇒ 文档内部自洽、`testcount` 全绿（它只校裸分解行），但与事实静默漂移。与上条分工：上条是"和数没跟着改"（自相矛盾 + 网关红），本条是"和数改了、分量没重采"（自洽 + 无闸可见）。查法：连坐时对**每个分量**各跑一次实测（`moon test -p <pkg>`，或全量目标跑一次与各分量求差）——不接受"按旧分量重算出来的和数"；机判面只有算术自洽，事实面必须重采。实例：testcount 连坐批把裸 774→776、native 全量 899→901，而早前同窗口一笔修复加的 6 个 gateway native-only 锚未连坐 ⇒ 分解行写 native-only 125 / gateway 110，实测 131 / 116 / 全量 907（该行在 facts 人工桶、testcount 不校，零闸）。

- **E13 同族面（2026-10-10 补）：把"新语料双侧 SAME"当成编译等价之外的结论** —— 新增语料用例时，若该例在**执行期**两侧就注定不等价（目标实现有受检 UB trap、参照实现没有 sanitizer），它会永久落在 `DIFF`（未登记）而不是 `SAME`/`DIFF-KNOWN`；声称"双侧等价"前必须**实跑该例并看它落在哪一桶**（`SAME / DIFF-KNOWN / DIFF`），不能只看"两边都能编过"。判据：任何"新例已对拍 SAME"的声称，都要求给出**该例在直拍闸的判定行**；只有 `SAME` 或**有 reason 文本的 `DIFF-KNOWN`** 才算对齐。
