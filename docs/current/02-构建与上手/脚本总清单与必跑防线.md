## 一、必跑测试规定

### 1.1 CI 全集（push / PR 自动执行，等价"必须全绿"）

权威源 = [`.github/workflows/ci.yml`](../../../.github/workflows/ci.yml)（单一 `rust` job，
Windows runner；夜间 schedule 对 Shadow 强制 `--refresh-clang` 全量重算防 Golden 漂移）。

### 1.2 本地提交前必跑（按改动区域——此前无此规定，本表为裁定成文）

| 改了什么 | 提交前必须跑 |
|:---|:---|
| `native/` 引擎行为（Rust） | `cd native && cargo build --release`（**产物新鲜度硬前提**——影子/回放读 release 产物，版本串含 HEAD，不重建 = 验证陈旧二进制）→ `cargo test --workspace --all-features` → clippy；改引擎语义 → `go run ./scripts/shadow_verify` |
| `native/runtime_libc/src/*.c` | 上行 + `go run ./scripts/precompile_bytecode_libc`（再生成）+ `git add` 产物 |
| `native/src/capi` / serve 协议 | 上行 + `go run ./scripts/replay` + `go run ./scripts/serve_smoke` |
| `moonbit/` 任意 | `cd moonbit && moon check` → `moon test` → `moon fmt` |
| `moonbit/` 生成物源（diag 码表 / host 路由 / libc 存根头） | 对应 `go run ./scripts/moonbit/gen_diag` / `gen_host_route` / `gen_stubs` 再生成（各带 `-check` 幂等门禁；产物禁手改） |
| `moonbit/` 公共 API（pub 符号） | `go run ./scripts/moonbit/moonbit_surface -check`（新对外面必须收面或入白名单 + 消费边登记） |
| `moonbit/libc` 放行集 / `codegen` host 路由 / `bytecode` libc 索引（任一改动） | `go run ./scripts/moonbit/libc_single_source -check`（三表分叉即红；合法变更须同步 `scripts/moonbit/libc_single_source/rules.json` 后复跑，禁改判定代码） |
| `moonbit/**/moon.pkg`（import 块）或新增包 | `go run ./scripts/moonbit/pkg_deps -check`（越层/成环/未登记分层即红；合法变更须同步 `scripts/moonbit/pkg_deps/rules.json` 的 levels） |
| `native/runtime_libc/src/*.c` 或 `moonbit/codegen` 的 library 路径 | `go run ./scripts/moonbit/libc_boot_diff`（自举等价性；**先** `cargo build --release --bin vitro_cli`） |
| 单源清单里任一条目涉及的代码（见 `scripts/moonbit/single_source/rules.json` 的两侧位置） | `go run ./scripts/moonbit/single_source -check`（新增同名单源实现即红；合法变更须同步 rules.json 的 allowed_def_files） |
| `moonbit/**/*.mbt` 的 **pub 面**（pub fn / pub type / pub const 增删改） | `go run ./scripts/moonbit/mbti_sync -check`（接口面脱节即红；闸会顺手同步 `.mbti`，红完一并提交即可） |
| 语料新增 / 扩展（`native/tests/cases/` 下 .c 增补，尤其 struct 密集或成员访问密集的大程序） | `go run ./scripts/perf_budget -check`（超预算即红，指向被推翻的性能裁决；合法变更须同步 `scripts/perf_budget/rules.json` 的 `max_per_file` 并复核裁决） |
| `native/include/vitro_capi.h`、`vitro_shared/src/error_codes.rs` 的错误码，或 `scripts/internal/capi/capi.go` 的 DLL 绑定符号 | `go run ./scripts/gen_capi_bindings -check`（值不一致 / 未登记缺口 / 绑定符号无声明即红；合法裁剪须写入 rules.json 的 `excluded_patterns` 并给理由） |
| `native/src/unified/*.rs`、`native/src/session.rs` 的 StepPayload 家族类型，或 `docs/spec/STEP_PAYLOAD_SCHEMA_V0_1.md` 的字段表 | `go run ./scripts/gen_protocol_ts`（再生成）→ `-check`（幂等 + 字段集双向对账）；**改任一方向都须重跑**，产物 `protocol/index.d.ts` / `fields.mjs` 禁手改 |
| `moonbit/lexer|parser|typeck|codegen` 语义 | 对应 `lexer_diff` / `parser_diff` / `typeck_diff` / `codegen_diff`（对拍语料 `native/tests/cases/`） |
| moon 工具链升级 | `go run ./scripts/toolchain_probe --update-baseline` + 全部门禁（迁移义务见探针头注） |
| `scripts/`（Go 驱动） | `go vet ./scripts/...` → `go build ./...`；**判定型驱动加 `--selftest` 证红**（J9 义务，见[脚本埋雷验证记录](../07-质量与裁定/脚本埋雷验证记录.md)）；动真值采集 → `go run ./scripts/facts check` |
| 文档（含 SVG 插图数字） | `go run ./scripts/facts check`（红了改数字或跑防线刷新真值）；SVG 插图红 → `go run ./scripts/gen_svg`（禁手改 `data-fact` 锚定数字） |
| `templates/` | `python scripts/sync_templates.py` + Shadow Verification |

### 1.3 语料真值口径（2026-09-22 定；此前 597 / 598 / 600 三口径并存且均无 as_of）

**四语料真值 = 600**（实测：`baseline` 365 + `gap` 16 + `knr` 81 + `leetcode` 138）。
`codegen_skeleton` **另计 13**（骨架快失败面，不入四语料）；C++ 语料 83 个 `.cpp`（随砍 C++ 冻结）。

**引用任何语料数前先数目录**（本仓文档数字的历史漂移高发区）：

```bash
for d in baseline gap knr leetcode; do echo -n "$d "; ls native/tests/cases/$d/*.c | wc -l; done
```

文档里的 597（S3 收官）/ 598（S4–S5 收官）是**各片收官时的 as-of 快照**，不是当前真值；CURRENT 文档陈述"当前语料数"时必须写 600 或标注实测日期。
语料**随扩展增长**（597 → 598 → 600），故**不做机器对账**——facts 的「解析差分样本数」键长期处于"待采集"即因此项非稳定量。
