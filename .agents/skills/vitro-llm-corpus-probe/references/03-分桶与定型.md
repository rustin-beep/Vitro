# 03 · 分桶与定型（反例库）

## 分桶实现

```python
def bucket(r, expect):
    vals = [r["clang"], r["gcc"], r["wasm"], r["native"]]
    if any(str(v).startswith("JUDGE_ERROR") for v in vals): return "judge_error"
    if r["wasm"] != r["native"]: return "arm_divergence"
    if r["clang"] == "REJECT" and r["wasm"] == "ACCEPT": return "vitro_accept_clang_reject"
    if r["clang"] == "ACCEPT" and r["wasm"] == "REJECT": return "vitro_reject_clang_accept"
    if r["clang"] != r["gcc"]: return "judge_divergence"
    return "no_signal"
```
**顺序敏感**：`judge_error` 最先（自身故障优先暴露），`arm_divergence` 次之（AGENTS.md #14 列为最高 severity 独立桶）。

**产物里必须带**：`judge_id`（判据快照指纹）、`expect`（P/N）、`axis`（方向族）、`bytes`、`dt`、`wasm_codes` / `native_codes`。缺 `judge_id` 的结果**不可解释**。

## ★ 定型三问（逐条必过）

拿到 `vitro_accept_clang_reject` / `vitro_reject_clang_accept` 后，**先别登记**，按序问三问。

### 问 1 · 是文档化边界吗？

查 `docs/current/03-语言子集/C语言子集规范.md`：
- **§3.1 排除清单**：`bitfield`（提示"暂不支持该特性"）、`restrict`（"暂不支持存储类修饰符"）
- **差异清单尾表**：`不支持：bitfield、_Complex、_Static_assert、_Alignas、_Noreturn/_Thread_local/_Atomic、__attribute__((cleanup)) 等 GCC 扩展、自定义变参`
- **§828**：「Designated Initializer — 已支持 `.field = val`（结构体）和 `[i] = val`（一维数组），**局部变量上下文**；**全局/静态变量 designated init 暂不支持**」
- **§3.2 隐式转换表**：`int → pointer` **✅ 允许**（只警告"整数被隐式转换为指针…"）

**实锤反例 A · 文件作用域指定初始化器 → `E0`**
- 我原先把 `int a[8] = { [2]=7, [5]=9 };`（文件作用域）被拒登记为「**误拒合法 C**」——**定性错误**。
- 它**是文档化边界**（§828 明写暂不支持）。二分证明：**块作用域同写法 ACCEPT、文件作用域普通列表 ACCEPT** ⇒ 触发面精确是「文件作用域 × 指定初始化器」。
- **真正可修的是**：它报 `E0`（**无分类的兜底码**），而同为"不支持"的 bitfield/restrict 都报"暂不支持该特性" ⇒ **口径不一致**才是指向点。

**实锤反例 B · `int → pointer`**
- 误收样例（`print_int(42)`）里的转换**本身是文档允许的**（§3.2）。
- ⇒ 所以**不能**按"接受了非法程序"定性；要去看它**为什么连该发的警告都没发**（见问 2）。

### 问 2 · 是保留名冲突吗？

查 `moonbit/typeck/builtin.mbt` 的内置名分派表。

**实锤 · `print_int` 保留名劫持（本规程最硬的一条）**

```c
void print_int(int *p) { (void)*p; }          /* 形参 int* */
int main(void) { int v = 42; print_int(v); }  /* 传 int ⇒ clang/gcc 双双报 int→pointer，vitro 零诊断 ACCEPT */
```

**二分定死**（全部在 native 臂实跑，同文件连跑 3 次稳定）：

| 变体 | 结果 |
|---|---|
| 函数名 `print_int` | **ACCEPT（零诊断）** ← 唯一 |
| `f` / `g` / `f2` / `ff` / `foo` / `print` / `print_x` / `println` / `my_print` | 全部 REJECT `E3054` |
| 只改**参数名**（`ptr` / `f`） | 无影响 ⇒ 与参数名无关 |
| 空白 / 拆行 / 空行 | 无影响（**排除"看起来像"的伪因**） |

**根因**：`moonbit/typeck/builtin.mbt:60`
```
"print_int" | "__vitro_output" | "__vitro_step" => self.check_builtin_print_int(args, loc, name)
```
`print_int` 是**编译器保留的内置函数名**（demo 输出通道，`builtin.mbt:618` 注释：「单 int 参」）⇒ 用户定义同名函数时，**调用点按内置签名检查/放行**，用户形参 `int *` 被无视。
旁证：`CHANGELOG.md` 有「`print_int` 别名臂」勘误条；`moonbit/libc/libc_wbtest.mbt:52` 断言 `lookup("print_int") is Some(_)` 且 `is_libc_func("print_int")` 为 **false**。

**定性写法（照抄，别写成"误收非法程序"）**：
> 保留名冲突致静默放行——用户定义与内置保留名 `print_int` 同名时，调用点按内置签名（单 `int` 参）放行，正解应报「与保留名重定义/冲突」。

**面**：任何把函数命名为 `print_int` 的程序（教学场景概率不低）。

## 误拒侧的稳定族

实测最稳定的误拒族是**限定符顺序**（`E2005`，常见 `E2005×6 + E2007`），三个模型独立复现，且跨多个方向（文件作用域 `static const` / `const static`、参数 `int const x`、甚至出现在"指针退化"这类别的方向里）。
⇒ **方向是稳的（缺口族），形状是模型定的**——语料来源的**家族数必须继续加**，而"这个方向饱和了"不能只凭一两个模型说。

## ★ 同根多症状（2026-10-13 新增）—— 按"根"归并，不要按"码"归并

**实锤**：500 例里 3 处非新根，全是**已有根的第二张脸**：

| 根 | 症状 A（发现的） | 症状 B（后来发现的） |
|---|---|---|
| 枚举成员的编译期常量求值没接上 | 数组尺寸 → 误判 VLA，码 `E0` | `case` 标签 → `E3047`「不能使用**变量**」 |
| `print_int` 保留名劫持 | **误收**：`print_int(v)` 传 `int` 零诊断放行 | **误拒**：`print_int(&x)` 传对 `int*` 却被 `E3029` 拒 |
| 指定初始化器 | 文件作用域被拒（`E0`） | 解析层 `E2008`「Designator 预期 ']'」 |

**做法**：拿到非 `no_signal` 后，**先按"最小复现的触发机制"归并，再决定开几条 issue**；
同一个根的不同症状**补进原 issue 正文**（"补充"节），**不要另开新 issue**——否则一个根会被拆成三条，读者无法看出它们同源。

**判据**：换一个语法**位置**（数组尺寸 / `case` 标签 / 参数 / 赋值右值）就复现 ⇒ 多半同一个根；
换一个**层面**（parser / typeck / 常量求值）就复现 ⇒ 可能是不同根。

**推论**：报告"缺口个数"时必须说明口径——是**形状数**还是**根数**。500 例批次：形状 9 个，根 6 个。
