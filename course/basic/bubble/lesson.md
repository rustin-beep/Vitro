## 这门课在做什么

右边的编辑器里是一段冒泡排序。点「运行 + 采集帧流」后，Vitro 不是把它一口气跑完——而是把 VM 的**每一条指令**都录下来，变成可以来回拖动的时间轴。

## 先跑一遍，看三个东西

1. **数组索引格**：左侧的索引格就是内存里 `a[5]` 的实时快照。注意交换发生的那两帧——柱子不会瞬移，你能看到「半完成」的中间态（`a[j]` 已写入、`a[j+1]` 还是旧值）。这不是 bug：**指令级的真实执行状态**正是白箱教学和黑盒调试器的分界线。
2. **当前行描边**：编辑器里亮着的行就是 VM 正在执行的语句。
3. **时间轴**：拖动底部滑条，任意进退。`seek` 是随机访问——不是重新跑，是从检查点恢复。

## 一个常见错误，先放在这里

初学者最常把内层边界写成 `j < n - i`（少了那个 `- 1`）：

```c
for (int j = 0; j < n - i; j++)   /* 反例：多比一次，靠相邻交换仍能排对，但白做一次比较 */
```

程序结果仍然正确——这正是它危险的地方。在 Vitro 里跑这两个版本，对比帧数：错误版本每轮**多一次比较**，帧流更长。时间轴的长度本身就是算法正确性与效率的显影。

## 试着改

把 `a[5] = {5, 3, 1, 4, 2}` 改成已经有序的 `{1, 2, 3, 4, 5}`，重新采集。帧数变短了吗？想一想：哪一步提前终止了，哪一步没有——这是下一课「为什么冒泡最好情况是 O(n)」的入口。
