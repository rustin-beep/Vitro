# Vitro 生成器 -check 契约

**适用场景**：新写或重构 `scripts/` 或 `scripts/moonbit/` 下的生成器（产物进仓、`-check` 进 CI 的那类），或排查「闸门看似接上了但恒红 / 不工作 / 静默改写产物」。

> ⚠️ **先确认路径归属**——生成器分两处，`moonbit/AGENTS.md:45-47` 已为同型错误立过一次勘误：
>
> | 位置 | 生成器 |
> |---|---|
> | `scripts/` | `gen_svg` / `gen_protocol_ts` / `gen_demo_algorithms`（gen_capi_bindings 已随 2026-10-05 C ABI 面裁撤删除）（发射形态，见下节） |
> | `scripts/moonbit/` | `gen_diag` / `gen_host_route` / `gen_libc_data` / `gen_protocol_fields` / `gen_stubs` |
>
> **9 个里 5 个在 `scripts/moonbit/`**。把 `./scripts/gen_diag` 写成少一段的形态，在 `moonbit/` 与仓库根**两处都跑不起来**（`moonbit/` 下无 go.mod 也无 `scripts/`）。`moonbit_surface` 是唯一例外：其内部自带 `os.Chdir("moonbit")`，必须从仓库根调用。

**产物首行统一**：`@generated by <生成器路径> —— 禁手改`（git diff/review 工具链按 @generated 识别）。新增生成器沿用此头，勿再造新写法。

## 两种产物形态（先选形态，契约随之；2026-10-04 确立）

| 形态 | 产物归宿 | 闸 | 适用 |
|---|---|---|---|
| 入库 + `-check` | git 跟踪 | CI 比对字节一致（下方五条硬契约） | 产物被仓库内源码/文档直接消费（.mbt 源、协议面等） |
| **发射** | **不入库**（.gitignore），CI/部署消费前现场发射 | 发射即闸：完备性断言内置生成器、失败即红；陈旧产物无法存在 | 产物只被运行时消费、且消费侧已有构建管线（demo：`js/*.js`、`wasm.wasm`、`algorithms.js` 三产物同形态） |

**发射形态硬契约**：① 完备性断言必须内置生成器（对账真值源全集——发射是唯一执行路径，断言即闸）；② 发射步必须排在所有盘上产物消费者之前（assemble check / smoke 类，否则它们在无产物处先红、报错误导）；③ `.gitignore` 登记 + `git rm --cached`；④ `@generated` 头注明「产物不入库：现场发射」；⑤ **无 `-check` flag**（产物无入库面，比对失去对象；留着是死代码）。消费发射产物的工作流要各自发射（ci.yml 闸侧 + pages.yml 部署侧，无产物传递）。先例：`gen_demo_algorithms`（2026-10-04 由「入库+check」转发射，产物 92KB 曾是唯一入库的生成物——先于 TS 重写批「产物不入库」原则入库的漏网特例）。

## 五条硬契约（缺任何一条 = 闸门失效；入库 + -check 形态）

1. **flag 走 `flag` 包**（`flag.Bool("check", ...)`），禁手工 `os.Args[1] == "--check"`。手工形态只认双横线，`-check`（单横线，CI 与其他生成器的调用形态）会**静默落入生成路径直接改写产物**。
2. **生成流程必须内置 `moon fmt`**，产物形态以 fmt 为准，gen 原始输出只是中间态。缺这步的后果不是格式难看：入库的是 fmt 后形态、生成器吐未 fmt 形态 ⇒ `-check` 在**干净仓库上必红**，根本进不了 CI。注意 fmt 宽度按 UTF-8 字节计（中文 3 字节，超 ~84 字节折行）。
3. **check 无副作用**：写 gen 输出 → fmt → 回读比对 → 不等则**恢复运行前状态**再 exit 1。「还原」语义 = 恢复到运行前（不是恢复成正确内容）——注入篡改后跑 check，工作区会保留你注入的那份（`git status` 标 M 属正常），验证完自己 `git checkout --` 撤。
4. **行尾归一化后再比较**（CRLF 假红），与 `.gitattributes` 锁 LF 双保险。
5. **需要 `moon fmt` 就必须 chdir 到 `moonbit/`**（workspace 命令）——这是必然而非风格选择；顺带使 `../native` 等相对路径零改。

## 六个实战陷阱（全部实测修出的缺陷）

6. **临时文件必须 `.mbt` 结尾**：moon fmt 只处理 moon.pkg 覆盖的 `.mbt`——`xxx.mbt.tmp` 不会被 fmt，与产物恒不等，check 永红。命名 `xxx_check_tmp.mbt`（同包会被 fmt），比对后删除。
7. **多产物必须「全部比对完再统一还原」**：逐个「比对→还原→exit 1」会在第一个漂移产物处退出，字典序靠后的产物停留在 fmt 后形态**未被还原**。正解 = 收集全部漂移项 → 统一还原 → 一次性报红（列出全部漂移文件名）。回归测试的 **-check 错误路径必须单独走一遍**（跑完立刻 `git status`），只验绿路径抓不住这条。
8. **注释块 + 空行 + `///|` 必须由模板自出**：整包 fmt 的稳定形态是「注释块+空行+`///|`+声明」，而带文件参数的 `moon fmt <files>` 产不出该形态。模板少输出空行 ⇒ 手补后 check 恒红，且**只删空行提交是错的**（后续任何一次整包 fmt 会加回来）。验证闭环必须**三验**：① `-check` 绿 ② 产物与 HEAD `git diff` 零 ③ 跑一次整包 `moon fmt` 后 `git status` 仍干净。
9. **从源码文本抽符号表**：显式约束抽取窗口（定位目标函数起点、扫到收尾 `}` 为止）+ 重名 fail loud + 抽取条数低于阈值即红。否则今天「恰好正确」，明天新增一个同形态分支就静默污染。
10. **解析了但未消费的字段 fail loud**（如 JSON 字段声明了却不用）——无声的版本漂移入口，当前值为空 ≠ 永远为空，且没有任何闸能替你发现。
11. **gen 与 fmt 互踩有两种形态**：宽度换行（第 2 条）与格式化空行/`///|` 归属（第 8 条）。遇到「-check 恒红」先想这两处。
12. **多产物生成器的"单产物子命令 + all"必须双向登记**：新增产物时只加 `case "xxx"`、漏把调用加进 `all` 分支 ⇒ 新产物**不在 `-check` 闸内**，篡改/失步一律不红（闸看似接了、实际没牙）。2026-09-29 gen_svg 加 skills 图实测：J9 篡改证红时发现 `-check` 恒绿，根因即此。核对法：`grep -c "genXxx(" main.go` 应 = 分支数 + all 调用数。
13. **读入外部结构化文本先归一 CRLF**：`core.autocrlf=true` 的 Windows clone 工作区里仓库文件是 CRLF，`strings.HasPrefix(text, "---\n")` 这类行首锚会误判（2026-09-29 同日实证——checkout 还原 SKILL.md 后 frontmatter 解析全挂）。归一 `strings.ReplaceAll(text, "\r\n", "\n")` 再解析 + `.gitattributes` 锁 `.agents/** text eol=lf` 双保险。

## -check 产物的防漂移三规则（CI 首跑两轮红的学费）

- **比对面只含跨环境稳定值**：采集时刻类内容（as_of 时间戳）**禁入生成产物**——CI 重生成时必变，逐字节比对必漂。
- **facts 依赖收窄**：只依赖 CI 必可用的键（read_report / fs_scan / read_const 类）；CI 里 moon test 秒挂会使其真值 unavailable，硬消费者（mustFact）即 fatal。
- **CI 产物落位**：hygiene job 的 artifact upload/download 会改变目录层级，facts 采集器按原位路径读——CI 里须有「恢复产物到引擎报告路径」的步骤，否则硬消费者首跑即爆。

## 接 CI 前的自检清单
- 本地 `-check` 与 `--check` 两种横线各跑一遍。
- J9 证红：`printf '\n// tampered' >> <产物>` → exit 1 且文案正确 → 撤销 → 绿。
- 生成幂等：重生成后与入库产物 sha256 一致 + `git diff` 零。
- 记住：**生成器闸**（产物新鲜度）与**审计闸**（surface / pkg_deps / single_source / mbti_sync 等）是两类，都要在；新闸照同款接入。
- **在册生成器全量（9 个，均在 `ci.yml` 命中——8 个 `-check` + 1 个发射）**：

  | 路径 | 生成器 |
  |---|---|
  | `scripts/` | `gen_svg`、`gen_protocol_ts`、`gen_demo_algorithms`（发射形态） |
  | `scripts/moonbit/` | `gen_diag`、`gen_host_route`、`gen_libc_data`、`gen_protocol_fields`、`gen_stubs` |

  （清单变更时同步更新此表；核对：`grep -oE "gen_[a-z_]+" .github/workflows/ci.yml \| sort -u`——发射步同样是 `go run` 形态可命中）
