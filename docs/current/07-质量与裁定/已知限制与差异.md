## ② 教学语义设计（有意为之——不是缺陷）

Clang 在这些输入下是**未定义行为或静默错误**；Vitro 的白箱设计把它们变成可教学的确定性诊断。这些条目**不会修**——它们是产品本体。

| # | 条目 | Clang 对照 | 语义 |
|---|---|---|---|
| 1 | **受检访存三缺口转 trap**：NULL 解引用 / UAF 读 / 越界读——Clang UB 或读到垃圾，Vitro 给 E30xx 诊断并停 | 无 Clang 对应（Clang UB） | `memory/check_access` 单入口 |
| 2 | **strcpy/strcat E3070 栈缓冲校验**：写入目标容量校验（堆块容量 + 栈缓冲跨度），越界即停带文案 | 无 Clang 对应（Clang UB） | `host/host_string.mbt` |
| 3 | **memset 等写侧受检**：界内软夹紧（超长截断）+ 越界 trap——oracle 无检形态不继承 | 不一致（有意） | `host/host_memory.mbt`（U5 系列） |
| 4 | **1MB 白箱内存 + 释放隔离区**：全部内存可见可解释、UAF 有教学观察窗口、隔离预算可配 | 无 Clang 对应 | `memory` 包 |
| 5 | **步数/调用深度保险丝 + deterministic 模式**：无限循环给诊断不挂起；时钟恒 0 可回放（判分缺省——CLI `run`/`step` 默认 `deterministic=true`）；**旁路已开**（#211 批）：`vitro run --realtime` / serve `config.set {"deterministic":false}`（native 宿主）→ time() 真时间戳、clock() 自会话起微秒（分臂口径见[标准库支持矩阵](../04-标准库与防线/标准库支持矩阵.md)`time`/`clock` 行；wasm 臂无熵源恒 0）；localtime/struct tm 族仍缺挂 #10 | 无 Clang 对应 | vm/gateway config |
| 6 | **扩展关键字（U0#1）**：`fun`/`struct` 字面量等教学扩展在宽松模式可用 | 不一致（有意） | gap 语料域（`keyword_compat`） |
| 7 | **有符号整数加/乘溢出受检 trap**（#102 登记，2026-10-16）：`int` 加/乘溢出 → trap（rc=2）带教学文案，不回绕——有符号溢出在 C 中本就是 UB，受检形态是自洽设计选择。边界对齐：unsigned 加/乘回绕**保留**（C 定义行为）；`long long` 8 字节、`long` 4 字节（LLP64——与 Windows clang 一致） | Clang 回绕（UB 的实现行为——跨平台不一致：Linux 64 位 long 上正常输出） | vm 受检算术 |
| 8 | **VFS 每会话预置两个教学文件**（#95 登记，2026-10-16）：`test.txt`（`hello\nworld\n`）与 `numbers.txt`（`1 2 3 4 5\n`）——`fopen` 即读（未创建也能打开）；同会话内程序可覆盖写（写后读自洽），跨会话不可见；其余文件名正常失败。同名误读风险：程序自建同名文件时读到的是预置内容（首次写前） | 无 Clang 对应 | `gateway/serve_run`+`serve_step` 的 `inject_preset_file`（run 与 step.begin 各注入一次） |
