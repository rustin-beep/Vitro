## 下游接入（MoonBit 宿主）：`moon add` 即用

不 clone 本仓、以 MoonBit 宿主身份把引擎当库接。以下配方为下游视角实测批（2026-10-14，moon 0.1.20261012 / `vitro/engine@0.8.0`）双臂验证通过的形态（#115）：

```bash
moon add vitro/engine
```

主包 `moon.pkg` 三件套——**`.mbt` 文件顶部不能写 `import`**（工具链要求 import 声明在 `moon.pkg`，报错 `[3001] Invalid import declaration here` 即命中此坑）；`is-main` 旧语法已被 `pkgtype` 取代（现役工具链直接 `Lexing error`）；`supported_targets` 不声明会吃警告（依赖链上游声明了而本包未声明）：

```toml
import {
  "vitro/engine/gateway",
}
pkgtype(kind: "executable")
supported_targets = "+wasm-gc +native"
```

代码侧入口（gateway 包导出）：

```moonbit
@gateway.invoke(line)          // NDJSON 单帧进出——全部协议方法的统一入口
@gateway.protocol_version()    // 协议版本
@gateway.engine_version()      // 引擎版本（含构建期 git 短哈希，可做产物自检）
@gateway.reset()               // 会话重置
```

两条边界说明：

- **`.mbtx` 脚本形态 vs 包形态**：`examples/demo.mbtx` 这类脚本可以把 import 直接写在文件顶部；`moon new` 生成的正规包必须写进 `moon.pkg`——两种形态差异此前零提示，是下游反向工程的最大坑点。
- **Windows native 构建（#117 边界）**：`MOON_CC=clang` 是**本仓 workspace 语境**的配方；下游独立项目的 native 目标若走 MSVC 直连，工具链会忽略 `clang` 并回落 MSVC 探测，此时须设 `MOON_CC=clang-cl`——详见下文 Windows 提示。

出口选型（四通道矩阵与宿主策略）见 [出口分档与宿主策略.md](../06-出口与协议/出口分档与宿主策略.md)；协议字段与在架版本的对应关系见 [CLI使用手册.md](CLI使用手册.md) 的「字段 ↔ 最低版本」表（#116）。

## 零分钟上手：MoonBit 现役引擎（`vitro/engine`）

**推荐：统一入口 launcher（#49 批一；2026-10-15 三后端单壳批起缺省 js 臂）**——一个入口三臂任选，缺省 **js 臂**（MoonBit 壳直编 JS、node 直跑，免 wasm 实例化层）；node 缺失或 js 产物缺失自动降级 native exe，降级恒在 stderr 明示 `backend=` 与原因；`--backend js|native|wasm` 显式选边（wasm 臂 = MoonBit 胶水拉 gateway wasm-gc，与浏览器分发同源；node <22 时壳 rc=5 哨兵降级——js-string builtins 的 V8 下界）：

```bash
scripts/bin/vitro run corpus/baseline/hello_world.c                    # sh（Git Bash/Linux/macOS）；Windows cmd 用 scripts\bin\vitro.cmd
scripts/bin/vitro --backend native run corpus/baseline/hello_world.c   # 显式 native 臂（防线基线臂）
```

> 产物在位时零构建直跑。自举顺序：native exe 是兜底臂（缺失时 launcher fail loud rc=127 并给重建命令），js/wasm 产物按需重建——三臂产物重建命令见 [构建指南.md](构建指南.md)。`--backend` 必须紧随 `vitro`（尾置 fail loud rc=4，#70）。三臂同形性由 CI 闸 `scripts/vitro_cli_smoke` 多臂对拍锁定。

**源码构建与测试**（闸门验证 / native 臂产物）：

```bash
# 782 测试用例（facts `moonbit_test_passed` 口径）+ 全部闸门绿（闸清单以 ci.yml 为权威，不锚闸数）
cd moonbit && moon check && moon test

# 端到端跑一个 C 程序（`vitro` 总入口：C 源码 → 编译 → VM 执行）
cd moonbit && MOON_CC=clang moon build --release --target native cmd/vitro
./_build/native/release/build/cmd/vitro/vitro.exe run ../corpus/baseline/hello_world.c
# → Hello（返回码 0）
# js 臂产物（launcher 缺省臂被测物）：cd moonbit && moon build --release --target js cmd/vitro_js
# 更多：vitro compile / step / api（万能单帧，全部协议方法脚本化）——见 [CLI使用手册](CLI使用手册.md)
```

> **Windows 提示**：`moon build --target native` 默认走 MSVC `cl` 链接后端，本仓实测病态慢（moon#2254 自述口径）；**一律设 `MOON_CC=clang`**，全量约 17s（[moonbitlang/moon#2254](https://github.com/moonbitlang/moon/issues/2254)）。**适用边界（#117，2026-10-15 补）**：`MOON_CC=clang` 是**本仓 workspace 语境**的配方（包/target 声明形态匹配）——下游独立项目 native 目标若走 MSVC 直连目标，工具链会忽略 `clang` 并回落 MSVC 探测（警告 `MOON_CC is ignored … not a cl-compatible driver`），此时须设 **`MOON_CC=clang-cl`**（或 cl.exe）才真正生效；下游勿照抄本句后误以为已避开构建悬崖。MoonBit 侧完整构建/闸门/发布流程见 [`moonbit/AGENTS.md`](../../../moonbit/AGENTS.md)。

## 一分钟上手：命令行工具

`vitro` 总入口（MoonBit）可直接编译、运行、单步与脚本化调试 C 代码：

```bash
cd moonbit && MOON_CC=clang moon build --release --target native cmd/vitro
# 产物：moonbit/_build/native/release/build/cmd/vitro/vitro.exe

# 直接运行代码片段（`-` = 源码从 stdin 读）
echo '#include <stdio.h>
int main() { printf("hello, vitro\n"); return 0; }' | ./_build/native/release/build/cmd/vitro/vitro.exe run -

# 编译并查看诊断（中文诊断：错误码 + 位置 + 修复建议）
./_build/native/release/build/cmd/vitro/vitro.exe compile ../corpus/baseline/hello_world.c

# 一次性 step 流
./_build/native/release/build/cmd/vitro/vitro.exe step ../corpus/baseline/hello_world.c
```

> 完整命令与选项（`compile / step / api` 万能单帧与批式多帧）见 [`CLI使用手册.md`](CLI使用手册.md)。

## 五分钟上手：JSON-lines 会话（headless 出口）

长寿命会话进程：**stdin 每行一个 JSON 请求，stdout 每行一个 JSON 响应**（NDJSON）。
供 IDE 后端、判分服务、自动化脚本以任意语言消费，无需 ctypes 或 FFI。

```bash
cd moonbit && MOON_CC=clang moon build --release --target native cmd/serve
./_build/native/release/build/cmd/serve/serve.exe <<'EOF'
{"id":1,"method":"compile","params":{"source":"#include <stdio.h>\nint main(){ printf(\"%d\", 1+2); return 0; }\n"}}
{"id":2,"method":"run"}
{"id":3,"method":"output.delta","params":{"cursor":0,"stream":"stdout"}}
{"id":4,"method":"shutdown"}
EOF
```

响应形如（2026-10-15 实测；替换 Rust oracle 时代旧示例——旧示例缺 compile 响应的 `preprocessor_trace`/`algorithm_matches` 字段、run 响应缺 `output_truncated`、delta 帧缺 `truncated_bytes`，均为协议冻结面追增字段，#98 连坐勘正）：

```json
{"id":1,"ok":true,"result":{"ok":true,"diagnostics":[],"preprocessor_trace":[],"algorithm_matches":[]}}
{"id":2,"ok":true,"result":{"ok":true,"status":"finished","return_value":0,"trap":"","waiting_input":false,"steps_executed":14,"output_truncated":false}}
{"id":3,"ok":true,"result":{"delta":"3","cursor":1,"total":1,"stream":"stdout","truncated_bytes":0}}
{"id":4,"ok":true,"result":{"shutdown":true}}
```

> **在架版本注记（#116，2026-10-16）**：上行示例含 `run` 响应的 `output_truncated` 与 `output.delta` 响应的 `truncated_bytes`——均为仓内 HEAD 新增字段，**在架 mooncakes 最新版（0.8.0）尚不携带**；按在架版写消费代码时这两键不存在。字段 ↔ 最低版本全表见 [CLI使用手册.md](CLI使用手册.md)。

三条关键契约：

- **id 关联**：请求可带 `id`，响应原样回填（异步/乱序对账）；
- **帧同构**：成功帧 `{"ok":true,"result":{…}}`、错误帧 `{"ok":false,"error":{…}}`，解析路径统一；
- **输出分通道**：`stream` 取 `display`（默认，含引擎附注）/ `stdout`（纯程序输出，判分与 Clang Golden 比对用）/ `stderr` / `note`。

> 方法一览（编译 / 运行 / 单步 / seek / 断点 / 内存区域 / 配置）见 [`CLI使用手册.md`](CLI使用手册.md) serve 节；
> StepPayload 的字段语义见 [`docs/spec/STEP_PAYLOAD_SCHEMA_V0_1.md`](../../spec/STEP_PAYLOAD_SCHEMA_V0_1.md)。

## 五分钟上手：wasm-gc 出口

```bash
cd moonbit && moon build --release --target wasm-gc gateway/wasm
node scripts/wasm_gateway/host.js     # 16 断言冒烟（gateway 4 导出面 / trap / 体积上限）
```

`gateway` 库 + `gateway/wasm` 薄壳构成 **wasm-gc 出口**（S7 批五号落地，总计划 F-5；
String 零拷贝直传，NDJSON 帧协议与 serve 同一语义）。**CLI wasm 臂产物为两件**：
`gateway/wasm`（wasm-gc 引擎，浏览器直调同一件）+ `cmd/vitro_wasm`（MoonBit node 胶水壳，`--target js`）——`scripts/bin/vitro --backend wasm` 消费两者；js 臂则是 `cmd/vitro_js` 直编 JS、不经 wasm 实例化（三臂口径见 [构建指南.md](构建指南.md)）。浏览器直调形态见仓库附带
[静态单页 demo](https://rustin-beep.github.io/Vitro/)（`demo/`）。

> 历史注记：原 Rust wasm32 出口（`vitro_native.wasm` ≈3.75MB）已随删区退役，
> `wasm_smoke` 冒烟门禁随之移除；现役 wasm 出口冒烟 = `scripts/wasm_gateway/host.js`。

## 常见问题

### `moon` 命令未找到

安装 MoonBit 工具链（见 [moonbit/AGENTS.md](../../../moonbit/AGENTS.md) 环境节）；版本基线锁定于 `scripts/toolchain_baseline.txt`。

### 直拍防线报 "clang not found"

防线以 Clang 为唯一 Golden 来源，缺失时会**故意 fail fast**（exit 2），而不是静默跳过。安装 LLVM/Clang 并加入 PATH。

### 程序等待输入（`waiting_input`）

`run` 返回 `waiting_input: true` 时，可通过 `-i <file>`（CLI）或 `run.input` / `batch_input`（serve）提供标准输入。

### 想看图形界面

仓库自带单页 demo（`demo/`，[线上版](https://rustin-beep.github.io/Vitro/)）——基于出口协议的教学可视化参考实现；Svelte 5 前端批进行中（#122，0.10.0 批母）。社区前端仍可基于出口协议自行实现；历史 Flutter 前端见标签 `before-frontend-split`。
