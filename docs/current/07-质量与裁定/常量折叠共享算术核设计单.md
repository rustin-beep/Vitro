## 一、现状测绘：三套求值器 × 三套域判定 × 一套执行核

### 1. 一个比「三套求值器」更深一层的结构性事实

M08 报告（B5/C1）把问题定性为「三套求值器并存 + 折叠器与运行期无共享算术核」。本批亲读后把结构再剖一层：

> **「运行期是对的」不是一个求值器的功劳，而是一条三段链**：
> ① typeck `promote_type` 定**类型面**（expr.mbt:24，病 30 修，2026-10-11，口径正确）→
> ② codegen 按域判据选 **opcode 族**（binary.mbt:47-61，signed/unsigned/宽度烘焙进 Add/UAdd/Div/UDiv/DivQ/UDivQ…）→
> ③ VM 按定宽 opcode 做**无类型的位模式运算**（exec_arith.mbt / exec_float.mbt，不含任何域判定）。
>
> `const_eval` 试图在一步里重做这三段（拿 lty/rty/resty 自判值域），却**没有复用 ①的结果、没有 ②的定宽 opcode 约束**，于是判错（u_domain）。所以「共享算术核」要共享的不是一个「求值器」，而是**把 ①的域判定规则与 ③的位模式运算+故障判定合成一个纯函数核**，让折叠器（编译期）与 opcode 执行臂（运行期）两侧都只做薄壳映射。

另一个结构性原因：**AST `Binary` 节点只携带结果类型**（`resolve_binary` 返回 `(ty, Binary(op, l, r, loc, ty))`，ops.mbt:153；比较运算结果恒 `int()`，ops.mbt:91/106）——**操作数公共类型不落 AST**。每个值消费方（codegen、const_eval）各自从 lty/rty 重算公共域，这就是三套域判定并存的土壤。核方案必须显式补上这一步（§二·2）。

### 4. 一套执行核（VM，无类型判定——亲读全文）

**VM 从不做域判定**：符号性/宽度在 codegen 发射时已烘焙进 opcode（Add vs UAdd vs AddQ；Div vs UDiv vs DivQ vs UDivQ；Lt vs ULt vs LtQ vs ULtQ；Shr vs LShr vs ShrQ vs LShrQ…）。VM 各臂只做位模式运算 + 故障拦截。亲读口径表（`exec_arith.mbt` + `exec_float.mbt`，行号为 5233ad65 实况）：

| 运算 | i32 有符号 | u32 | i64（Q 族） | u64（UQ 族） |
|---|---|---|---|---|
| Add/Sub/Mul | **i64 中转+范围检查→教学 trap**（exec_arith.mbt:18-71） | 回绕 | **回绕不 trap**（exec_float.mbt:209-220，头注明示「与 i32 族分口径」） | 同 AddQ |
| Div | 除零 trap E3088 + INT_MIN/-1 trap（exec_arith.mbt:72-86） | 除零 trap | 除零 trap E3088 + LLONG_MIN/-1 trap（exec_float.mbt:221-237） | 除零 trap（UDivQ，exec_float.mbt:275-286） |
| Mod | 同 Div（exec_arith.mbt:97-112） | 同 | 同（exec_float.mbt:238-253） | 除零 trap（无 MIN%-1 面） |
| Neg | INT_MIN trap（exec_arith.mbt:123-133） | 回绕（UNeg） | LLONG_MIN trap（NegQ） | 回绕（UNegQ） |
| 移位 | 移位量 <0 或 ≥32 **trap**（Shl/Shr/LShr，exec_arith.mbt:262-299） | 同 | ≥64 trap（Q 族，exec_arith.mbt:321-358） | 同 |
| 比较 | i32 语义 | u32 重解释（ULt 族） | i64 语义（LtQ 族） | u64（ULtQ 族） |
| 浮→整 | CastD2I/CastF2I **饱和**（`to_int`，exec_float.mbt:91-94/163-166） | — | CastD2Q 饱和（`to_int64`，exec_float.mbt:312-315） | — |
| 整→浮 | CastI2D 有符号 | CastU2D 零符号位（病 31） | CastQ2D / CastUQ2D（#345） | 同 UQ2D |

两个关键补充事实（M08 未写透、设计直接依赖）：

- **VM 的 `And`/`Or` opcode 是不可达占位**：C 的 &&/|| 短路由 codegen 发射结构实现（`binary.mbt:62-92`：左值 Dup + JumpIfZero/JumpIfNotZero 跳末 + Pop + 右值 + 结果规范化 `PushConst 0 + Ne`）；`binary.mbt:378-380` 注释自承「And/Or 已在上方短路结构处理，到不了这里（穷尽 match 的占位臂）」，而 exec_arith.mbt:214-223 的 And/Or 臂仍是非短路双值形态。**A3 折叠器的短路修复应仿 codegen 的两阶段结构（CE_LogiRhs 帧），不是修 VM。**
- **i32 与 Q 族的溢出口径刻意分划**（两文件头注明示「对拍契约」）：i32 Add/Sub/Mul/Neg 是教学 trap，Q 族是回绕。这不是 bug 而是裁定过的教学口径——**核必须继承此分划**（§二·3 语义表），否则 VM 接核会翻掉大量 trap 行为锚。

## 二、共享算术核方案

### 1. 核的定位与落点

新包 **`vitro/engine/arith`**（叶包：不依赖 ast/typeck/vm/opcode——核内自持最小类型面，仅可依赖 `util` 或零依赖）。落点依据（亲查 moon.pkg 依赖图）：typeck 与 vm 的公共既有依赖只有 `ast`/`source`/`util`；核**不 import ast**（类型面用核内枚举），从而避免 ast↔核 的循环风险并使核可独立白盒测试。

连坐义务（AGENTS 纪律 11）：新包须登记 `scripts/moonbit/surface_edges.txt` 边表与 `pkg_deps` 白名单，否则 CI 红；pub 面变更跑 `moon info` 连坐 .mbti。

### 2. 接口面（设计草案——实施批可微调签名，不可改语义分划）

输入 = **规范化位模式值（Int64 容器）+ 核内域描述**；输出 = **值 或 故障**。核不做 AST 解析、不决定 trap/诊断策略——AST→(值,域) 的映射由消费方薄壳完成，故障→(trap 文案/诊断码) 的翻译留在消费方（VM 的教学文案、typeck 的 E3075 族都是消费方资产，不进核）。

```moonbit
// —— 核内最小类型面（与 @ast.Type 解耦）——
/// 整型域：char/uchar 经 integer_promote 后不再出现在核内
pub enum IntDomain { I32; U32; I64; U64 }

/// @ast.Type → 核域 的薄壳映射（typeck 侧提供；核只认 (kind, unsigned) 二元组）
pub enum IntKind { KChar; KInt; KLongLong }   // 教学 C 子集三档宽度

// —— 域判定（D1 的值域面孪生 + D4 的收编点）——
/// C11 §6.3.1.1 整型提升：char 系 → I32（unsigned 位消失）；int/LL 不动
pub fn integer_promote(kind : IntKind, is_unsigned : Bool) -> IntDomain
/// C11 §6.3.1.8 usual arithmetic conversions（promote 后两侧的公共域）
pub fn common_domain(l : IntDomain, r : IntDomain) -> IntDomain

// —— 故障（核不决定策略）——
pub enum ArithFault {
  DivByZero                                   // VM→E3088 文案；折叠器→E3075 族诊断
  DivOverflow                                 // INT_MIN/-1（i32）/ LLONG_MIN/-1（i64）
  ShiftOutOfRange(Int64)                      // 移位量越界（按左操作数提升后域宽）
  AddOverflow | SubOverflow | MulOverflow | NegOverflow  // 仅 i32 有符号域产（Q 族回绕不产——继承现状分划）
}

// —— 求值 ——
pub enum IntBinOp { OpAdd; OpSub; OpMul; OpDiv; OpMod;        // 算术
                    OpBitAnd; OpBitOr; OpBitXor; OpShl; OpShr; // 位/移位（Shr 含算术/逻辑二义？否——见下注）
                    OpLt; OpLe; OpGt; OpGe; OpEq; OpNe }       // 比较（Eq/Ne 也吃 dom——修 A2）
/// 单点覆盖 16 算子 × 4 域：值语义 + 溢出/越界故障，一表驱动
pub fn eval_int_binary(op : IntBinOp, l : Int64, r : Int64, dom : IntDomain) -> Result[Int64, ArithFault]

pub enum IntUnOp { OpNeg; OpBitNot }
pub fn eval_int_unary(op : IntUnOp, v : Int64, dom : IntDomain) -> Result[Int64, ArithFault]

// —— 归一与转换 ——
/// 值按域宽/符号截断-扩展（ce_normalize 的核版；fold 出口、Cast 整→整共用）
pub fn normalize(v : Int64, dom : IntDomain) -> Int64
/// 浮→整饱和转换，按目标域 clamp（修 A5：CastD2I/CastD2Q/折叠三面同源）
pub fn f2i_saturate(f : Double, dom : IntDomain) -> Int64
```

三条设计要点：

1. **Shr 的域取左操作数提升后类型**（C11 §6.5.7：结果符号性随左操作数）——与 Div/比较的公共类型域不同源。这不是新规则，是 D2 现状的镜像（`binary.mbt:365-377`：`result_is_long_long` 走 LShrQ 当且仅当 **ty**（=提升后左型）is_unsigned）。核接口上由调用方给 Shr 传**左操作数提升后域**、给其余算子传**公共域**——语义分划写在核 doc 注释与语义表（§二·3），不藏在调用方。
2. **Eq/Ne 显式吃 dom**：`-1 == 4294967295u` 的修复 = 两侧先 normalize 到公共域 U32 再比较位模式（`0xFFFFFFFF == 0xFFFFFFFF`→1）。这是 A2 的核内解。
3. **`CI(Int64, Bool)` 的源无符号位退役**：const_eval 现用第二分量记「源是否无符号」供 fp 转换取解释（#345）。接核后 CVal 改携带**核域**（`CI(Int64, IntDomain?)`——浮点侧 None），整→浮转换的符号解释从域导出（U32/U64→零符号位），`to_f64` 的双解释逻辑随之入核或留薄壳。

### 3. 域语义总表（核的一表驱动真源——对照 C 标准 + clang 实测 + 现状两侧）

整型算子 × 域的**目标口径**（= 现状 VM 行为的镜像，保证 VM 接核零行为变化；折叠器接核后与运行期强制同值，UB 域按「故障→拒折+诊断」处理）：

| 算子 | 域 | 值语义 | 溢出/越界行为 | clang 静态折叠口径（速查表/M08 对拍） | 折叠器目标行为 |
|---|---|---|---|---|---|
| Add/Sub/Mul | I32 | i64 中转后截 32 位 | **故障 AddOverflow 等**（教学 trap 口径） | 折回绕值 + -Winteger-overflow 警告 | 同值 + **W 级警告**（S2 修复；拍板项①） |
| | U32/I64/U64 | 位模式回绕 | 无故障（回绕） | 同 | 同值（无警告——clang 同） |
| Div/Mod | I32 | i32 商/余 | DivByZero、DivOverflow（INT_MIN/-1） | 除零=error（非常量）；MIN/-1 折回绕零诊断 | 故障→**拒折+E3075 族诊断**（A4+A6） |
| | U32/UDiv 域 | 无符号商/余 | DivByZero | 同 | 同 |
| | I64 | i64 商/余 | DivByZero、DivOverflow（LLONG_MIN/-1） | 同 | 同 |
| Shl/Shr | 全域 | 左值按左操作数提升后域移位 | ShiftOutOfRange（I32 域 0~31 / I64 域 0~63，负数同拒） | 越界=UB（clang warning，gcc error） | 故障→拒折+诊断（A6；右移域随左操作数） |

### 4. 两侧收敛路径

**折叠器侧（E1）**：const_eval 保留显式栈机骨架（病 40 教训——深链防溢出），只换求值臂：

- `CE_AppB` 整型臂：删 u_domain（L100-104）→ `dom = common_domain(integer_promote(lty), integer_promote(rty))` → 两侧 `normalize` → `eval_int_binary(op, x, y, dom)`；比较族含 Eq/Ne（修 A2）；移位族 dom 换左操作数提升后域（修 A6 移位面）；`Ok` 推值、`Err(fault)` 返回携带故障的 None（喂 A4 诊断——E3075 族新文案对齐 trap 家族措辞）。
- `CE_AppU` 整臂：`integer_promote(oty)` → `eval_int_unary`（Neg 的 NegOverflow→拒折+警告）。
- `CE_Cast` 整臂（L258-263）与 `fold_static_init` 的 CF→LongLiteral（L402）：改 `f2i_saturate(f, 目标域)`（修 A5 两处）。
- `And/Or`（L202-204 + L280-284）：两阶段短路——压 `CE_E(l)` + 新帧 `CE_LogiRhs(op, r)`；弹 CE_LogiRhs 时左值定局（Or 左真/And 左假）则**丢弃右帧**直接推 0/1，否则补压 `CE_E(r)+CE_AppB`（M08 A3 处方原样，本批核其与 codegen 结构同构成立）。
- A4：const_eval 失败且树中无 Identifier/Call（纯常量形态求值失败）→ 必是除零/移位越界/溢出 → 按 fault 报诊断；diagnose_static_init 补 Index/Member 裸用臂（#264 数组名豁免面不扩大）。

**VM 侧（批 3，可选后置）**：exec_arith/exec_float 的 21 个算术臂逐臂改调核——每臂是纯替换：opcode→(IntBinOp, IntDomain) 一处映射表（`Div=>(OpDiv, I32)`、`UDivQ=>(OpDiv, U64)`…），trap 文案翻译留在 VM。**验收等价判据 = vm 既有锚 + protocol golden 全绿（零行为变化）**，因为核语义表就是 VM 现状的镜像（§二·3 表的「目标口径」列刻意取现状 VM 值）。

**类型面侧（批 2）**：ops.mbt D4 三处改调 `integer_promote`（A7）；`resolve_binary_key_shapes` 的 Shl 锚补 `assert_false(ty.is_unsigned())`（M08 点名的锚盲区）。

**codegen 侧（不重写，加对拍锚）**：D2 目前正确，但与 D1 双轨是未来漂移点。批 5 只加「判据对拍 wbtest」：同表达式族断言 codegen 实际发射的 opcode 族 == 按 `common_domain` 推导的期望族（例如 `-1LL/2u` 期望 DivQ）。D2 判据重写为从核导出**不进五批**——挂未来项，待漂移实证再动（重写 codegen 判据的回归面远大于收益）。

## 四、备选方案对照：轻量「折叠前对拍」路线

**方案 L**：不抽核。折叠器求值后，把同一常量表达式走 codegen+VM 再算一遍，两值不一致→拒折（+登记）。即「用运行期当折叠器的 oracle」。

| 维度 | 方案 N（共享核，主推） | 方案 L（对拍拒折） |
|---|---|---|
| **成本** | 批 0 新包+批 1/2 改造（一次性 ~中）；此后算术语义只写一遍 | 前端看似低，实际要造「任意常量表达式→字节码」的编译通道（现 codegen 只在函数体语境）=**第四个求值路径**；每张翻译单元的每个静态初始化器都跑一遍 VM=编译期开销 |
| **收益** | A1-A8+S1/S2 全修；E1/E2/E3 有收敛落点；语义表单源；clang 对齐 | 只能**抓**分叉（拒折不再静默错值），**不能修**（拒折后走置 0 路径，配合未修的 A4 反而是错值放大器）；E2/E3 完全不受益；A4 诊断面零改善 |
| **风险** | 批 1 golden 翻面（已预估，个位数）；核表抄错一格（批 3 有镜像锚防线） | UB 域两侧口径本就分划（折叠回绕 vs VM trap，§一·4）→ 对拍在溢出面**恒不一致**→ 要么 UB 域全拒折（`LLONG_MAX+1` 这类 clang 也折的合法形态被误伤）要么维护豁免表——**豁免表本身就是第二套语义表**，问题没消失只是换了形态 |

**裁定：方案 L 不成立为主方案**——它把「语义单源」转化为「双实现+豁免表」，而豁免表维护正是本仓「无同形面对账」造因（总报告造因②）的复刻。但 L 的核心动作（同表达式两上下文对拍）作为**长期防线**价值真实：批 1 验收锚「折叠↔运行期一致性 wbtest」就是 L 的锚形态（抽样表达式族、双上下文断言同值，漂移即红）——**收编为方案 N 的验收闸，不独立成方案**。
