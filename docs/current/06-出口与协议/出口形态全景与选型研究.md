# 出口形态全景与选型研究（2026-10-17）

> **性质**：出口**形态全景** + 选型决策依据。把 Vitro 引擎对外的一切出口——制品形态、交付形态、宿主形态——放在一张图里比较，回答"某个消费者该走哪条路"。
> **与《[出口分档与宿主策略](出口分档与宿主策略.md)》的分工**：上游文档定**承诺面口径**（承诺 / 可用不承诺 / 不提供 + 触发线）；本文定**形态全景与选型**（每条路长什么样、什么条件下选它、实测代价是多少）。本文不推翻上游任何结论。
> **上游裁定**：服从 [MoonBit迁移总计划](../01-定位与路线/MoonBit迁移总计划.md) F-5（wasm-gc 单出口、多宿主）。
> **证据纪律**：数字分两类——**实测**（本文现场跑出，标方法）/ **既有记录**（标出处与 as_of）。未证实的推断一律写明，不得当结论引用。
> **适用边界**：`vitro/engine` 对外交付面。引擎内部结构、教学资产不在本文范围。
> **最后核对**：2026-10-17

## 1. 先把"出口"分三层（此前混淆的根源）

同一句"出口"在讨论中指过三种东西，混着说就会各说各话：

| 层 | 问的问题 | 本仓取值 |
|---|---|---|
| **制品形态** | 引擎编译成什么？ | wasm-gc（承诺）／ js（可用不承诺）／ native（可用不承诺） |
| **交付形态** | 消费者拿到的是什么？ | 浏览器站点（demo）／ Electron 桌面应用／ npm 包（`@vitro/protocol`）／ mooncakes 包 |
| **宿主形态** | 引擎在谁内部跑？ | WebView 内嵌／ Electron 内 Chromium／ 独立 wasm 运行时（Wasmtime）／ 协议 sidecar 子进程／ 源码级 in-process |

**选型的正确顺序**：先定宿主形态（由消费者的技术栈与约束决定）→ 再定制品形态 → 最后才是交付形态的包装。此前把"本仓 demo 选了 Electron"当成"下游也必须用 Electron"，就是跳过了第一步。

## 3. 逐条说明

### 3.1 浏览器前端（demo 站点）——现役第一交付形态

`demo/`（547 .ts + 567 .js），wasm-gc 制品 + TS 呈现层 + CodeMirror 6 编辑器。
**体积实测（2026-10-14，node zlib）**：wasm 916.8KB raw / 335.2KB gzip / 259.4KB brotli；页面 JS 140.5 + 90.4KB；CSS 60.4KB；**整包 1225.4KB raw / 423.9KB gzip / 330.8KB brotli**。
**约束**：js-string builtins 版本矩阵（§5）；Safari 26.2 的 `instantiateStreaming` 禁令（上游 §3.5，必须走两步装载）。

### 3.2 Electron 桌面应用——本仓桌面壳的裁定

**版本实测（2026-10-15，npm registry）**：electron 44.7.2 = Chromium 152；electron-builder 26.15.3。
**体积实测（GitHub release asset）**：win32-x64 **150.6MB** / darwin-arm64 124.4MB / linux-x64 117.3MB。
**为什么是它（2026-10-16 裁定）**：引擎 wasm-gc 硬依赖 V8 专有 `js-string builtins`；Electron 自带 Chromium ⇒ 三平台一致。Tauri 走系统 WebView 会把"引擎版本分布"这个唯一卡点重新引进壳。
**已知坑**：Vite 产物不能用 `loadFile(file://)`（crossorigin + origin=null 被 CORS 拦，实测白屏），须自定义协议 + `standard/secure/supportFetchAPI`。

> **重要**：这是**本仓 demo 的第一交付形态**，不是下游消费者的强制约束。下游完全可以不碰 web 栈（走 #4 或 #5）。

### 3.3 系统 WebView 壳——已否，但 Windows 单点可用

Tauri 2 / Wails / Proton / 裸 WebView2。
**否决理由**：macOS WKWebView 与 Linux WebKitGTK 的 js-string builtins 支持滞后（上游 §3.5；WebKit bug 308136 / 322238）。
**例外**：Windows WebView2 = Chromium，**Windows 单点成立**（上游 §4 已倾向给 SharpTutor）。
⇒ 教训：**任何只验证 Windows 就推广三平台的结论都不可靠。**

### 3.4 wasm-gc + 独立 wasm 运行时（Wasmtime）——2026-10-17 实测跑通

面向"**原生渲染、拒绝 web 栈**"的消费者。

**决定性开关**：`moonbit/gateway/wasm/moon.pkg` 的 `use-js-builtin-string`。

| 开关 | imports | 体积 | Wasmtime |
|---|---|---|---|
| `true`（现役） | **4117**（`wasm:js-string`×6 + 4111 个 imported string constants） | 916.8KB | **实例化失败** |
| `false`（零导入风味） | **0** | **1016.2KB** | **实例化成功** |

⇒ 上游 §3.5「独立 wasm runtime 全部 N/A」这一判词**仅对现役制品成立**；换零导入风味即不成立。这是本次研究对上游的边界补充。

**实测跑通（Rust 宿主，wasmtime crate 48.0.6）**：
```
engine_version()   = "0.8.0"
protocol_version() = "v0.1"
invoke({"method":"ping"}) → {"id":null,"ok":true,"result":{"pong":true}}
error_catalog            → 23726 字符，中文正常
```
**两个集成硬约束**：① wasm-gc 是**名义类型**，自建同构 array 会被拒（`VMSharedTypeIndex(1)` vs `(4)`），须借用模块自身 `ArrayType`；② MoonBit String 是 **`array<i16>`（UTF-16）**，必须按 UTF-16 编解码，按 UTF-8 解则中文乱码。

**宿主语言是硬约束**：Rust / C 可用（C API 有 171 个 GC 引用操作函数，含 `wasmtime_anyref_as_array` / `wasmtime_arrayref_get`）。**Python、.NET 当前读不了 GC 引用**（Python 绑定 `_from_raw` 未映射 valkind 7；.NET 绑定编译期拒）。Go 侧 wazero 不支持 wasm-gc，wasmtime-go **未查**。

### 3.5 协议 sidecar——现役可用、零改造

`serve.exe`（native 独立 exe，**不依赖 node**）长驻，stdin/stdout 收发 NDJSON。
**实测**：`ping` / `session.create` / `compile` / `shutdown` 四帧全通；`compile` 参数字段是 **`source` 不是 `content`**（误用 `content` 会得 E0 假故障）。
**适用**：宿主语言不受限、不要 in-process 的场景。**代价是跨进程**；且若用 native 臂即放弃 wasm 的性能优势。

### 3.6 mooncakes 源码级集成

`moon add` 引擎进 MoonBit 宿主，引擎 **in-process native**，js-string 版本矩阵对引擎不再成立。代价：UI 生态最年轻；#41 记录 native 比 wasm 慢（倍率见 §4）。

### 3.7 生成宿主 SDK（gen_bindings）

**未启动**（#118）。当前 TS 侧先行形态是 `@vitro/protocol` npm 包（待投放）。

### 3.8 C ABI——不提供

上游 §2 三条硬理由：① C 后端正被新 native 后端替换，存活期无官方承诺；② 旧 capi 45 导出中 28 个无消费者；③ Wasmtime .NET 绑定编译期即拒。
**触发线**：出现真实进程内原生消费者（非 .NET 非 web、协议延迟实测不可接受、需深度内存集成）⇒ 先做 native C ABI 探针。
补充实测（2026-10-16）：Windows 上 `MOONBIT_NEW_NATIVE=1` **不生效**（仍编译 .c，静默回落 C 后端）。

### 3.9 移动端

已评估：WebView 壳类继承 §5 版本矩阵且不如 PWA；小程序类（WXWebAssembly）非真复用且无 wasm-gc/js-string。**桌面 Electron 结论不可平移**（App Store 禁第三方引擎）。

## 4. 性能：实测与既有记录的分歧

| 对比 | 结果 | 口径与来源 |
|---|---|---|
| wasm-gc+Wasmtime vs native sidecar（run 单次） | **132.57ms vs 150.67ms（+12%）** | 本文实测：compile 一次后只计 run；负载 300×300 循环，**1 626 324 步**，返回 90000；各 20 次；**计时在进程内部**（只 spawn 一次，规避会话税） |
| native vs wasm（nested） | **430.9ms vs 131.9ms（3.3×）** | #41 既有记录。**本文未能复现该倍率** |
| 三臂构建（增量） | js 1.0s / wasm-gc 3.5s / native(clang) **27.9s** | 本文实测（MSVC 约 7min，见 AGENTS 纪律 11） |
| 三臂运行 | — | **会话内采集，经 `perf_baseline` 判词为不可引用**（启动定标中位 216.8ms，CreateProcess 仅 8.4ms），**不作结论** |

**3.3× 未复现的可能原因（均未证实，禁止当结论）**：① 本文用零 js-string 风味，字符串走 wasm GC array 而非 JS 原生 builtin；② Wasmtime 用 Cranelift，#41 是 V8 TurboFan + 带 js-string；③ 负载不同。**在拿到严谨对照前，不得以"3.3×"作为立项收益依据。**

## 5. 贯穿性判据：js-string builtins

**卡点只有一个，不是 wasm-gc**。引擎制品用 `builtins:['js-string']` + `importedStringConstants`，准确表述是"**绑 JS 宿主**"，不是"绑 V8"（Firefox SpiderMonkey、Safari JSC 均已进名单）。

| 能力 | Chrome | Firefox | Safari |
|---|---|---|---|
| wasm-gc | 119+ | 120+ | 18.2+ |
| js-string builtins | 130+ | 134+ | **26.2+**（且 `instantiateStreaming` 在该版本失效） |

⇒ **凡不含 JS 宿主的环境（Wasmtime / Wasmer / wasmi / wazero），现役制品一律 N/A**；出路是零导入风味（§3.4）。

## 6. 选型决策树

```
消费者是什么？
├─ 浏览器 / web 应用           → #1（现役形态）
├─ 桌面应用
│   ├─ 能接受 Chromium 体积      → #2 Electron（本仓裁定）
│   ├─ 只要 Windows             → #3 WebView2 裸嵌（单点成立）
│   └─ 要原生渲染 / 拒绝 web 栈   → #4 wasm-gc + Wasmtime（宿主须 Rust/C）
├─ 任意语言、不苛求 in-process   → #5 协议 sidecar（零改造）
├─ MoonBit 宿主                 → #6 源码级集成
└─ 移动端                       → PWA（#9）
```

**判据速查**：
- 性能优先 + 能控宿主语言 → #4
- 接入成本优先 → #5
- 三平台一致性优先 → #2
- 只要 Windows → #3

## 7. 待办与未证实清单

1. **性能对拍未收敛**：① Wasmtime 优化档调优；② 带 js-string 风味在 V8（node）侧对照，定位 3.3× 来源；③ 两侧同 JSON 处理的严格对拍。
2. **#4 的宿主语言覆盖未验证**：Python / .NET 绑定读不了 GC 引用；Go 侧未查。
3. **双风味发布形态未设计**：零导入风味与现役 JS 风味契约不同，须**并存不能替换**。
4. **#2 未实施**：两个未实测风险点（module Worker 在自定义协议下、`showDirectoryPicker` 工作区模式）。
5. **#7 未启动**（#118）。

## 8. 复现指引

```bash
# 零导入风味制品（改 moon.pkg 的 use-js-builtin-string 为 false）
cd moonbit && moon build --release --target wasm-gc gateway/wasm

# Rust 宿主（wasmtime crate 需 ≤48，除非 rustc ≥1.96）
cd tmp/wasmtime_host && cargo build --release
./target/release/wasmtime_host.exe <制品路径>      # 功能探查
./target/release/bench.exe         <制品路径> 20   # 性能计时

# 协议 sidecar 对照
python tmp/bench_native.py 20
```

> 宿主工程与制品快照目前位于 `tmp/`（非入库面）。若 #4 正式立项，需将宿主工程移入仓内并纳入 CI。
