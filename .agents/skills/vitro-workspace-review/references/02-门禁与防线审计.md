## 2 · 审「新加的闸」——三层，缺一层就不算验过

1. **会红且双向**：篡改**声明侧**（文档数字 ±1）与**真值制品侧**各注入一次 → 期望非零退出，还原复绿。
2. **它声称堵住的盲区真堵住了吗**：把原缺陷场景**原样复现**，看闸是否红。
   - 反例：某闸自称"堵住「文档与真值一起错」的机判盲区"，注入的正是上一轮的现场值 → **PASS**。根因：它的"真值"读自缓存制品 ⇒ **只是复述，不是对账**。
   - 处方：凡闸的真值来自缓存制品，闸内必须**强制新鲜度**（自己跑采集，或要求 `provenance=run` 且 `as_of` 落在本轮）。
   - 另注：制品若被 `.gitignore` 忽略 ⇒ 干净 clone 下不存在，前置步骤要写进文档。
3. **接线**：`grep -c "<脚本名>" .github/workflows/ci.yml`。**0 = 本地工具，不是闸**。
   - 此时文档里"经 N 闸机判"的措辞要么改口，要么补 CI 步骤**并同步"N 闸"这类计数**（否则数字漂）。
4. 附带核**声明行内部一致性**：头条数字改了、带分解式的括号没改时，闸只看头条仍绿 ⇒ 建议加断言 `分解和 == 头条`。

**判闸红不红的前置两问**：① 是不是本地工具？② 是不是自愈型（干净态起跑一次定论）？

## 3 · 审「缓存型 / 环境依赖型防线」

任何"编译并运行被测程序"的防线，**第一件事查被测程序的 cwd 与它读写哪些文件**：

1. `grep -n "exec.Command" -A3 <脚本>` 看有没有 `cmd.Dir` / `cmd.Env`。**只隔离 exe 输出目录 ≠ 隔离程序 cwd。**
2. **两态对比实验（必做）**：① 现状（游离文件在 + 缓存热）；② 干净起点（移走游离文件）+ **清空缓存**。同一份源码跑同一批用例 ≥2 轮。
   - 判据：**同源同编译器不同结论 = 判据不可信**。
3. **缓存 key 里没有的东西最危险**：key 通常 =（源码 + 工具链版本 + 参数），**不含工作区状态** ⇒ 本地永远回放同一答案，把竞态冻结成"KNOWN"。
   - 手法：**用 Python 复刻 key 生成式，就能把缓存条目反查回用例名**。
4. **白名单条目的"理由"要当待验断言**：清空 known 打印真实差异、与登记 digest 对比，判它是**不变式**还是**竞态快照**。
5. **同族防线的强度不等**：用静默 exe 顶替被测二进制（**记得还原并 `md5sum` 对账**），看各防线是否都能红。
6. **文档化的用法也要试一遍**：某些参数组合可能因静态白名单校验而**恒红**。

## 4 · 审人写的分析型 / 判定型脚本 —— 六问清单

1. **默认参数匹配用途吗？** 把默认参数原样跑一遍，看输出结论是否与用途一致。
   - 反例：某脚本的窗口是 `const`（非参数），真实仓下它自称要量的那一段**整段为空** ⇒ 结论与用途相反，判**不可用**——别只看它"跑得通、能出数"。
2. **同一份证据是同一套参数产出的吗？** 参数写死在代码里 ⇒ 两份输出可能互相矛盾且**不可复现、不可对账**。
3. **能否会红 + 灵敏度多少？** 造最小 fixture 验证正检；再造**低于阈值**的块验证**漏检**——漏检要明写成结论。
4. **静默失败面**：不存在的根 / 空目录 / 读不到的文件，是 fail loud 还是打印"0 条"？
   - 反例：`os.Open` 失败静默跳文件、`sc.Err()` 不查、**root 不存在也照样退出 0 并打印"0 条"** ⇒ 与"真无重复"不可区分 ⇒ 违反"fail loud"纪律。
5. **归一化口径的假阳 / 假阴**：只跳整行注释（行尾注释不剥）；剥掉空行 / 注释后拼接会**跨注释块**；不区分生产码与测试文件（重复率被测试文件主导）；重叠窗口不合并（Top-N 易被同一区域位移变体占满）。
6. **文档 / 字段与实现是否一致**：头注声称的机制 vs 实际机制；**死字段**。写进报告时给**相对路径**留证。

## 5 · 给"白名单豁免"补区间机判（模板可直接搬）

`digest` 类豁免（issues 拼接后的哈希前几位）只钉**差异的文本形状**，不表达差异**落在哪一段内存**：差异搬家而计数与首差地址恰好不变时 digest 不动。处方 = 让白名单条目**显式认领区间**，再由消费方机判实际落点：

1. **先标定，不要拍脑袋定阈值**：双侧 dump 内存各产一份，对拍出全部差异地址 + 两侧在候选区间外的**最高非零地址**（存活数据上界）。
2. 阈值取"**实测值的上限**"而非"实测值"（留出倍数余量），并写清**方向是 fail loud**：真越界会红（逼人看一眼），而活数据区差异必红。
3. 常量**单源**指向内存布局定义，不要另造布局表。
4. **两道断言，缺一不可**：① 条目**未声明**区间字段 ⇒ 红；② 声明了但实际落点越窗 ⇒ 红。命中时把实际落点打进日志——**归因证据入档，人写的 reason 文本不作依据**。
5. **双向牙测试**：删字段 → 期望"未声明"红；临时收窄阈值 → 期望"越窗"红；两次都还原复绿。再跑**全量**确认零回归。
6. 别为"声明了但用例没有该通道差异"加断言——digest 命中时该组合基本不可达，加了就是死代码。

## 6 · 数字审计：先反证口径，别改数字

- 见红先反证是不是**假阳性**：md 通道 = 「Context 正则命中行 × 行内 `\d{2,6}` 落区间」，**不懂"是否在陈述现值"** ⇒ **禁机械替换，改口径或改句子**。
- **数字差异先对齐口径**再看是不是错（同一命令的不同口径可能都对）。
- **四个结构性盲区**（只比「文档 ↔ facts」不看真值 / 不判 `unavailable` / Frozen 桶优先 / 豁免白名单吞 error）详见 [`03-缺陷形态清单.md`](03-缺陷形态清单.md) D7。
- 验证某条盲区时，写同包探针直接调内部函数（行分类 / 数字跨度 / 真值命中），**用后即删**。
- 测豁免白名单要**双向**：正条目 → 豁免生效（扫描数减少）；坏条目 → 看它靠什么红。

## 7 · 归一化 / 清扫函数要有"同包探针"直调

判定型工具里的归一化最容易**吃掉合法输出**。

手法：写同包探针（`scripts/<tool>/zz_probe_*_test.go`，跑完即删）**直调该函数**，构造"两侧差异行恰好以被剥前缀开头"的输入，看归一后是否判定为相同。

## 8 · 覆盖度口径对齐（写报告前必做）

- **数字三分法**：报告里每个数字标注是 `CURRENT`（须等真值）还是 `AS-OF`（时点快照）。文件名命中 `scripts/facts/audit.go` 的 `reHistFile` 词表（现行版：`裁定|决议|评估报告|工作记录|维护方案|追踪|审计计划|回执|登记|埋雷|事故|整备|审阅报告|执行记录|复审|CHANGELOG|ARCHIVE`）即**整个文件落 AS-OF 冻结桶**，裸数字不参与漂移判定。
  - ⚠️ 反面坑：**新写「现值」文档别用这些词命名**——会意外获得整文件冻结豁免，让真值行失去机判。判文档落哪个桶以 `audit.go` 现行词表为准，勿凭记忆。
- **别机械替换**"绑实测结果"的行与"带分解式"的行。
- **"闸红不红"务必先排除**：是不是本地工具（D1）、是不是自愈（D2）、工作区是否有第三方的并发改动（用 `git show HEAD:` 判别）。
