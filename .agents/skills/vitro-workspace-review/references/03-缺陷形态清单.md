# 缺陷形态清单

> **开审前扫一遍。** 本表按"形态"聚类，每一条都在本仓真发生过。
>
> 用法：拿到一批代码，按本表逐类过一遍（每类给"判据 / 查法 / 实例"），比从头读一遍命中率高得多。
> **新形态追加到本表**（规则见 [`05-演化机制.md`](05-演化机制.md)）。
>
> **实例写法四条**（2026-10-02 立，防腐化）：
> 1. **禁写一次性测量值**：测试数（`34/34 全绿`）、`PASS n / FAIL m`、批次号、文件数、条数——它们随代码演进而过期，而本表只增不改，过期的数字**没有任何机制修正**。
> 2. **允许写"形状"而非"真值"**：对比关系（`70 任务 → 28 任务`）、临界样本（`20 × 0.2 = 4.0`）、触发条件属于判据本身，可留。
> 3. **日期只保留"形态最早可考"的场合**，且写成 `（Y-M 立）` 而非 `（Y-M-D 实测 34/34 全绿）`——**要的是"真发生过"，不是"当时多少"**。
> 4. **实例优先给"可复现判据"**（一条命令 / 一段注入写法 / 一个文件:行），其次才是"当时观察到什么"。复现不了的实例，只留一句结论并注明来源。

## A · 锚的问题（测试写了但没有牙）

> **按"改坏为什么不红"归类**；各触发面括号内为**原条目号**（历史引用可据此追溯）。
> **共同查法**：对每个实现点做**突变注入**（改坏它）+ **对照注入**（同时改坏 1–2 个已知有锚的点）——只有前者全绿而后者红，才叫"**这一点**无锚"；否则只能说"这套测试整体没牙"。

### A1 · 锚对"错的实现"零判别力

锚能跑、也断言了，但**样本或参数挑得让错误实现照样绿**。六种触发面：

- **a. 样本自身对称**（原 A2）：`encode` + `decode` 往返断言通过，但两者共用同一约定 ⇒ 约定本身错了也测不出。对"顺序 / 下标 / 默认值"这类共用约定要**单独加锚**。实例：符号表插入序的序突变多处全绿（现序正确，但往返锚天然测不出序）。
- **b. 判别样本对两个候选语义输出相同**（原 A5）：`atan2(1.0, 1.0)` 对称 ⇒ 对弹参序零判别力（`pow(2, 10)` 才有）；`fmod` 样本全是正 x ⇒ 分不出截断与最近取余。查法：对每个样本自问"它能反证哪个候选"。
- **c. 算术判据的样本全落在分界点之外**（原 A10）：`ceil` / `round` / 阈值比较类**临界判据**，把判据写错一格（`<` ↔ `<=`、half-up ↔ half-even）时全绿。查法：找出"**恰落在分界点上**"的输入（`ceil` ⇒ 乘积 / 商恰为整数；`round` ⇒ 恰 `.5` 平局；阈值 ⇒ 恰等于阈值），数锚样本里有没有。实例：`FrameWindow::trim` 的 `discard = ceil(len × ratio)`，锚样本的 `len × ratio` 全是小数 ⇒ 注入 `<=`（= floor+1 语义）后全绿；补 `with_limits(19, 0.2)` 推 20 帧（20×0.2 = **4.0** 整数积）的锚后，同一注入立即红。
- **d. 分派的分支维度未覆盖**（原 A11）：按类型 / 枚举分派的判据（`match kind() { Char => 1, Double|LongLong => 8, _ => 4 }`、按 Tag 选通道、按 Op 选文案），样本只落默认 / 兜底分支——或只落在"**取值恰好等于默认值**"的分支 ⇒ 把分派整体退化成写死常量时全绿。查法：**逐分支列出取值**，要求每个非默认分支至少一个样本；对"默认值恰好等于正确值"的分支尤其要单独做"写死默认"注入。实例：`find_variable_name_at_addr` 的元素宽度按**元素类型**分派（char 1 / double·long long 8 / 其余 4），锚只用 `int[4]`（默认分支，取值与默认值同为 4）⇒ 写死为 4 后该包全绿，而 `double[N]` 的 `&arr[k]` 全部解析不出名字、`char[N]` 的数组外地址被误归属。
- **e. 锚用的参数规模把分支挡在门外**（原 A12）：带"上限 / 阈值参数"的分支（`if want_start > start_step`、`discard > len`、`size > budget`），锚一律拿**协议默认大值**构造 ⇒ 触发它所需的参数规模远大于锚样本，该分支**既走不到、也没有断言**。查法：把该分支整体 **no-op 化**后跑该包全部测试，`failed == 0` 即命中；再问"用**最小可配参数**能不能造出可达输入"——能就补锚，造不出才按 A5 降级为不可达。实例：`finish_replay` 的 discard 钳位需 `target ≥ window_size`（协议默认 2 000），锚族 target 全 < 100 ⇒ 写死后该包与其下游包全绿；而这段代码承载 3 次历史事故修复。
- **f. 锚只断言部分样本 / 部分下标**（原 A4）：一批同类对象（`decoded[0..n]`、多通道）里锚只覆盖其中一个。查法：数同族对象个数与锚里的下标集合。实例：某解码器 6 个通道里 5 个用 `.map()` 重建、独 1 处共享引用，而锚只断言 `decoded[2]`。
- **g. 审阅处方本身没过边界样本**（2026-10-02 补）：审阅给出的**修复处方**（替代实现方案）只拿单一顺路样本验证过 ⇒ 处方在边界上翻车，照方抓药会引入新分叉。与 a–f 是镜像关系：那些是"实现没被锚反证"，这条是"处方没被样本反证"。查法：处方给的替代实现，要拿**既有锚的全部样本**（尤其边界值——早退分支遮蔽的、数值边界的）跑一遍，而不是只验一个顺路样本。实例：审阅处方"confidence 改裸 `to_string()`"，验证样本 2/3 恰好落在被删函数的早退分支之外 ⇒ 处方看似成立；边界 1.0 上 `Double::to_string` 输出 `1` 而 oracle 恒 `1.0`——照方实施即引入新分叉（实测否决，改走 `double_to_json_text` 单源）。
- **h. 照搬批只搬了 oracle 一部分单测**（2026-10-03 新增，与 d 同族）：oracle 的单测常按"每个分支一个 `#[test]`"组织，照搬侧若只挑了其中几个形态写成锚（哪怕写成端到端全链路锚），**未搬的分支既走不到也没有断言**——而"锚了很多条"的观感正好掩盖这一点。查法：列出 oracle 测试文件的 `#[test]` 函数名集合，与目标侧锚**逐分支**（不是逐条）对齐；对每个"无对应锚"的分支做**突变禁用**（判据改恒假 / 返回值退化成兜底态），全绿即命中。实例：某五态分类器只锚了其中两态（其余分支的样本恰好也落在被锚的那两态上），把第三个分支的判据改成 `> 999999`、第四个分支的返回值改写成兜底态后，该包测试仍全绿；oracle 侧恰有对应的三个单测未被搬。处方 = 按 oracle 单测逐分支补齐，或把聚合分派改成表驱动 + 逐表项锚。

### A2 · 输入面没盖到

锚本身有牙，只是**喂进去的输入从没触发过那条路径**。

- **a. 只有合法输入**（原 A1）：实现里有"受检访问失败 → trap / 短路 return"分支，但测试输入**全部合法**。查法：读实现的 error / catch 分支，反查测试里有没有构造过触发它的输入。实例：host handler 层数十处 `catch` 收口，对若干处做突变全绿——`host_fopen` / `host_fread` 的受检路径确实无锚（host 测试全用合法地址）。
- **b. 语料形状单一**（原 A6）：某函数在全部语料里只有一种形状的用法。查法：`grep -rn "<fn>(" native/tests/cases/` 看全部用法。实例：全语料只有 `round(2.5)` 一处且是**正**平局 ⇒ 结构性抓不到负平局缺陷（而负平局全错）。
- **c. 只有"平均情况"的基准**（原 A9）：微基准只测顺利路径 ⇒ 结论方向被样本分布决定（某 API 在 0% 失败时快 2.5×、**100% 失败时反而慢 1.35×**）。基准必须覆盖**失败率 / 规模 / 边界**三个维度。

### A3 · 锚把与 oracle 不同的行为固定成了预期（锚错 > 锚漏）（原 A3）

- **判据**：既有测试的期望值与 oracle 实际行为**不一致**，但测试是绿的 ⇒ 修复时会"按错的来"。
- **查法**：发现"两侧形态不同"时，**先查是不是既有锚已锚定了错形态**。
- **实例**：`getchar` 行尾不产 `\n`——既有白盒锚用的正是"每行不含换行的数组"形态，把与 oracle 不同的行为锚死，三道防线因此全绿。

### A4 · 分解式数字无锚，只有头条数字有锚（原 A7）

- **判据**：文档写"X = a + b + c"，闸只比 X。
- **实例**：`protocol 44 = 白盒 32 + 黑盒 6`（32+6=38≠44，行内不自洽）而计数闸只比头条 44。

### A5 · 不可达分支不硬报（判定纪律，非缺陷形态）（原 A8）

- **判据**：某分支在当前实现下**永远走不到**（前置不变量保证）。
- **查法**：**能否找到一条区分两条路径的输入**；找不到 ⇒ 等价或不可达，属读码判定，**不硬报**——收尾时列进"未覆盖"表并注明"判据不足"。
- **实例**：某 `catch` 前的 `register_alloc` 已保证地址在已登记区域内 ⇒ 后续受检写必成功 ⇒ 该分支不可达。

## B · 分叉（两侧不等价）

### B1 · 名字对位陷阱：同名函数语义不同
- **判据**：把 `libm::f` 机械映射到目标语言标准库同名函数。
- **必查清单**：`round`（**平局方向**：C99 要求远离零，而 core 自称 half up ⇒ 负平局全错）、`log`→`ln`、`mod`→`fmod`（**截断**取余 vs IEEE **最近**）、`floor/ceil/trunc` 的 ±0 符号。
- **实例**：`round(-0.5)` 真值 `-1.0` vs 实现 `-0.0`；`-1.5`→`-2.0` vs `-1.0`。**正平局恰好一致 ⇒ 只看正样本会全绿**。

### B2 · 行的边界形态（含不含换行符）
- **判据**：一侧"每行含尾换行"，另一侧剥掉。
- **实例**：一侧 = `split_inclusive('\n')`（行**含** `\n`），另一侧**剥**了；同一文件里 `scanf` 路径补了 `\n` 而 `getchar` 路径**没补** ⇒ 两个入口行为不一致。

### B3 · 空串 / 零元素极端
- **判据**：修好了"尾随分隔符"边界，漏了"空输入"。
- **实例**：修好 `"a\n"` 后，`("", 0)` 仍分叉——一侧 `"".lines()` = **零行**（`None`），另一侧当**一行空串**（`Some("")`）。

### B4 · 多字节字符的边界前移
- **判据**：增量 / 差分接口按字节游标推进，未回退到 UTF-8 字符边界。
- **实例**：输出 `delta` 的 cursor——一侧有 `while !all.is_char_boundary(start)`，另一侧没有 ⇒ 切出半个字符。

### B5 · 文法宽容（非法输入被静默接受）
- **判据**：解析器只"扫字符"不做文法校验。
- **实例**：JSON 数字里 `1e` / `01` / `1.` / `.5` / `1e+` 全部 **ACCEPTED**（RFC 8259 均禁止）。

### B6 · 递归深度无上限 ⇒ 栈溢出
- **判据**：递归下降解析器（JSON / 表达式 / 嵌套结构）**无 depth 计数**。
- **实例**：自写 JSON 解析器的 `parse_value` ↔ `parse_object/array` 递归无 depth 限制 ⇒ 深嵌套可致进程崩溃（`0xc00000fd` = `STATUS_STACK_OVERFLOW`）；`serde_json` 默认 **128** 层硬限制 ⇒ **两侧安全边界完全不同**。长驻进程（JSON-lines 服务）尤其危险。
- **注意**：阈值**不稳定**（依赖上下文 / 栈余量），复现可能不稳定——如实记录，别硬下"必崩"结论。

### B7 · 输出通道的去重 / 限额 / 幂等
- **判据**：一侧有 `if !contains(&msg) { push }` / 预算裁剪 / 首错优先之类的**状态相关**行为。
- **实例**：堆耗尽通报有去重（3 次失败只出 1 条），另一侧无条件 push ⇒ 3 条。

### B8 · 批量 / 转换 API 破坏输入（引用共享）
- **判据**：一侧是不可变借用（`.clone()` / 重建），另一侧共享引用 + 就地 `clear()`。
- **实例**：批量解码破坏输入——解码后原对象的字段被清零。

### B9 · 跨语言 JSON 输出的键序
- **判据**：一侧 `serde_json` 未开 `preserve_order` ⇒ 键**按字典序**；手写 emitter 常是**插入序**。
- **实例**：`{"behavior_contracts":…,"frozen_at":…,"schema":…}`（字典序）vs 实现 `schema` 打头。

### B10 · 相对路径基准不同（`dir_of` / 文件名解析）
- **判据**：一侧取"文件名所在目录"、另一侧取"当前目录"。
- **查法**：造形态极小语料（裸文件名 / `./x` / 绝对路径 / 子目录 / 嵌套 include 链 / 取不到的根相对路径），cwd 固定，双侧各跑一遍比 stdout。

### B11 · 「宿主分叉」被套用到多宿主共用实现（另一宿主的既有能力静默丢失）
- **判据**：提交把某分叉登记为「**X 宿主**下的形态限制」，但改动落在**两个宿主共用的函数**里 ⇒ 另一个宿主原本具备的能力一并降级，而它没有任何锚。
- **查法**：对每一条「形态分叉」登记，先答两问——① 这段实现在哪些宿主/入口的调用图上（含另一宿主）？② 另一宿主在改动前**能不能**做这件事（读被删代码 / 查旧提交），有没有用例锁它？两问任一为"能/无锚"即命中。
- **处方**：要么按宿主注入（native 走真实 provider、wasm 走内存表），要么把登记口径改成"全宿主共享"并**给受影响宿主补一条能力锚**（否则下次仍会静默丢）。
- **实例**：协议层从 native-only 包上提到「native + wasm-gc」共享包时，quote-include 的 provider 由 `tokenize_with(<FsProvider>, base_dir)` 换成 `tokenize_with_vfs(<空表>)`；wasm 无 fs 成立，但共用函数让 native 壳一并丢掉了 `#include "..."` 的文件系统解析（oracle 同请求解析成功、本侧回 E1021）。被删的 provider/`dir_of` 复制件前后零锚，`serve_smoke` 只跑 `<stdio.h>`（走内建存根）⇒ 无闸可拦。

### B12 · 照搬时把 oracle 的辅助函数换成语义相近的另一个（同族对互替）
- **判据**：移植 / 照搬某函数时，oracle 调用的**辅助函数**在目标侧被换成"名字不同但用途相似"的另一个 ⇒ 在两者**不重合的输入域**上静默分叉；主流程逐行读起来与 oracle 一致，分叉藏在辅助函数里。
- **查法**：对每条照搬的函数，把 oracle 侧调用的辅助函数名**逐个抄出来**，与目标侧调用名逐一对齐；出现"名字不同"就立即用**独立小工程直接调这两个函数**、打印各自在各输入上的返回值，求出不重合域。**优先查同族对**（解一层 vs 递归、含某类 vs 不含某类）：`base_kind` / `immediate_base_kind` / `base_element_type`；`trim` / `trim_end`；`parse` / `parse_lossy`。
- **与 B1 的区别**：B1 = 同名函数语义不同（对位时误以为等价）；B12 = 语义不同的两个函数改了名字被互换——读码时看不出"替换"这个动作，因为两侧名字本身就不同。
- **实例**：`get_array_snapshots` 照搬 oracle（`memory.rs`）时，元素宽度与取值分支用 `base_element_type`（只递归剥数组、**不解指针**）替换了 oracle 的 `base_kind`（先解一层指针、再递归数组）⇒ 指针元素数组上分叉：`int*[2]` 的 oracle 输出地址数值、本侧全 `?`；`char*[2]` 连元素步进都不同（oracle 1 字节、本侧 4 字节）。
- **处方**：把"辅助函数名对齐"列为照搬验收清单的一项机检（两侧调用名对不齐即登记）；同族函数并存时在头注写明各自语义与适用面。

### B13 · 迁移批把"多族 / 多模块聚合"的顺序按自己的组织重排 ⇒ 输出列表序与 oracle 不同
- **判据**：oracle 的聚合函数按固定次序 `extend` 多个族（算法判据各族 / 校验器各规则组 / 字段各来源），迁移侧按自己的文件切分或语义分组**重排**——同一输入**同时命中多个族**时，产出列表的元素顺序与 oracle 不同（每个元素本身逐字相同）。
- **查法**：① 把两侧聚合函数的调用序列并列逐项对齐（例：`algorithm_detector/mod.rs:35-41` 的七行 `extend` vs 迁移侧 `detect.mbt:35-46` 的四个 `for`）；② 构造**同命中多族的输入**——先用聚合内的单项函数分别验证"每个族都命中"，再按各自调用序推列表序。**只命中单族的样本永远测不出顺序差**（A5 同族：样本对两个候选序无判别力）。
- **与 B9 的区别**：B9 是**序列化键序**（JSON 对象成员名）；B13 是**列表元素序**（数组/向量），差在数据形态与比较口径。
- **与 B12 的区别**：B12 是"某个辅助函数被换掉"（单点语义）；B13 是"多个族的相对次序被重排"（聚合结构）。
- **处方**：把"聚合顺序"列为照搬验收清单的一项机检（两侧调用序列逐项对齐）；或迁移侧直接沿用 oracle 的 `extend` 次序，并在头注写明"顺序属输出面，不可重排"。
- **实例**：算法判据聚合 oracle 序 = sorting → search → graph → tree → structures → string → math（+dp 附加），迁移侧排成 sorting → search → **string → tree**；函数名 `bstKmpSearch` 同时命中 tree（`bst_search`）与 string（`string_match_kmp`）⇒ 两侧 `matches` 数组序**相反**（查法：同包临时 wbtest 直调各族判据，按两侧聚合序各拼一次列表、比首元素）。纯单族样本（如 `mergeSort`）两侧逐字一致，故该类差异此前未被察觉。

### B14 · 移植时浮点字段宽度被放大（oracle `f32` → 目标 `f64`）

- **判据**：照搬的 struct 字段 / 中间量在 oracle 侧是 **`f32`**，目标语言侧写成 **`f64`**（反之亦然）。**读码几乎看不出问题**——两侧源码都写着同一个算式、同一组常量，差别只在类型宽度。
- **为什么危险**：分叉**只在「算不出有限短小数」的取值上出现**。两者对源里的十进制字面量（`0.9` / `0.75`）的**最短往返 repr 相同**，所以常量表类字段（边权 / 权重 / 阈值）全绿；而**除法产生的比值**（`count / window`、`a / b`）在 f32 与 f64 下的最短 repr 不同 ⇒ 序列化出来的字符串分叉。**锚样本若恰好取可精确表示的比值（如 `3/4`），对宽度零判别力**（A1-c 同款：样本没落在能区分两者的取值上）。
- **查法**：① 逐字段对比两侧的浮点宽度声明（`f32`/`float` ↔ `Double`/`f64`）；② 对每个浮点字段问「它的取值是常量还是**算出来的**」——算出来的才算候选；③ 对候选比值用脚本枚举两侧最短 repr（f32 侧按 ryu/serde 语义取最短往返，f64 侧取 `repr`）求差集。**只比两侧源码文本必然漏掉**。
- **与 B12 的区别**：B12 是辅助函数被换成另一个（语义不同）；B14 是同一个算式被换了**运算宽度**（语义形式相同、数值结果不同）。
- **实例**：某检测函数的 `confidence` 在 oracle 是 `f32`（`count as f32 / denom as f32`），迁移侧声明成 `Double` ⇒ 比值两侧字符串分叉，而锚里唯一的比值样本是 `3/4`（两侧都是 `0.75`）⇒ 零判别力。同批同一 struct 的 `strength` 字段也是 f32→f64，但取值全是源里写的十进制常量 ⇒ 实测无分叉（**是常量表遮蔽，不是宽度无害**——换一批非常量取值同样会分叉）。
  - **纠正（2026-10-02 复核；原实例所写的 oracle 侧文本有误）**：原实例记 oracle 侧为 f32 最短表示 `0.6666667`，**实测不成立**——oracle 走 `json!`（`Value` 路径），`f32` **已被提升为 `f64`**，wire 文本是 **f64 最短表示** `0.6666666865348816`。那个 `0.6666667` 是照"oracle 是 f32 ⇒ 本侧用 f32 ryu"**推断**出来的，未经原始字节验证；该误述当年直接误导过一次实现（见下条同族面）。**判文本口径前必须先取原始响应字节。**

- **同族面（2026-10-02 补入 B14，不新开编号）**：浮点 wire 文本是**序列化路径**的函数，**不是类型宽度的函数**——宽度两侧全一致也照样分叉。
  - `serde_json` 两条路径产出**不同文本**：`json!` / `to_value` 走 `value::Serializer`，其 `serialize_f32` 是 `Value::from(f32)` = `Number::from_f64(f as f64)`（`src/value/ser.rs`）⇒ 文本 = **f64 最短表示**；而 `#[derive(Serialize)]` + `to_string` 路径走 `ryu::Buffer::format_finite(f32)` ⇒ 文本 = **f32 最短表示**。
  - 照搬时若按"oracle 侧是 f32 ⇒ 本侧用 f32 ryu"实现，得到的是**值对、文本错**：本侧 `0.6666667` vs oracle `0.6666666865348816`。可达比值枚举实测 **26/45 分叉**，只有 `0.5` / `0.75` / `0.25` 一类二进制精确比值同文本。
  - **查法**：① 先判 oracle 该字段的**序列化路径**（`json!`/`to_value` ⇒ Value 提升；`derive(Serialize)` + `to_string` ⇒ ryu 直排），再定文本口径；② 用**原始响应字节**验证——解析成数值再比会掩盖差异（两侧各自解析后"看着都像 2/3"）；③ 端到端锚要挑**非二进制精确**的样本（`3/4` 对两种口径都同一文本，零判别力，同 A1-c）。
  - **反面提醒**：锚若把**推断出来**的文本钉成期望值，就锁死了错形态（A3）——按 oracle 改对实现反而变红。

### B15 · 照搬格式化占位符时位宽语义不重合（2026-10-03 新增，与 B12 / A1-c 同族）

- **判据**：oracle 用格式化占位符产出的文本（`{:04X}` / `{:02}` / `{:>8}` 之类）在目标侧**手写替代实现**（目标语言无同名格式化 API），替代实现把占位符语义读成"恒定位宽"或补位方向相反 ⇒ 只在**部分取值**上分叉：取值超过最小位宽时两侧一致，未超过时一侧补零另一侧不补（或位数不同）。与 B12 的分工：B12 是"换了一个已有的同族函数"，本条是"新写了一个替代实现"；与 A1-c 的分工：A1-c 是数值临界样本，本条是**文本位宽临界**。
- **查法**：① 把 oracle 侧每个格式化占位符逐条抄出，标注它的**最小位宽 / 填充方向 / 截断规则**；② 对每个替代实现，用**跨越最小位宽的三个取值**（小于 / 等于 / 大于 10^位宽）实测两侧输出文本；③ 端到端响应里的**总长度差**是最快的旁证——差值恰等于「行数 × 每行位宽差」时即为本条。
- **实例**：oracle `format!("addr=0x{:04X}", addr)` 对 `0x5018` 输出 `5018`、对 `0x501` 输出 `0501`、对 `0x123456` 输出 `123456`（**最少 4 位**，Rust 语义实测）；照搬侧手写"按 32 位逐 nibble 输出" ⇒ 恒 8 位 `00005018` / `00000501` / `00123456`，**三者全部不等**。该分叉只在"取值不足 5 位 hex"时显现，而端到端锚恰好把 8 位形态断言成期望（A3：锚锁死错形态，按 oracle 改对反而变红）。复现 = `rustc` 打 `{:04X}` 三个取值 + 目标侧直调替代函数比文本。
- **处方**：把"占位符语义（最小位宽 / 填充方向）"列入照搬验收清单逐项核；端到端锚改用**能跨最小位宽**的取值，别用"恰好等于位宽上限"的样本锁形态。

## C · 死面 / 无生产者 / 不可达

### C1 · 字段声明了但从不被读
- **实例**：某结果结构体的 `abnormal` 字段**从不进入判定** ⇒ 耗尽的异常结果（stdout "" + exit 0）与"程序本无输出"不可区分，可致**假 SAME**。
- **同族面：类型 / 接口声明了字段，但零消费者**（2026-10-04 补）：TS 迁移把 wire DTO 手写成 `interface`，文件头注还写着「字段 = 消费面实际读取集」，实际有相当一部分字段（及若干嵌套 interface）在全库**零引用**，也无任何用例能反证它们 ⇒ 声明面永不腐烂也永不生效，读者还容易把"有类型"读成"已接线"。
  - **查法**：① 对每个声明字段 grep 全库（排除声明文件自身），命中 `0` = 无消费者；② 再答第二问——**它有没有被实测观测到**（写探针直调制品，dump 该字段是否存在 / 是否出现过非空取值），两问皆否即"幽灵声明"；③ 把**声明字段集**与**运行期实测字段集**求双向差（两侧都算，才同时抓"多声明"与"漏声明"）。
  - **与 C2 / C6 的分工**：C2 = 无生产者（写了没人产出）；C6 = 消费者到了 DOM/模板但无消费终点；本条 = 连消费者都没有，而**声明面声称有**。
  - **处方**：无消费者的声明删掉或移入显式标注的「预留（未接线）」块；要保留就把该字段接进冒烟闸的键断言。

### C2 · 字段只有"读 / 测试赋值"，**没有任何写入方**
- **判据**：grep 某字段，只有【定义 / 初始化为 `[]` / 读取 / 白盒测试手工赋值】四类，**无生产者**。
- **实例**：`file_ranges`——对应实现在**引擎层的多文件管线**（活跃区侧无该包）⇒ 多文件分支**逻辑已测、生产者未接**，看起来"已生效"。
- **处方**：要么登记"生产者待接线"，要么加闸。

### C3 · 接线臂不可达（"已接 N 臂" ≠ N 臂可达）
- **判据**：预注册表把某名字全量塞进调用表，导致宿主臂成死面。
- **查法**：`dump-compile` 一个逐名调用探针，看该名字发 `CallHost` 还是 `Call 10xx`；再用路由表交叉核对。
- **实例**：`isdigit…isxdigit` / `rand` / `srand` / `abs` 等 14 臂全不可达，但测试"通过"并在锚**幽灵行为**（锚的是宿主实现的随机序列，真实路径走 libc 实现）。

### C4 · 死参数 / 死代码（修复的副产品）
- **判据**：改了实现后，参数 / 变量不再被使用。
- **查法**：`moon check` 的 warning 增量（`unused_value` 族）。

### C4-b · 呈现层「锁死态」无人解锁（2026-10-03 审阅新增；C4 同族）
- **判据**：HTML/模板写死 `style="display:none"` 或等效隐藏态，而 JS 侧**没有任何代码改回它的 display** ⇒ 该区块（常含标题与教学说明）对用户永久不可见。
- **查法**：对每个内联 `display:none` 元素，grep JS 有无对其 `style.display` 的赋值或等价 class 切换；**零命中 = 锁死**。实例：`#array-viz-head`（数组区标题+「指令级中间态」教学说明）写死 none，渲染函数只切了内容容器不切标题——用户永远看不到这段说明。

### C5 · 同族实现里漏改一处
- **判据**：一串同类实现，逐个数"有几个用了做法 A、有几个没用"。
- **实例**：6 个输出通道里 5 个重建、1 个共享引用；3 个分配臂改了 trap loc、同文件的 `free` / `unreachable` 没改。

### C6 · 「消费语句存在但无消费方」（有消费者、无消费终点）
- **判据**：字段被读进 DOM class / 局部变量 / 模板串，但**下游没有任何东西真正消费它**（无对应样式定义、无分支判断、无输出通道），字段值对最终呈现零影响。
- **查法**：对每个"写进 class / 传给模板 / 存进局部"的字段，**追它的消费终点**——class 名在 CSS 里有没有定义？变量在后续分支里有没有被读？**"赋值了"不等于"生效了"**。
- **与 C2 的对偶**：C2 = 无生产者（写了没人产出）；C6 = 有消费者但无消费方（读了没人消费）。两者都表现为"看起来已接线"。
- **实例**：前端 `class="diag ${severity}"` 把 `severity`（error / warning）写进 DOM class，而样式表只定义 `.diag` 基础样式与 `.diag .code` / `.diag .fix` / `.diag .loc`，**没有 `.diag.error` / `.diag.warning`** ⇒ error 诊断与 warning 渲染外观完全相同，severity 对呈现零影响（查法：`grep -n "\.diag" style.css` 只有基础样式；同族检查法 = 把模板里写进 class 的每个枚举值与样式表的类名集合求差）。

## D · 门禁 / 闸自身不可信

> 共同特征：**你以为的"绿"不代表被验过**。审闸比审代码更值钱。

### D1 · 闸自证两问：是不是闸 / 会不会自愈

> 任何"闸绿了"的结论，先过这两问再采信（原 D1 / D2 / D12 三条合并——D12 本就是这两问的汇总）。
> **编号 D2 与 D12 留空**，以免打断既有引用。

- **问一：它是不是闸**（原 D1）：`grep -c "<脚本名>" .github/workflows/ci.yml`。**0 = 本地工具，不是闸**。实例：某 D 级差分工具长期未接线 ⇒ "运行期正确"全靠手工复跑，回归无人拦。
- **问二：它会不会自愈**（原 D2）：头注明写"红→绿形态"（检测的同时顺手修）的闸，判"某提交上红不红"**每次都要从干净态起跑**（`git checkout -- .` 后再跑，一次定论）——第二次 PASS 不是证据。

### D3 · 缓存 key 里没有的东西最危险
- **判据**：缓存 key =（源码 + 工具链版本 + 参数），**不含工作区状态 / 环境**。
- **后果**：本地永远回放同一答案，把竞态冻结成"KNOWN"。
- **手法**：**用 Python 复刻 key 生成式，就能把缓存条目反查回用例名**。

### D4 · 超时 / 异常结果被当确定性结果
- **实例**：超时路径走 `Kill()` ⇒ 子进程返回"非零退出码" ⇒ 被当作"程序真的失败"落缓存。注释自称"超时 = 环境异常可重试"，实现未区分。第二次跑**秒回同一结论**即为已缓存。

### D5 · 归一化吃掉了合法输出
- **判据**：归一化函数剥掉的行前缀，同时是程序输出的合法前缀。
- **实例**：某归一化剥 `// ` / 两空格 / `Warning` / `Error` / `Finished.` 开头的行 ⇒ 两侧同被剥 ⇒ **假 SAME**。
- **手法**：写同包探针直调该函数，构造"两侧差异行均以被剥前缀开头"的输入看归一后是否 `相同=true`。

### D6 · 闸的真值来自缓存制品 ⇒ 是复述，不是对账
- **判据**：闸声称堵住"文档与真值一起错"的盲区，但它读的"真值"是 `status: cached` 的制品。
- **必需**：闸内**强制新鲜度**（自己跑采集，或要求 `provenance=run` 且 `as_of` 落在本轮）。

### D7 · `facts` 类审计的四个结构性盲区
1. **只比「文档 ↔ facts」，看不见「facts ↔ 真值」**：两者同为陈旧值就一起绿 ⇒ 凡"某数字在文档里"类结论，**必须自己重跑采集命令**。
2. **不把 `unavailable` 判红**：CI 上真值校验面可能小于本地，且**绿 = "没校验"而非"校验过"**。
3. **Frozen 桶优先于 Manual / Suspect**：命中**行内任一日期**即冻结 ⇒ **"带日期的分解式现值行"对两条通道都隐形**。
4. **豁免白名单吞 error**：加载豁免表时丢弃 error ⇒ 头注声称的"条目指向不存在文件即红"**从不打印**；被豁免文档数字干净时**静默通过**。测白名单要**双向**。
- **假阳性口径**：md 通道 =「Context 正则命中行 × 行内 `\d{2,6}` 落 Lo/Hi」，**不懂"是否在陈述现值"** ⇒ 会把行内的行数、处数、版本号误判成漂移。**禁机械替换，改口径或改句子**。

### D8 · 门禁覆盖面比你以为的窄
- **默认 target**：CI 的测试步骤若不带 `--target native`，native-only 包的锚**全不在门禁内**。核对：两种情况各跑一次比总数。
- **只扫某些目录**：目录扫描类闸（如源码卫生检查）可能只覆盖活跃区 ⇒ **根目录 md 不在覆盖内**，其问题会长期隐身且使后续 diff 不可见。
- **只比产物不比运行期文本**：产物差分不覆盖运行期 stdout / 诊断文案。
- **只比"去重后的首现序列"**：端到端对拍器为压噪声，常按"每 `(phase, desc)` **首现**"去重后再比 ⇒ **同一标注的重复次数、以及非首现帧的取值差，全在覆盖面外**。读闸先问一句"取键函数里去重了吗"，再用"只改坏非首现帧"的注入验证（首现不动 ⇒ 闸全绿即坐实盲区）。实例：算法标注族级对拍器比 `(phase, desc)` 首现序列（82 模板 × 28 算法双向一致），逐帧全量面**不在其覆盖内**，需另用探针补比。
- **文本抽取闸的抽取面会静默塌缩**（2026-10-02 补）：基于正则 / 字面量抽取的文本对账闸，被检代码**一换写法**（字面量→变量、匹配链式调用→`querySelector` 等抽取器不认的形态）抽取面就归零 ⇒ 同一 bug 字面量红、变量静默过；空输入文件更是天然全绿。**闸没有任何"各路命中数下限"守卫**。查法：构造"同 bug 的变量形态"与"空文件"各跑一发，看是否都绿。处方：硬编码**各路有效位点数下限**（低于即红，demo 闸实测基线 1/3 处取值）+ 不可解析位点计数打印；下限触发于大重构时按新基线更新（良性红）。实例：demo UI 字符串契约对账闸，`el.classList.add(cls)`（cls="active"）形态静默通过、同 bug 字面量红——加 class/id/var 三路下限（3/30/60）后塌缩即红。

- **「字段级冻结」闸的请求序列天然不含某字段的非平凡取值**（2026-10-03 补）：闸以**固定请求序列**驱动双宿主比对，若序列里没有任何一帧能让某字段取到**非空 / 非 ASCII / 非默认**值，该字段实际上从未被比对过——而闸的名字、文档与规则资产都写着"字段级冻结"。查法：对每个被声称冻结的字段，回序列里找"能产出它非平凡取值的帧"，找不到即该字段在覆盖外；再核**闸的规则资产（rules.json / 豁免表）有没有登记这条未覆盖面**（没登记 ⇒ 读者会以为已冻结）。与上一条同族：上一条是"抽取器认不出形态"，本条是"序列根本不产生该形态"。
- **实例**：`output.delta` 帧跟随的是一个无 stdout 输出的程序 ⇒ `delta` 字段恒空/纯 ASCII，于是该字段的已知分叉（非 ASCII 文本的编码折回、cursor 在字符中段切字节）不在冻结面内，规则资产也未登记这条缺口。

- **抽取面「静默归零」的两个新触发面**（2026-10-04 补，与上一条同族）：上一面是「字面量→变量」（**值**换了），下面两面是**值没换、写法/来源换了**。
  - **(a) 被检代码换了语法形态**：抽取正则按旧语言写法写死，源码一迁移（JS→TS、加泛型 / 类型断言、链式调用改 `querySelector`）⇒ 该形态的位点整批消失，而闸的输出措辞不变。查法：把闸的抽取正则**原样**搬到迁移前后两份源码上各跑一遍、求命中集合之差（差集非空即塌缩面）；再注入该新形态的**幽灵值**看闸红不红，**同位置的旧写法对照必须红**。实例：demo UI 字符串契约闸的「取 id / 类名链 / 变量绑定」三路正则只认 `$(` / `getElementById(` / `querySelector(`，对 `$<T>("id")` 与 `($("id") as T)` 两形态一律不匹配——聚合层面（id 集合）仅因同一 id 在别处仍有裸 `$()` 调用才侥幸未塌，但「位点数下限」这类逐路守卫正靠不住。
  - **(b) 多来源抽取里某一路恒为 0 命中**：闸把两个来源合并抽取（如 HTML 的 script 标签 + 入口模块的 import 图），其中一路因**路径前缀 / 引号形态假设**恒空（只匹配 `src="./x"`，而 HTML 写 `src="x"`）⇒ 它声称覆盖的那一路实际零覆盖，且"某来源贡献 0 条"不触发任何报错。查法：**逐路打印命中数**（不是只打合计），并对每路做「删掉该路所指的某个资源」注入看闸红不红。实例：部署 workflow 里的「组装资源存在性」内联自检，HTML 一路贡献 0 条，删掉 HTML 裸 `src` 指向的那个脚本后自检照旧报「全部在位」。
  - **处方（两面共用）**：抽取面**逐路打印命中数 + 逐路设下限**（低于即红）；资源存在性类断言**别复用抽取结果**，直接列期望路径清单逐个 `test -e`。

### D9 · 被判程序的工作目录
- **判据**：`grep -n "exec.Command" -A3 <脚本>` 看有没有 `cmd.Dir`。**只隔离 exe 输出目录 ≠ 隔离程序 cwd**。
- **后果**：被测程序在仓库根跑，语料里的 `fopen("test.txt")` 等真读写仓库根；若这些文件名被 `.gitignore` 覆盖，`git status` **永远干净**，副作用完全隐形；并发下互相覆盖 ⇒ **同源同编译器不同结论**。
- **两态对比实验（必做）**：① 现状（游离文件在 + 缓存热）；② 干净起点（移走游离文件）+ **清空缓存**。同一份源码跑同一批用例 ≥2 轮。

### D10 · 白名单条目的"理由"是待验断言
- **手法**：清空 known 打印真实差异、与登记 digest 对比，判它是**不变式**还是**竞态快照**。
- **实例**：某条目的 reason 写"另一侧无此文件"，实测文件就在仓库根，差的是"读到了兄弟用例写的残留内容"。
- **同族面（映射表类对账闸，2026-10-03 补）**：把两条测试的"覆盖关系"写成**手工映射表**（`rust_test → mb_anchors`）时，闸能机判的只是"表覆盖齐全 + 引用存在"，**判不了映射语义**。查法：任取一条 `anchored` 条目，把它的锚换成另一个**实存但无关**的锚名，跑闸——仍绿即坐实。含义：`missing=0 / 无洞` 只等于"表填满"，**不等于"语义全覆盖"**；头注与文档措辞应写"映射无洞 + 引用无陈旧"，别写"全覆盖"。处方：能机判的部分（1:1 形态要求锚名与测试名对齐 / 同一锚不得被多条 `anchored` 复用）补断言，跨包 `merged` 类仍需人工逐条核。

### D11 · 同族防线的强度不等
- **判据**："两个防线都绿" ≠ "两个都有牙"。
- **手法**：用静默 exe（`int main(){return 0;}`）顶替被测二进制（**记得还原并 `md5sum` 对账**），看各防线是否都能红。

### D13 · 格式闸要复刻 CI 口径
- **判据**：CI 的 fmt 步通常是"跑格式化 + `git diff --exit-code`"，**不是** `--check` 子命令；后者在本机可能 exit 127。
- **正确查法**：记下 fmt 前的脏文件集合 → 跑格式化 → **新脏出来的就是漂移文件** → **只 `git checkout -- <新增脏文件>` 复原**（绝不用 `git checkout -- .`）。

### D14 · 表头计数与表体行数不一致
- **查法**：清单类文档，逐行数表体，与标题里的计数对账。
- **实例**：标题写"N 个，全部接线"，表体实际行数是另一个数（且"全部接线"为真、标题数是陈旧的）。

### D15 · 闸的判定依赖**未固定版本的运行时/工具链**
- **判据**：闸的断言（或被测 API 的行为）在**两个运行时版本的语义差**上翻转；而 CI 没有 pin 该版本（无 `actions/setup-node` / `setup-python` / `rust-toolchain` 之类）。**本地绿 ≠ CI 绿**，且同一台机器换 PATH 上的解释器就变红。
- **查法**：① `grep -c "setup-node\|setup-python\|dtolnay/rust-toolchain" <ci.yml>`——**0 = 判定随 runner 默认版本漂移**；② 把候选版本各跑一遍同一产物 + 同一脚本（本机常同时存在托管版与系统版，`which -a` / 显式绝对路径），比较退出码；③ 断言涉及"规范演进中的 API"时（如实例中的 `WebAssembly.Module.imports` 对 string-constant 的可见性），**去字节层取证**——自己解一遍产物（ELF/PE import 表、wasm import 段），别用高层 API 的自报数当"事实"。
- **处方**：断言改成不随版本翻转的口径（按 module/name 过滤，只判"功能性 import"）；CI 加版本 pin；文档/提交信息里的数字按字节层真值写。
- **实例**：wasm-gc 宿主冒烟断言 `WebAssembly.Module.imports(mod).length === 0` 与提交声明的"产物零 imports"：node 22（V8 12.4）列出 2174 条 `module:"_"` 的 string-constant import 且 `instantiate(mod, {})` 抛错（exit 2）；node 25（V8 14）则隐藏它们并自动满足（16/16 PASS）。产物 import 段实测 ≈2180 条 ⇒ "零 imports" 只在高层 API 的新版语义下成立。

### D16 · 依赖解析静默降级 ⇒ 对着"错制品"全绿
- **判据**：一套测试 / 门禁对「源码工作树」与「已发布制品」能给出**同一结论**，而实际解析到哪一个取决于某个配置文件是否生效。该配置缺失（或 cwd 不对）时**静默换源**：不报错、不改措辞、**输出逐字相同**，还可能更"干净"（任务数更少）。
- **查法**：先问"这条门禁判的是工作树还是制品？"，然后打印**解析树**（`moon tree` / `go list -m` / `cargo tree`）确认实际源；再**把该配置文件临时移走跑一遍**（注入），看是否静默换源仍绿，两态的输出差分就是这道门禁的真实判别力。
- **实例**：依赖本地工作树的 moon 工程，`moon.work` 在 ⇒ `moon tree` 出 `-> vitro/engine@0.7.0 (local <工作树>) [workspace member]`、70 任务；移走 ⇒ 解析到 registry 制品（无成员标注）、**任务数骤降（70 → 28）、`moon check` 0 errors、`moon test` 仍全通过且打印逐字相同**。
- **后果**：「改上游就当场爆红」这类**拦截力声明**，前提是解析锚存在；没有锚时它只是纸面承诺——上游改了帧语义，本仓测试照样对着旧制品全绿。
- **处方**：加**解析断言**（日志必须含工作区成员解析行 / 解析出的路径必须等于工作树），**不接受"跑绿了"当证据**；同类同形：monorepo 里 `workspace:` 协议漏配、`replace`/`patch` 未生效、`node_modules` 软链指向已发布包。

### D17 · 非源码资产（静态页 / 前端 JS / CSS / 部署 workflow）不在任何闸的扫描面内
- **判据**：仓内新增一类"人写、非编译输入"的资产（静态 HTML/JS/CSS、模板、workflow yml），而门禁族全是"扫源码目录 + 比编译产物" ⇒ 资产里写错的**字段名 / 硬编码数字 / 产物路径**没有任何闸会红。
- **查法**：① `grep -c "<资产目录>\|<新 workflow 名>" .github/workflows/ci.yml` ⇒ **0 = 未接线**；注意这查不到"独立 workflow 自身无 lint"（如 actionlint 缺失 / YAML 语法无校验）。② **注入实证**：把资产里一处消费点改坏（如前端读后端帧的字段名 `out.total` → `out.totall`），跑全部**可能**覆盖它的闸；全绿即坐实无锚。
- **后果**：页面靠人肉点开验收；后端帧字段改名 / 文档数字更新后，前端静默渲染 `undefined` 而门禁全绿。
- **处方**：给资产配一条**冒烟闸**（喂同一份预置用例数据跑一遍消费逻辑，断言"消费的字段在帧里存在"+"预置真值与实跑逐字节一致"），而不是指望人记得；部署类 yml 另加 actionlint，或在 CI 里把 yml 里出现的关键路径 `test -e` 一遍。
- **实例**：`demo/` 单页（index.html / app.js / cases.js / style.css，浏览器直调 wasm-gateway）注入 `out.total` → `out.totall`（页面会打印 "undefined 字节"）后，`source_hygiene` / `facts check` / `testcount` / `moonbit_surface -check` **四道全绿**；`grep -c "demo/" ci.yml` = 0；根因是 `source_hygiene` 只扫 `moonbit/`，全仓无 HTML/JS lint。
- **同族（可并查）**：README / 文档里**为外部读者承诺的链接与在线地址**同样零闸——`curl` 才能知道它是 200 还是 404，`facts check` 只比"文档 ↔ facts 的数字"，不查外链可达性。

### D18 · 对账闸只锁字段子集 ⇒ 同一制品的旁证字段成为静默漂移面
- **b. 守护变量空转（2026-10-03 审阅新增，D21 同族）**：闸的代码里**算了某个守护值（计数/长度/校验和）却从不把它放进任何断言** ⇒ 注释自称"数字漂移即红"实际永不红。查法：`grep -c <变量名> <脚本>` == 1（只出现赋值处）即空转；唯一可靠处方 = 把值接进 check（或删掉假装存在的守护）。实例：demo_smoke 的 `methodCount` 只赋值不参与断言，页面方法面计数 16 漂到 21 两批无人拦。
- **判据**：闸的校验函数（schema / 枚举 / 双向对账）只覆盖制品（JSON / 表）的**一部分字段**，其余语义字段（`detectable_by_defense`、`notes`、`rationale`…）**写了但不进任何判定** ⇒ 它们与已校验字段（如 `anchors`）互相矛盾时，闸照样绿。
- **查法**：读闸的 `validate`，列出制品**全部字段** vs **被校验字段**，**求差集**；对差集里每个"语义字段"问一句"它跟已校验字段能否相互矛盾"。
- **实例**：`scripts/diff_ledger` 校验了 schema / 枚举域 / 17 键 / anchors 双向对账，但 `detectable_by_defense` **域开放**（含 `memory-verify-wbtest`、`libc_single_source` 等非三防线值）且与 `anchors` 无一致性断言 ⇒ 某条目写 `["shadow"]` 而 anchors 只有 clang_direct + vm_diff（shadow 空）时闸全绿。
- **处方**：给差集里的每个语义字段补**域枚举** + 与已校验字段的**一致性断言**（如 `detectable_by_defense ⊇ {名 | anchors[名] 非空}`）；注入一条违规验证会红。

### D19 · 豁免 / SKIP 表里的"僵尸条目"：销项漏删 ⇒ 断言被永久跳过
- **判据**：豁免表（`serve_smoke/moonbit_exemptions.json` 之类）按"断言名精确匹配"跳过断言。条目**理由过期**（写"某族未接"而该族已接）时，断言本身可能**早已能 PASS**，却仍被跳过 ⇒ 该面实际不受检，且"销项"动作看起来做完了。
- **查法（必须两态对跑，单跑看不出来）**：① 原样跑一遍记基线（`PASS n / SKIP m`）；② **删掉一条豁免条目**再跑——**真豁免** ⇒ 该断言 FAIL；**僵尸条目** ⇒ 该断言 **PASS**（记下来）。逐条做，或让脚本机械做两态对拍。**表内注释"PASS 也豁免（防僵尸条目）"这类承诺，只有机判才算数。**
- **与 D10 的区别**：D10 是"差分 known 白名单的理由是待验断言"（要去比 digest / 打印真实差异）；D19 是"豁免条目**连跑都没跑**"——删条目看红不红即可，不需要重采真值。
- **处方**：给脚本加**僵尸豁免机判**（带豁免 / 不带豁免各跑一次，`SKIP 条目删后仍 PASS` 即红）；至少在销项批里把**同族条目**列全再核（C5 同款）。
- **实例**：一次"step 族 + 栈帧销项"里，豁免表仍留两条理由为"同上（S8）"的条目；删掉后该断言**真跑且 PASS**（这就是僵尸判据），而同表 `ping 携带 ABI 版本` / `capabilities 携带 engine_version` 删后**真 FAIL**（合法豁免，形态差非缺陷）。⇒ 同族 4 条里 2 条是僵尸；漏删的 `栈帧区域带 alloc_by=call / alloc_line（C2）` 与已删的 `栈帧区域带函数名（C2）` 同族（C5 形态）。

### D20 · `-check` 生成器「写-读-比-还原」在早退路径上不还原 ⇒ 闸自己破坏工作区

> **与 D1 同族**：D1 问「它是不是闸 / 会不会自愈」，本条是同一自证问题的**问三——跑它会不会改坏我的工作区**。

- **判据**：生成器的 `-check` 实现常写成「先把再生成内容**写**到产物路径 → 回读**比**较 → 不一致才**还原**」（为了绕开 `moon fmt` 之类的规范化步骤）。只要在**写之后、还原之前**存在任何早退路径——读不到某个产物、格式化工具有外部依赖、写出与还原之间抛错——**已写入的那些产物就被留在未规范化的形态**，`git status` 出现非预期改动。
- **查法（一条命令即可判）**：**移走该生成器的某一个产物**（`mv <产物> /tmp/`）→ 跑 `-check` → `git status --short` 看**其它**产物有没有被改写。正常应零残留（`-check` 的契约是**只读**）。
- **处方**：把「写」推迟到全部校验通过之后；或写临时文件再 `rename`；任何失败路径都必须走还原（含 `err != nil` 的读失败分支，不只是"对比不一致"分支）。
- **为何门禁没抓到**：`-check` 自己**就是**那道闸——它在红的时候顺手改了文件，而 CI 只读退出码、不读工作区。所以"闸红"与"闸改坏了树"是两件独立的事，必须分别验。
- **实例**：某新生成器的 `-check` 在「产物缺失」分支直接 `fatal` 早退，未还原已写入的其它产物；把其中一个 `.mbt` 移走后连跑，稳定复现"另一个 `.mbt` 被覆盖成未过格式化的原文"，而退出码是正确的 1（看起来一切正常）。

### D21 · 自证闸的通过条件与它打印的路数 / 计数不一致（2026-10-02 补）

> "看着覆盖了、实际没判"——`-selftest` 的**打印**里有某路的计数，但**通过条件**不含那条路。

- **判据**：读自证分支的判定表达式（`if kinds[...] < 1`）与打印格式串**逐路对照**——打印了 `id=%d` 判定里却没有 `kinds["id"]`，即命中。
- **查法（逐路打坏）**：把每一路的判定分别注入废掉（`if !x[y]` → `if false && ...`），跑 `-selftest`——**仍绿**的那路就是没判的。这是唯一可靠的验证（读代码对照会被同类项淹没：zombie 多张表共用一个 kind 计数，单表失能另一表撑住 ≥1）。
- **处方**：通过条件覆盖全部打印的路数；多张规则表共用一个 kind 时，下限提到"表数"（两表雷 ⇒ ≥2，单表失能即红）；措辞与实际项数对齐（"三路"实为四类就写四类）。
- **实例**：demo UI 对账闸的 `-selftest` 打印 `id=%d` 但判定只有 class/var/zombie——注入废掉 id 路仍 exit 0；且 zombie 计数 ≥1 由两张规则表的雷共同撑住，废掉单表判定也仍绿——修复后四类各 ≥1 + zombie ≥2（两表各一），逐路打坏六发全红。
- **自证分支的覆盖面 ≠ 头注 / flag 描述声称的覆盖面**（2026-10-03 补）：自证入口（`--selftest`）的头注写"篡改帧 / 删基线必红"，而实现只测了管线辅助函数（正则 mask 生效 + 非法输入拒绝）⇒ **篡改基线时主流程红、自证入口仍绿**——"自证通过"被误读成"比对逻辑也验过"。查法：把该 flag 的说明**逐场景**构造出来跑一遍自证入口，仍绿的那条即未覆盖（与主条的"打印路数 ≠ 判定路数"是同一病的两个面：主条看输出，本条看**宣称**）。处方 = 自证里对每个声称场景做一次真注入，或把 flag 说明收窄到实际覆盖的场景。

| E2 | **提交信息数字与实测不符** | 逐个复跑，别信提交信息里的验证段 | 声称"N 闸全绿"而实际有闸红；声称"某清单 N 项"与实测不符 |
| E3 | **数字不标口径** | 同一概念多处不同口径 | 同一量在制品 / 徽标 / 提交信息里分别是三个数，读者以为是同一个 |
| E4 | **状态句不同步** | 改了 A 文档没改 B；只改数字不改状态句 | 根 `AGENTS.md` 写"某阶段已收官"而总计划对应行仍是"开工批已落" |
| E5 | **头注 / 行内注释与实现脱节** | 对每个被改动的注释做一次全量 grep 列点，逐个回读 | 删了参数但头注仍写"带行号"；头注改了数字而行内注释仍是旧值 |
| E6 | **EOF 换行被顺手删掉** | `git diff \| grep "No newline at end of file"`；**判惯例看同目录同类文件** | 同次改动把某清单文件的 EOF 换行删了，而同目录其余文件全带 LF |
| E7 | **文档转义符按字节核** | 涉及转义 / 字面量的段落一律 `open(p,'rb').read()` 打印 `repr` | 写 `\n` 时落了真换行、backtick 也丢了 |
| E8 | **Markdown 多行结构断裂** | 改动区逐行打印 `len/starts/ends`（`ends` 是否 `\|`） | 表格行被拆成 3 行 ⇒ 表格在该处断裂 |
| E9 | **声称"已登记"但没登记** | 同时 grep 注释与文档两边 | 新差异只在注释里提过，规格层没写 |
| E10 | **外链未核验** | 引用外部 issue / 文档时实测可达且内容与引述一致 | 引用的上游 issue 编号真实存在、状态与引述相符 |
| E11 | **手册 / 文档引用的资产不在版本控制内** | 手册写了工具或数据路径，但该资产只在某台机器上 ⇒ 别的 agent / 机器 / CI 照手册做不了；且它零版本管理（改动无历史、不进门禁、不被任何闸扫到） | 对手册里每条"工具 / 数据路径"断言做两查：① `ls` 实测存在；② `find . -name <文件名> -not -path "./tmp/*"` 判是否入库（**空 = 库外**）。处方 = 手册显式注明"库外、需另行获取 + 版本要求"，或二期入库（入库时明确它是不是门禁的一部分） |
| E12 | **新增外部路径依赖但部署/CI 触发面未同步**（E11 同族；2026-10-03 审阅新增） | 批次新增了对仓库内**其它目录**的依赖（artifact 组装 cp 了它 / 文档引用了它），但 `on.push.paths` 仍只含旧目录 ⇒ 该路径改动**不触发重部署/重跑**，线上静默陈旧 | 对每个会 `cp/run` 外部路径的 workflow 步骤，检查触发面 ⊇ 消费源路径集（`sed -n '/^on:/,/jobs:/p' <workflow>` 对照组装步骤）；全仓无 workflow 路径一致性闸 ⇒ 人工对账。实例：pages.yml 组装 cp 了 `assets/logo/**` 与 docs 渲染源，但 paths 只有 demo/moonbit——品牌图更新线上不生效 |

- **E6 同族面（2026-10-03 补）**：格式约定的**权威是 `.editorconfig`，不是同目录邻居**——邻居常是混合态（机器生成的不带末行换行、手写的带），拿邻居判"惯例"会把违规判成合规。查法：先 `cat .editorconfig` 取 `insert_final_newline` / `indent_size`，再对**改动前后两个版本取字节**比对缩进与末行（别只对工作区取态）。实例：一批把三个既有 JSON 从 2 空格 + 末行换行重排成 1 空格 + 无末行换行（同批新建的资产同款），与 `.editorconfig`（`indent_size = 2` / `insert_final_newline = true`）冲突，且没有任何闸拦——`source_hygiene` 只扫活跃源码目录；后果是内容只增两条、diff 却涨到全文件级噪声，且编辑器按 `.editorconfig` 一保存就会再翻一遍。

- **E5 / E9 同族面（2026-10-04 补）**：
  - **E5 面：头注写的是「计划做的机制」，不是「实际做的机制」**。迁移批里常见头注先描述理想方案（"用 X 机制补齐 Y 缺口"），实现却退成另一条路（打一行 `@ts-expect-error` / 直接不写），甚至**压根没做**——头注却已按"已做了"的口吻落笔。查法：对每个被改动的头注做一次全库 grep，逐条回读"它描述的机制在代码里找得到吗"（找的是机制，不是关键词）；同族还包括**章节注释被切分时留在错误文件里**（注释归属一个模块，代码搬到另一个模块）。
  - **E9 面：重大让步 / 裁定只落在提交信息里**：关掉某项严格检查、某闸"清零后再接线"、某防线暂缓——写在 commit message 与代码行内注释里，**规格层（文档）零登记** ⇒ 下次审阅只能翻 git 历史才知道"这是有意为之，不是漏了或忘了"。查法：对提交信息里每条"裁定 / 知情让步 / 待办"，**同时 grep 文档与代码两边**；只有提交信息命中即命中。处方 = 让步登记进语境层文档（本仓三层文档纪律的"裁定"层）。
