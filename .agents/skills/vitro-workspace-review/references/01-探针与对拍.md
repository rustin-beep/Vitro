# 探针与对拍

> 阶段 3 / 阶段 4 的具体做法。**只在真要做探针时读。**

## 0 · 通用纪律

- **探针留证**：复杂 / 难以重建的探针放 `tmp/review_YYYYMMDD/`（被 `.gitignore` 忽略），报告里给**相对路径**；一次性小探针**用完即删**，`git status -uall` 确认零残留。
- **真机端到端优先于白盒自证**：能写成 C 程序用 oracle CLI 跑的（VFS / 文件 IO / `scanf` 流），就**别只靠白盒锚**。
- **先证会红**：探针本身也要证明它有能力报错（喂一个已知坏的输入，看它红不红），否则"探针全绿"无意义。
- 跑完删树内副本后**复跑单包测试确认计数回落**（探针文件会让单包测试数 +1）。
- 工程结构见 §6（缺一个文件就静默 EXIT=0，见 [`04-工具链与踩坑.md`](04-工具链与踩坑.md) A2）。

## 1 · 形状探针（编译侧）

语料对每个构造通常只取**一种形状**，换标量宽度 / 指针层数 / 存储类就出盲区。

高发形状：

| 形状 | 为什么容易漏 | 期望 |
|---|---|---|
| `union` 成员赋值 | 反查结构体定义的实现在 union 上回退 ⇒ 一律按 4 字节存 | 回退即 `CONTENT-DIFF` |
| 多级指针取址（`char **p; char *a[2];` 的 `p[i]` / `a[i]` 步长） | 取基类型只解一层 | SAME |
| 匿名 struct typedef 成员、指针 → union 成员 | 语料未覆盖 | SAME |
| 嵌套成员读写宽度 | 宽度取"节点自身类型"才对，反查表会回退 | SAME |

```bash
mkdir -p tmp/review_YYYYMMDD/probe_x && cat > tmp/review_YYYYMMDD/probe_x/x.c <<'EOF'
...EOF                                   # 单文件；oracle 不接受 file scope 变量声明
go run ./scripts/codegen_diff tmp/review_YYYYMMDD/probe_x   # 期望 SAME
```

逐指令定位：

```bash
./native/target/release/vitro_cli.exe dump-compile f -o rust.json
cd moonbit && moon run --target native cmd/dump_compile -- <dir> <outdir>
# 注意：MoonBit CLI 成功打印也可能写 ok:false ⇒ 必查产物 ok 字段
```

## 2 · 运行时对照（宿主编译侧）

端到端门禁覆盖不到的面，四步：

1. **取 oracle 真值**：写只做 `printf(...)` 的 C 程序，跑 oracle CLI，清洗掉框架输出（`===`、空行、"程序运行完成"、"编译成功"之类）后落文件。
2. **取实现值**：临时白盒探针 `moonbit/<pkg>/zz_tmp_*_wbtest.mbt`，把结果拼串后 **`fail(s)`** 打出（`assert_eq` 只报 FAILED 行、**不含实际值**）：
   ```moonbit
   test "tmp_dump_xxx" {
     let cases : Array[(Double, Int)] = [(1.2345678901234567e30, 17)]
     let mut s = ""
     for c in cases { s = s + format_g(c.0, c.1, false) + "\n" }
     fail(s)
   }
   ```
   > 浮点字面量**必须带小数点**（`1e23` 语法错 → `1.0e23`）。
3. **机械 diff**：`diff -u oracle_clean.txt mbt_clean.txt`（抓 dump：`sed -n '/FAILED:/,$p' | sed '1s/.*FAILED: //'`）。
4. **扩面**：用 Python 生成随机 / 边界值批量两侧跑（默认精度与高精度各一组，`%.17g` 最易暴露 ULP 分叉）。
5. **交叉验证算法本身**：用 Python（`decimal` 精确幂 + `format(x,'.Nf')` 正确舍入）复刻同一逻辑与 oracle 逐行比，据此判定 oracle 用哪种算法 —— **处方比猜编译器内部可靠**。

## 3 · 弹参序判别必须用非对称实参

- **压参方向的单源**：编译侧压参用 `.rev()`（从右到左入栈）⇒ **栈顶 = 首个实参**。判"先弹谁"必须回这条，**别猜**。
- 自造锚要用**非对称实参**：
  - `atan2(1.0, 1.0)` 对弹参序**零判别力**（这种写法在已提交测试里出现过）；
  - `pow(2.0, 10.0)` 有判别力；
  - `fmod(2.0, 7.5) = 2` / `fmod(7.5, 2.0) = 1.5` 是最省事的判别对。
- 真值取法：单调用 C 探针 `printf("%.17g\n", f(...))` → oracle CLI；实现侧白盒直压栈（先压 `arg[1]` 再压 `arg[0]`）后调宿主分发入口。

## 4 · 接线臂可达性核查（最高产出的"门禁盲区"检查）

**"已接 N 臂" ≠ N 臂可达。**

- 机制：编译侧会把预注册的函数表**全量**塞进调用索引（仅少数通过"改走宿主"例外）⇒ 这些名字一律发 `Call <1000+idx>`，对应的宿主调用臂是**死面**。
- 查法：`dump-compile` 一个逐名调用探针，看该名字发 `CallHost` 还是 `Call 10xx`；再用路由表（`is_host_rerouted` + 预注册清单）交叉核对。
- 报告口径：路由覆盖闸报"N 条路由全部有实现"**不代表**这些宿主臂可达 —— **两者是不同问题，别混**。

## 5 · 输入通道的行边界形态

审"新接了 stdin 的通道"时，**第一件事核对行的形态**（含不含 `\n`）——见 [`03-缺陷形态清单.md`](03-缺陷形态清单.md) B2。

判别样本：

```c
#include <stdio.h>
int main(){ int c; int n=0; while((c=getchar())!=EOF)n++; printf("n=%d",n); return 0; }
```

```bash
printf 'ab\ncd\n' > in.txt
./native/target/release/vitro_cli.exe run p.c -i in.txt
```

三种输入都要试：`"ab\ncd\n"`（多行含尾换行）、`"ab\n"`（单行含尾换行）、`"ab"`（**无**尾换行）。

⚠️ **发现"两侧行形态不同"时，先查是不是既有锚已锚定了错形态**（见 A3）。

## 6 · 独立探针工程结构

```
tmp/review_YYYYMMDD/<name>/moon.mod           # 注意是 moon.mod，不是 moon.mod.json
tmp/review_YYYYMMDD/<name>/src/moon.pkg       # 必须有（哪怕只含一个换行）
tmp/review_YYYYMMDD/<name>/src/*_wbtest.mbt   # 白盒 test 块放这里才会被收集
```

- **`moon.pkg` 不可省**：缺它时 `moon build --target native <dir>` / `moon check` **完全静默**（`no work to do`、**EXIT=0、零产物**）——"跑过 check 全绿"可能什么都没跑。内容须 `pkgtype(kind: "executable")`。
- 需要 `@env` / `@fs` 等 core 包要在 `moon.pkg` 的 `import` 里显式声明。
- 计时对照用 `date +%s%N` 包住进程、**best-of-3**、两模式**交替**跑（避免 turbo / 热漂移把差 20% 的结论读反）；想更稳就取两个 N 做线性拟合扣掉启动开销。命令行模式选择用 `@env.args()`。
- **`raise` 相关探针**：必须声明真 error 类型；`fn main raise` 不允许 ⇒ `fn main` + `try/catch`。
- **微基准必须覆盖失败率维度**：只测"平均情况"会得出反向结论（见 [`03`](03-缺陷形态清单.md) A9）。并注明构建模式（debug / release）。

## 7 · 突变注入手法

```
备份 → replace(old,new,1) → sleep ≥1.5s → 跑单包 → 记录 failed
→ 还原 → 复跑确认回落（finally 里再还原一次，防中断留脏）
```

- **无锚判定必须带对照**（同时改坏 1–2 个已知有锚的点），否则只能说"整套没牙"。
- **"改坏不红"分两种性质**：① **真锚盲区**（要报）；② **等价分支**（改掉后由兜底路径殊途同归）⇒ 读码判定，不硬报。**判据：能否找到一条区分两条路径的输入形状**。
- **反向突变（审修复批）**：把修复还原成缺陷版，期望对应用例红；记录**红的是哪个用例名**。`failed == 0` ⇒ 修复写了但锚没牙。
- 可注入点样本：平局分支、负指数倒数、零填充、映射表推进、格式串 `%%` 分支、EOF 粘滞分支、合并差一、上限硬编码、增量恒零。

## 8 · 浮点 / 数值移植的三方位级对拍

**必须拉第三列 = 平台 libm。** 本仓判据是"oracle 照搬"，但 oracle（Rust `libm`）**自己就会与平台 libm 不同**。只做两侧对比会把三种情况混成一种：① 移植片错、② 移植片比 oracle 更对、③ 两者同时偏离真值。

```bash
# 不要加 -lm（msvc target 会找不存在的 m.lib 而链接失败），直接编
clang probe.c -o probe_clang.exe && ./probe_clang.exe > clang_bits.txt
```

- 输出统一为 `<name> <idx> <bits>`（bits = 结果 f64 位模式的**无符号十进制**，C 侧用 `memcpy` 取、`%llu` 打）⇒ 三方文件直接 `diff` / 字典比对。
- **三类必测边界**：`±0.5 / ±1.5 / ±2.5 / ±3.5`（平局）+ `nextDown(0.5)`、`-0.0`（符号零：`sqrt(-0.0)` / `ceil(-0.5)` / `pow(-0.0,3)` / `atan2(-0.0,-1.0)`）+ NaN 来源（`asin(2)` / `log(-x)` / `pow(-2,0.5)`）。
- **NaN 载荷 / 符号**（`0x7ff8…001` vs `0xfff8…000`）是低级但**可观测**（用户 `memcpy` 取位模式即见）。
- **顺带查语料覆盖**：`grep -rn "<fn>(" native/tests/cases/` 看该函数在语料里的**全部**用法是否含判别样本。

## 9 · 跨语言真值对拍：优先找现成出口

- **有 serve / CLI 出口时，直接取真值**：例如 serve 的 `contracts` / `semantic_labels` 方法可直接吐 Rust 侧 JSON ⇒ 与实现硬编码真值**逐字节比**（非自证循环）。
- 没有出口才用探针复刻；而**探针复刻本身要标为"待独立验证"**。
- **判据红线**：`-check` 类生成器的"真值"若来自自己的缓存制品，那是**复述不是对账**（见 `02` §2）。

## 10 · 「边界不可达」也要实测收口

列在"未覆盖"里的边界项，**能用端到端探针收口就别留在表里**。

做法：造 6–7 个形态的极小语料（裸文件名 / `./x` / 绝对路径 / 子目录 / 嵌套 include 链 / 取不到的根相对路径），cwd 固定在该目录，双侧各跑一遍比 stdout。

收益：全形态一致 + 某形态两侧均失败 ⇒ 该分叉**不可达**，可以结项；顺带常能捞到一两条 P3。
