## 这门课在做什么

一个只有 12 行的小程序，却同时踩到了三种数据：全局的 `double`、局部的 `double`、局部的 `long long`。它在 Vitro 里被采成 **9 帧**（语句级），帧数不多，但每一帧都能对上源码的一行。

关键点在于：**变量表里的显示口径和 printf 的输出口径不是一回事**。同一个平均值 4.0，变量表写 `avg=4`，程序打印 `4.0`。

## 先跑一遍，看三个东西

1. **帧 0 里就有全局变量**：`g_scale` 的值是 2，类型 `double`，可这一帧的 `code_line` 还是 0——全局段在 `main` 之前就初始化完了，帧流还没落到任何源码行上。
2. **变量表里的 `avg` 是 `4`，不是 `4.0`**：`double` 按定点格式化并去掉尾随 0，所以 4.0 显示成 4；而 `printf("%.1f ...")` 才把它打回 `4.0`。看数值要对齐显示口径，别把「显示成 4」当成「整数 4」。
3. **帧 4 就是那条 for 循环**：它对应 **68 条指令帧**，语句级把同一行的连续帧合并成 1 条。所以语句级看不到「转了几轮」，只看到跑完之后的末态 `total=3`、`i=3`（`i` 已经越过上界 3，循环条件不成立了）。把粒度切到「指令级」，这 68 条会一条条摊开。

## 一个常见错误，先放在这里

循环边界写成 `<=`：

```c
for (int i = 0; i <= 3; i++) { total = total + i; }   /* 反例：多跑一轮 */
```

这行代码**能编译通过**，但结果错了。实测两版：**帧数都是 9（完全一样）**，可 stdout 从 `"4.0 3"` 变成 `"4.0 6"`，变量表里 `total` 从 3 变 6、`i` 从 3 变 4（指令帧从 99 涨到 119）。

这一课最该记住的就是这个反差：**语句级帧数相同，不代表行为相同**。帧数只告诉你「走了几条语句」，值变没变要看变量表和输出。

## 试着改

1. 把 `g_scale` 改成 `3.0` 重新采集：帧数仍是 9，`avg` 变成 6，stdout 变成 `"6.0 3"`。全局变量在帧 0 就被读进来了——改它的值，帧 1 之后的每一帧都会跟着变。
2. 把循环条件改回 `i < 3`，再把 `total` 的初值从 0 改成 1：帧数还是 9，但 `total` 会变成 4。再改一次初值，看 `total` 怎么动——帧 4 是唯一一处能看到它的地方。
