## 版本号口径（2026-10-31 用户拍板）

本版**不是准备充足的新版本**。按仓内版本纪律（minor 规则：新增公共 API → 递增次版本号），0.9.0 后窗口内合并的 `vfs.list`、`algorithms.catalog` 出口等新增 API 面本应记作 **0.10.0**；但本版的真实动因是**在架事故修复**（见下节），且 mooncakes 平台**不支持拆分发包**——新增 API 无法单独延迟到下一个 minor 发布，只能随事故修复版一起带出。用户拍板取 **0.9.1**（patch 口径），特此在版本档案说明：**0.9.1 的版本号反映的是发版动因（修复在架断供）而非内容面（含新增 API）**；若严格按纪律口径应视为 0.10.0。0.9.1 之后接续：#399（step.next 行末不变量）/ #361（fuzz 采样键平台归一）等工作窗口已排入 0.9.1 后。

## 发版动因：在架事故（0.9.0 包下游断供）

moonc ≥0.10.18 删除 core/abort——0.9.0 在架包内的引用链在新工具链下**下游 `moon add vitro/engine` 后 `build` 必红**（#402 body 实锤：0.9.0 型断供在 `moon publish --dry-run` 下即 Check failed，master 候选件 Check passed）。该形态在既有发布彩排里零闸能抓——由此本窗口新建 **`release_preflight` 发布前置闸**（#402：publish dry-run 双档 + package 非退化 + 反刷量约束）并在本版彩排首战。**必须尽快发版修复在架断供**是本版跳过 0.10.0 拍板节奏的直接原因。
