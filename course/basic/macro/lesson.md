## 这门课在做什么

这一课的程序只有 8 行，但它是整个 demo 里唯一一门**编译期就能看见**的课：`SQUARE(N + 1)` 到底被展开成了什么文本。

运行期只采到 **6 帧**。宏没有函数、没有栈帧、没有参数传递——它在预处理阶段就被替换成了普通表达式。等你看到帧 2 时，`s` 已经是 16 了，中间的「3+1」「(3+1)*(3+1)」在运行期**根本不存在**。

## 先跑一遍，看三个东西

1. **展开结果在编译帧里**：`preprocessor_trace` 给出 `SQUARE(N + 1) ⇒ ( ( 3 + 1 ) * ( 3 + 1 ) )`。两处 `3 + 1` 各自被括号包住——这就是宏参数必须带括号的意义（下一节的反例会去掉它）。
2. **语义标签里留着宏名**：帧 2 的标签是「调用 SQUARE」，不是「调用某个函数」——引擎认得这是个宏展开，但它仍然只是**一条赋值语句**，没有调用栈变化（栈深始终是 1）。
3. **宏不产生额外帧**：L6 那行的 9 条指令帧在语句级合并成 1 条。宏比函数便宜，代价是它对参数不做类型检查、也没有作用域。

## 一个常见错误，先放在这里

宏参数不加括号：

```c
#define SQUARE(x) (x*x)     /* 反例：x 替换进去后先结合 */
```

这行代码**能编译通过**，宏也照样展开。实测两版：**帧数都是 6**，`preprocessor_trace` 从 `( ( 3 + 1 ) * ( 3 + 1 ) )` 变成 `( 3 + 1 * 3 + 1 )`，stdout 从 `"16"` 变成 **`"7"`**。

因为乘法优先于加法，`3 + 1 * 3 + 1` 算出来是 3 + 3 + 1 = 7，不是 16。错误版本和正确版本的帧流**一模一样**——宏的坑全部发生在看不见的编译期，只有展开文本和输出会暴露它。

## 试着改

1. 把 `SQUARE(N + 1)` 改成 `SQUARE(N)` 重新采集：stdout 变成 `"9"`，帧数仍是 6，展开文本也变成 `( ( 3 ) * ( 3 ) )`。参数少了一层括号，展开结果立刻干净。
2. 把 `#define N 3` 改成 `#define N 5` 重新采集：`SQUARE(N + 1)` 展开成 `( ( 5 + 1 ) * ( 5 + 1 ) )`，stdout 变成 `"36"`，帧数还是 6。再把反例那行（`(x*x)`）换上——这次 N=5 会给出 `5 + 1 * 5 + 1` = 11，你会看到同一个错误在不同输入下错得不一样。
