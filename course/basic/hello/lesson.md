## 这门课在做什么

最小的一个程序：打印一行，然后返回 0。源码只有 6 行（算上 `#include` 与空行），但在 Vitro 里点「运行 + 采集帧流」之后，它被拆成 **5 帧**。

这 5 帧不是动画关键帧，是引擎给出的**执行轨迹**：帧 0 的 `code_line` 是 0（还没进任何源码行），帧 1 落在 `int main() {`，帧 2 落在 `printf` 那一行，帧 3 落在 `return 0`，帧 4 的 `code_line` 也归 0、调用栈已空。

## 先跑一遍，看三个东西

1. **编辑器里的当前行描边**：帧 2 时亮着 L4（`printf("Hello\n");`）。行染读的就是帧里的 `code_line`，不是推测出来的——这就是白箱的第一层：引擎肯告诉你它此刻站在哪一行。
2. **头尾两帧没有源码行**：帧 0 和帧 4 的 `code_line` 都是 0。序章帧还没进 `main`，收尾帧程序已经退出。帧流里有「不落任何源码行」的诚实空态，不是每一帧都该有行号。
3. **变量表全程为空**：这个程序没有局部变量，所以「局部变量」面板在 5 帧里都是空的。变量表显示的是**当前作用域**的变量，不是内存全景。

## 一个常见错误，先放在这里

把 `printf` 写到 `return 0` 后面：

```c
int main() {
  return 0;
  printf("Hello\n");   /* 反例：永远执行不到 */
}
```

这段代码**能编译通过**（引擎诊断 0 条，不报不可达代码），但 stdout 是空的——`return 0` 直接结束程序，后面的 `printf` 根本没执行。

实测两版：**正确版 5 帧 / 错误版 4 帧**，少掉的那一帧正是 L4 的「调用 printf」；stdout 也从 `"Hello\n"` 变成 `""`。帧流长度本身就是执行事实——「这段代码跑过没有」在白箱视角下是可以量出来的。

## 试着改

1. 把 `printf("Hello\n")` 改成 `printf("Hello")`（去掉 `\n`）重新采集：帧数仍是 5，stdout 变成 `"Hello"`——**输出变了，帧流长度没变**。
2. 在 `main` 里再加一句 `printf("second\n");` 重新采集：帧数从 5 涨到 6（多出一条「调用 printf」的语句帧），stdout 变成 `"Hello\nsecond\n"`。记住这个对应关系：**一行代码 ≈ 一条语句帧**，下一课起帧数就不再这么干净了。
